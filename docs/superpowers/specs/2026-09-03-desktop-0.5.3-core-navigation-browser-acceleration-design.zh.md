# Desktop 0.5.3 官方同步、导航、BrowserSkill 与交付加速设计

[English](2026-09-03-desktop-0.5.3-core-navigation-browser-acceleration-design.md) | 中文

**状态：** 用户已于 2026-09-03 批准按推荐方案开始

**Desktop 基线：** `7384b863e88b005b3309e49a0aebb7a2ea91d4c3`（公开 `desktop-v0.5.2`）

**官方目标：** `dsh-v0.1.2-alpha.5` / `db6bdc3576c2d4e7c965e8e3ed0c2a731eed87f5`

**目标 Desktop 版本：** `0.5.3`，通过 `alpha.1`、`alpha.2`、`alpha.3` 三个内部候选逐层验收

## 目标

1. 把内置 Harness 从 `0.1.1-rc.2` 迁移到官方 `0.1.2-alpha.5`，保留已有 Desktop 功能和真实用户升级数据。
2. 会话正文左侧使用钢琴键式完整历史导航；预览绝不覆盖输入框。
3. 把现有 Desktop Workbench 整理为可扩展、按需加载的固定右栏，不重复引入第二套终端、文件或浏览器运行时。
4. 内置 BrowserSkill 的 Harness 插件和双平台 CLI，但默认不启动、不接管标签页；浏览器扩展仍由用户明确安装和授权。
5. 缩短开发交付等待：构建一次，多组原生验收并行复用产物；中间候选走快速门禁，最终 SHA 才做完整双平台发布验收。
6. 在不提前宣告 readiness、不跳过 Loader 校验的前提下继续优化真实启动瓶颈。

## 非目标

- 不把 `DSH-better-sidebar` 整包复制进 Desktop，也不同时保留两套右栏。
- 不通过 DOM 哈希类名注入隐藏官方导航；不同时挂载官方、自研、`dsh-session-nav` 三套导航。
- 不自动安装 Chrome/Edge 扩展，不读取或复用用户普通窗口，未确认时不借用标签页。
- 不把首次启动在线下载、删除许可证、移动运行时到 `DSH_HOME` 当作包体优化。
- 不因追求数字提前打印 `dsh web:` 或把加载页当作真实 Desktop ready。

## 已核对事实与设计决定

### 官方同步必须先做

从 `0.1.1-rc.2` 到 `0.1.2-alpha.5` 是大范围上游演进，不是单点修复。目标版本新增完整会话 Turn outline、分页跳转与 TurnNavigator，并在 alpha.5 修复旧版本升级时可能启动失败或会话标题丢失的问题。

因此同步顺序固定为：旧数据迁移 RED → 官方代码同步 → Desktop 扩展移植 → 旧数据 GREEN → 双平台临时 Home 与真实升级副本 smoke。UI 与 BrowserSkill 只能基于同步后的接口实现。

已有 `codex/desktop-049-official-core-sync` 分支含 alpha.2 同步经验，只允许作为冲突与兼容性参考；新候选必须从已发布 0.5.2 基线建立，并最终包含 alpha.5 的精确上游祖先或可审计等价导入。

### 左侧完整会话导航

数据权威使用官方 `turnOutline` 与 `TurnNavigator`：一项对应一个 Turn，包含 `turn`、`seq`、有界 `prompt`、有界 `response`，需要时通过官方 `loadThrough`/分页通道加载旧历史。

视觉参考 `kiligzzz/dsh-session-nav`，但实现留在第一方组件中：

- 导航簇位于会话正文左沟槽，保持 10px 常规节距、2px 视觉键、6px 静止长度。
- 悬停键为 26px，相邻三级依次 20/14/10px；当前键只改变颜色，不把正文向右推。
- 预览显示一行用户内容和最多三行回复，最大宽度 300px。
- 导航可见高度必须使用 `conversation viewport - composer height`，预览 `top` 在该高度内 clamp；靠近底部时向上收，不得进入 composer、QueueDock 或统计行。
- 键盘、减少动态效果、深浅主题、长会话内部滚动与窄窗隐藏/紧凑模式继续使用官方语义。
- 同步后删除或停用 rc.2 分支上的 `PromptAnchor`/`PromptRail` 重复实现，只保留一种导航真相。

### 固定右侧 Workbench

继续使用现有 `layout.utility`、Electron `WebContentsView` 浏览器、终端、审阅和文件面板。参考 `DSH-better-sidebar` 的服务化标签、固定栏和按需加载，但不引入其完整依赖树。

新增内部注册合同：

```ts ignore-check
export interface DesktopWorkbenchTabDefinition {
  readonly id: 'review' | 'terminal' | 'browser' | 'files' | 'agent-browser'
  readonly titleKey: string
  readonly icon: WorkbenchIcon
  readonly order: number
  readonly load: () => Promise<{ default: ComponentType<WorkbenchModeProps> }>
}
```

- 内置四页通过同一注册表生成纵向入口，重模块仅在首次选择时加载。
- BrowserSkill 启用后增加 `agent-browser` 状态页；它显示连接、扩展安装、Agent Window 与借用状态，不复制普通网页浏览器。
- 右栏仍是固定、可拖宽的单一 surface；不增加浮动预览、Side Chat 或第二个 Terminal。
- 入口和文字各有独立布局槽，长中文/英文单行省略，100%、150%、200% 缩放不能互相挤压。

### BrowserSkill 内置边界

BrowserSkill 分为三层：Harness 插件、平台 `bsk` CLI、Chrome/Edge 扩展。Desktop 只内置前两层；第三层必须由用户在浏览器商店明确安装。

```ts
export interface DesktopBrowserSkillState {
  readonly enabled: boolean
  readonly cli: 'bundled-ready' | 'missing' | 'incompatible' | 'unhealthy'
  readonly extension: 'connected' | 'disconnected' | 'unknown'
  readonly ownedSessions: number
  readonly borrowedTabs: number
  readonly lastErrorCode?: string
}
```

- 只采用公开发布且 SHA-256/完整性固定的一组版本；不得直接打包 `main` 未发布内容。
- `bsk` 只在用户启用或模型实际调用 BrowserSkill 时启动，Desktop 冷启动不探测浏览器、不启动 daemon。
- DSH 插件只暴露结构化 `browser_*` 能力；不开放任意 JS/CDP/evaluate。
- 默认操作插件创建的 Agent Window。借用普通标签页必须由 BrowserSkill 原生确认，完成后归还；退出 Desktop 只清理本实例拥有的 Session。
- Extension 未连接时返回可操作的安装/连接引导，不进行无限重试。
- Mac 只带 x86_64 CLI；Windows 只带 x86_64 CLI，禁止把另一平台二进制打入成品。

### 启动与交付加速

现有 Windows 0.5.2 同机证据显示，典型冷启动 4257ms、热启动 3271ms；主要可控阶段是 `profile-compose → loader-mount` 约 1.2s，以及 Harness ready 后首个 Desktop surface 约 0.9–1.2s。module fallback 重复治理仅约 64–66ms，不值得绕过安全校验。

运行时策略：

- 对同步后的 Loader 重新采样，不沿用旧版本数字推断优化。
- 只缓存以 profile、bundle、patch、package lock 和版本精确摘要为键的可重建图；每次仍验证摘要、物理包根和失败传播。
- Workbench、BrowserSkill、Markdown 重预览等非首屏扩展按需加载；会话恢复、授权、路由、Client manifest 不能延迟。
- 目标：同机 10 次冷/10 次热比较，冷/热 median 至少一项改善 15%，另一项不退化超过 5%，P95 不退化超过 10%；否则撤销产品优化但保留测量工具。

交付流水线：

```ts
export interface DesktopCandidateDescriptor {
  readonly sourceSha: string
  readonly platform: 'mac-x64' | 'win-x64'
  readonly productInputSha256: string
  readonly artifactSha256: string
  readonly mode: 'quick' | 'full'
}
```

- build job 只组装一次并上传不可变 staged/DMG/Setup 候选。
- lifecycle、visual、performance 在独立 runner 并行下载同一候选；每个 job 先核对 descriptor、文件名、字节和 SHA。
- `quick` 只跑编译、关键合同、一次安装启动关闭；`full` 才跑基线性能、双缩放、完整卸载和公开发布门禁。
- 测试脚本修复允许复验已锁定产品 artifact，但最终 tag/Release 仍必须从最终源码 SHA 重建一次并重新做双平台 full。
- Mac 与 Windows workflow 同时 dispatch；预计 Windows 完整墙钟目标 10–13 分钟，属于工程目标而非发布承诺。

## 分期与所有权

### `0.5.3-alpha.1`：官方同步与流水线基础

- Mac 执行任务：唯一共享官方 core sync 所有者；迁移 Desktop 扩展并提供 Mac Intel 快速 smoke。
- Windows 执行任务：Windows pipeline 加速所有者；在 0.5.2 基线上先交付可复用 build/quick/full 合同，等待共享 core commit 后消费。
- 总指挥：规格、集成、冲突归属、候选 SHA 与阶段结论。

### `0.5.3-alpha.2`：左右导航与 Workbench

- Mac 执行任务：唯一共享 UI 实现所有者；实现 TurnNavigator 左侧样式、composer clamp、Workbench 注册表与懒加载。
- Windows 执行任务：只消费共享 UI，完成 100%/150%/200% DPI、任务栏和输入框不重叠验收。

### `0.5.3-alpha.3`：BrowserSkill

- Windows 执行任务：唯一共享 BrowserSkill Desktop 适配所有者；实现版本锁、插件挂载、CLI 定位、状态与 Windows x64 验收。
- Mac 执行任务：只消费共享提交，接入 Intel CLI 并完成 Mac 原生引导/连接/清理验收。

### `0.5.3`：最终发布

- 总指挥独占版本、README/PROJECT_CONTEXT、集成、tag 与 Release。
- 同一最终 SHA 的 Mac DMG 与 Windows Setup 必须 full GREEN；任意源码变化作废旧 artifact。

## 验收标准

1. rc.2 与 alpha.3 真实格式升级 fixture 均可启动，Session 标题、事件、Workspace、Memory/Evolution 数据逐字节保持；损坏缓存只能备份并重建，不得删除原始记录。
2. 左侧导航覆盖完整 Turn 历史，加载旧页后准确跳转；预览在各种 composer 高度和缩放下不重叠输入区。
3. 右栏固定、可调宽、按需加载；四个原功能无回归，BrowserSkill 页面只在启用时出现。
4. BrowserSkill 在没有扩展时给出引导；有扩展的隔离测试只控制 Agent Window；借用/归还、取消、退出清理和跨实例所有权全部 fail closed。
5. 插件与二进制有固定来源、许可、版本和 SHA；最终成品不含另一平台二进制。
6. quick/full pipeline 的 artifact 绑定、失败传播和最终 SHA 重建合同有自动测试；Mac/Windows 并行运行不共享可写用户 Home。
7. readiness、失败页、重试、退出进程树、卸载与用户数据保留不退化。
8. 发布报告区分典型启动、P95、Setup/DMG 下载大小和安装后占用；不得把某一项改善写成“全部更快”。

## 回滚

- core sync 在独立分支完成，未通过升级态 smoke 不进入 UI 分支。
- UI 可退回官方 TurnNavigator 默认位置和原 Workbench 静态入口，不回退 core 数据迁移。
- BrowserSkill 由 profile 开关禁用；禁用不删除扩展、用户浏览器资料或 BrowserSkill 自有状态。
- 新 pipeline 保留旧 full workflow 至第一次同 SHA 双平台 GREEN，之后才移除旧入口。
