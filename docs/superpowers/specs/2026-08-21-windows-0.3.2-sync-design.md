# DeepSeek Harness Windows 0.3.2 Synchronization

English | [中文](2026-08-21-windows-0.3.2-sync-design.zh.md)

## Goal

Publish a Windows x64 Setup from the same Desktop 0.3.2 source used by the verified Intel macOS release. The Windows package must expose the shared 0.3.2 product experience while retaining the established visible installer, startup, clipboard, process, and user-data protections.

The synchronization must finish through one Windows-only native build and release path. It must not rebuild, replace, or rename the existing macOS assets.

## Source and version ownership

- The public default branch is the only source for the Windows package; no feature is copied into a platform-specific branch.
- `apps/desktop/package.json` owns the Desktop version and artifact names derive from that value.
- The existing `desktop-v0.3.2` release receives the Windows Setup and checksum after native verification.
- Future Windows builds use the same version derivation so a Desktop version change cannot leave workflow filenames pinned to an older release.

## Build and release flow

The Windows workflow reads the Desktop version once, exposes it through step outputs, and uses the resulting artifact path for packaging, installer UI smoke, installed-application smoke, checksum generation, and artifact upload. A workflow-dispatch run on the public default branch is the release authority for Windows behavior.

The workflow uploads build artifacts to GitHub Actions without release-write permission. After the run succeeds, the release operator downloads those exact artifacts, verifies the checksum and package contents, and uploads only the Windows Setup and its checksum to `desktop-v0.3.2`. This separation prevents the Windows job from replacing the macOS DMG, macOS checksum, or update manifest.

## Windows adaptation scope

- Preserve the assisted per-user installer with welcome, destination, progress/details, finish, shortcut, automatic launch, and uninstall behavior.
- Exercise the shared 0.3.2 Add menu, SVG icons, adaptive reasoning control, official branding, and workbench from the installed Windows application.
- Use Windows-native terminal, path, process-tree, directory-picker, and shortcut behavior where the shared feature reaches an operating-system boundary.
- Keep the macOS system-update bridge unavailable on Windows.
- Preserve exact active and archived session ID copying, default-deny clipboard permissions, startup URL validation, and `~/.dsh` user data.

Implementation changes stay limited to release automation and Windows compatibility defects demonstrated by the native run. Shared UI or Mac behavior does not change merely to make a Windows assertion pass.

## Failure handling

- A missing, duplicate, or unexpected versioned artifact fails before installation.
- Installer, startup, clipboard, workbench, or uninstall failures stop publication and retain the existing public release assets.
- A checksum mismatch or unexpected sensitive path in the package stops upload.
- Release upload targets exact asset names and never uses a wildcard or release-wide replacement operation.
- A failed upload is inspected by exact asset ID; only an incomplete Windows asset may be removed and retried.

## Verification

Local checks cover the dynamic-version workflow contract, affected Desktop tests, formatting, and secret references. Windows native acceptance covers the visible installer, shortcuts, automatic launch, application version and branding, Harness startup on an owned random loopback port, Add menu, reasoning control, workbench modes, directory picker, active and archived session clipboard values, permission denial feedback, process cleanup, uninstall, and user-data preservation.

The final package is inspected outside and inside `app.asar` for `.env`, credential, and `.dsh` paths. The workflow must not reference API-key secrets. Public acceptance requires GitHub asset state `uploaded`, exact byte size, matching API digest, anonymous re-download, and matching SHA-256.

## Non-goals

- Rebuilding or changing the verified Intel macOS 0.3.2 package.
- Publishing historical macOS versions as part of the Windows synchronization.
- Adding code signing, automatic Windows updates, or unrelated UI changes.
- Backporting 0.3.2 features to a persistent Windows-only source branch.

## Acceptance

- macOS and Windows public installers both report Desktop 0.3.2.
- The Windows Setup installs through visible assisted pages and launches without requiring Node.js, pnpm, a terminal, a browser, or manual port configuration.
- The installed Windows application provides the shared 0.3.2 experience and passes the native security and lifecycle checks.
- The Windows Setup and LF-only checksum are publicly downloadable and match the verified workflow artifacts byte for byte.
- Existing macOS release assets retain their asset IDs, sizes, and digests.
