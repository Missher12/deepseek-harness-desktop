# 参考图式插件市场设计

[English](2026-08-20-reference-plugin-market-design.md) | 中文

## 状态与已确认决定

用户提供的插件截图是内部 Intel macOS 应用已经批准的视觉基准。插件市场内容按相同层级重新设计：标题与说明、全宽搜索框、已安装插件图标栏、公开与个人模式、紧凑筛选入口，以及按名称分区的无边框双列插件行。

搜索和分类必须作用于真实市场目录。“个人”指用户自己创作或在本地开发的插件，而不是所有已安装公开插件。现有安装、更新、启停、活动、主题、备份与恢复能力继续可用。本次只做内部版本，不上传 GitHub，也不包含 Windows 发布。

## 目标

用安静、易扫读的目录替换拥挤的多标签卡片市场，在保留 Harness 真实插件生命周期的同时贴近参考图。默认页面应立即回答三个问题：已经安装了什么、有哪些值得探索的公开插件、哪些本地开发插件属于用户自己。

## 现有约束

- 2026-08-20 设计阶段观察到的在线目录快照包含 1,650 个插件和 20 个中英文本地化分类；数量继续由目录维护，刷新后可以变化。
- 目录条目提供名称、作者、URL、可选 npm spec、分类、本地化说明、星标数、加入日期和可选截图；没有专用图标字段。
- 当前 profile 提供已安装包名称与 spec。本地开发安装使用 `file:` 或 `link:` spec。
- 当前市场还负责更新、活动日志、主题、分组、启停、卸载、备份与恢复；视觉重做不得删除这些能力。
- 当前设置内容宽度不足以支撑参考图中可读的双列布局。

## 备选方案

### 在自适应设置界面中完整采用参考结构

插件市场在桌面端加宽设置对话框，采用参考图层级，把真实目录分组成区块，并将维护功能收进已安装区域的齿轮菜单。窄窗口自动退化成单列。这是选定方案，因为它既接近参考图，也不引入第二套导航。

### 只用 CSS 重绘当前标签与卡片

改动更小，但会保留拥挤的标签栏、分类横轨、有边框卡片和狭窄内容区，无法实现用户给出的层级，因此不采用。

### 独立全屏插件市场

全屏路由空间最大，但会复制设置导航并改变用户进入插件管理的方式。这个架构扩展并非本次重做所需，因此不采用。

## 信息架构

市场内容按以下顺序渲染：

1. “插件”标题与本地化说明。
2. 一个全宽圆角搜索框。
3. “已安装”标题、齿轮操作和可横向滚动的图标栏。
4. “公开”与“个人”分段标签，尾部放置筛选操作。
5. 可纵向滚动的目录分区列表。

原来的发现、已安装、更新、活动、主题和备份顶层标签从主界面移除。齿轮操作打开管理菜单或面板，其中包含已安装管理、更新、活动、主题、备份与恢复；这些入口继续渲染现有功能页面。

## 公开目录分区

“Featured”是派生分区：在当前搜索和筛选约束下，从未废弃的公开插件中选取星标数最高的条目。其余分区遵循目录稳定分类顺序，并使用目录提供的本地化分类名称。

默认总览中，每个分区最多渲染六项，使用两列三行网格。紧凑页脚预览最多三个插件图标，并显示剩余条目数量；点击后使用相同行组件和有界分页进入该分类完整结果。总览中已经进入 Featured 的插件不会在普通分类里重复出现。

宽度不足以支撑两列时，分区网格变成单列。选择插件市场时，桌面设置对话框使用 `min(1040px, calc(100vw - 48px))`；其他设置分区保持现有尺寸。

## 真实搜索与筛选

搜索框在内存中筛选真实目录，匹配插件名称、作者和当前语言说明；匹配忽略大小写并去除首尾空格。搜索结果继续按分区组织，隐藏空分区，无需再次请求网络即可更新。通过 `useDeferredValue` 或等价的有界渲染路径保证在完整目录上输入流畅。

筛选入口继续提供现有真实排序和时间筛选：星标数或加入日期、升序或降序、发布时间窗口。筛选与搜索先组合，再进行分区。搜索不得制造 Featured、分类、数量或兜底插件；没有结果时，用一个本地化空状态替代分区列表。

## 已安装图标栏与插件行

已安装图标栏来自当前 profile 的真实 installed map。能在公开目录中匹配的已安装插件使用目录身份和可用的作者图片；本地或未收录插件使用现有确定性颜色与首字母兜底。图标栏长度受控并可横向滚动；点击图标进入对应详情或已安装管理视图。

目录行采用紧凑无边框结构：40 像素图标、一个可伸缩文字列和一个尾部操作。文字列包含单行名称与单行本地化说明。未安装公开插件展示现有真实安装操作，按钮使用描边药丸样式；已安装条目展示三点菜单。操作进行中用紧凑进度替代按钮，不改变行层级。

## 个人插件

“个人”包含 installed 依赖中 spec 以 `file:` 或 `link:` 开头的插件。这是现有系统中表示本地创作或链接开发插件的持久信号。公开目录包、普通 npm 依赖、GitHub 安装，以及仅仅未被目录收录的包，不会被静默标记为个人插件。

第一阶段通过相同行组件和现有已安装操作列出并管理这些本地插件。不新增可视化插件源码编辑器，也不根据仓库所有者猜测作者身份。没有本地插件时展示本地化说明，不提供虚构示例。

## 加载与失败状态

首次读取目录时渲染稳定结构骨架，对应标题、已安装图标栏、标签、分区标题和双列插件行。若存在缓存，可立即绘制缓存并在后台刷新。刷新失败时保留已有缓存并显示紧凑重试状态；没有缓存时，分区区域展示本地化失败状态。安装和维护失败继续使用现有安全确认、进度、取消、回滚与日志导出行为。

## 实现边界

Desktop-only 的 `dshmarket@1.10.1` patch 继续作为集成边界。纯分组与个人插件识别 helper 放在现有 market-data helper 附近并增加单元测试。`MarketSection` 负责组合与状态；使用聚焦的分区渲染器和行组件，避免已经较大的组件继续堆积重复 JSX。生成后的市场客户端产物、源码 patch、pnpm patch hash、staging 检查与打包 smoke 预期保持同步。

不增加新的凭据访问、原始文件系统桥、公开目录写入或插件自动发布。现有同源市场路由继续作为真实操作的权威入口。

## 验证

测试覆盖：

- 对名称、作者和本地化说明的真实搜索；
- Featured 派生、稳定分类顺序、总览不重复、每组六项限制和剩余数量；
- `file:` 与 `link:` 个人插件识别，且不误判公开或普通已安装插件；
- 已安装图标身份与兜底行为；
- 公开/个人切换、齿轮入口、筛选组合、空状态和安装/三点操作；
- 可读的桌面双列几何与窄宽度单列兜底；
- 无水平溢出与稳定加载骨架尺寸；
- patch 源码与已构建客户端产物同步；
- 使用隔离数据运行 Intel macOS 打包 smoke，并生成重做后市场截图。

只有聚焦单元与浏览器测试、类型检查、Lint、Desktop 打包、打包 smoke、安装包精确比较与启动验证全部通过后，才安装最终应用。

## 验收标准

1. 市场匹配用户截图的信息层级和视觉密度，而不是旧的标签卡片布局。
2. 搜索可以跨全部必需字段明显筛选真实目录条目。
3. 公开插件按真实本地化分类分区，Featured 位于最前，每个总览分区使用有界双列预览。
4. 个人只显示本地开发的 `file:` 或 `link:` 插件。
5. 已安装图标、安装按钮、三点菜单、筛选与维护入口全部作用于真实状态。
6. 现有更新、活动、主题、分组、备份、恢复与安全行为继续可达。
7. Intel x86_64 应用完成备份，安装到 `/Applications/DeepSeek Harness.app`，启动并验证，且不改变 `~/.dsh` 下的用户数据。

## 范围之外

可视化插件源码编辑器、自动生成插件、把个人插件发布到目录、私有云目录、作者身份推断、Windows 打包、GitHub 发布和公开 Release 产物不在本次范围内。
