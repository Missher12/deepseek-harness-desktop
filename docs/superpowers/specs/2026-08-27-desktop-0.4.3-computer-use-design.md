# Desktop 0.4.3 Browser Control, Computer Use, and Prompt Rail Design

English | [中文](2026-08-27-desktop-0.4.3-computer-use-design.zh.md)

## Goal

Starting from revised Desktop 0.4.2 commit `5998cfbe523f98809c6170a5d67bce499e684728`, ship one-source Mac Intel and Windows x64 Desktop 0.4.3. The release adds two observable and revocable Agent capabilities: structured control of the built-in browser and user-authorized control of multiple local applications. It also updates prompt navigation to the user-approved, high-visibility Codex-style rail.

The feature must not expose the Electron renderer, arbitrary JavaScript, a remote-debugging port, AppleScript, PowerShell, or unconstrained pointer/keyboard APIs to the model. Existing Harness approval, session ownership, tool lifecycle, and application cleanup remain authoritative.

## Scope

- Browser Control: navigation, semantic page snapshots, optional screenshots, referenced-element clicks, text input, keys, selection, scrolling, waits, back, forward, reload, and stop.
- Computer Use: enumerate grantable apps/windows, focus an app, return accessibility snapshots and optional window screenshots, click, double-click, drag, type, press keys/chords, scroll, and wait.
- Multi-app control through a user-managed application allowlist; one task may move between multiple authorized apps.
- One approval per ephemeral task through a short-lived `ControlLease`; known sensitive targets are denied, and mutations on a persistent human browser surface require an Electron-owned one-shot action challenge.
- Visible takeover state with app, window, session, status, and Stop controls plus a global emergency shortcut.
- Prompt rail navigation only, with no edit, rewind, delete, fork, draft restore, or automatic-send semantics.
- The same 0.4.3 source supports macOS and Windows through distinct native adapters, never shell-script parity theater.

## Non-goals

- Rewriting Harness, Electron, or the existing tool system.
- Duplicating Bash, PowerShell, Terminal, Jobs, Workflow, filesystem tools, or the sandbox.
- Reading passwords, one-time codes, payment-card data, keychain content, or OS security credentials.
- Automatically approving payments, publishing, sending, installation, removal, destructive deletion, trash emptying, or OS permission changes.
- Silent background control or a plugin bypass around the control indicator and stop mechanism.
- Arbitrary script injection, CSS/XPath selectors, IPC payloads, process injection, or raw operating-system APIs in the first release.

## Chosen Approach

### Adopted: two capability seams with native adapters

Add independent `browserControl` and `computerControl` Service Definitions, Host adapters, and model-facing tool Consumers. `desktop-control-protocol` is the sole source of every action, result, and branded ID DTO that crosses the Harness/Electron or Electron/helper process boundary; service packages reuse or re-export those types rather than copying them. The Harness child and Electron main process communicate over a dedicated, strongly typed IPC with a closed action vocabulary. The browser adapter reuses the built-in `WebContentsView`; the desktop adapter forwards bounded actions to an on-demand native helper.

The macOS 14+ helper uses AXUIElement for app, window, and control semantics; `SCScreenshotManager` with `SCContentFilter` and `SCStreamConfiguration` as the only capture path; and CGEvent for the closed action set. CoreGraphics is limited to window identity, coordinates, and CGEvent support, never capture fallback. The Windows helper uses UI Automation for the semantic tree, Windows Graphics Capture for authorized-window capture, and SendInput for the closed action set. Rust is appropriate for this native helper to provide stable native types, process isolation, and a shared protocol; this is not a rewrite of Harness in Rust.

### Rejected: a separate Playwright browser

A Playwright Bundle is straightforward to isolate, but duplicates Chromium, increases package size and memory, and cannot naturally control the built-in browser page the user is viewing or already signed into. It may remain a test dependency, not the product path.

### Rejected: shell, AppleScript, or PowerShell automation

Script automation is quick to prototype but unreliable for element identity, window ownership, scaling, cancellation, auditing, and platform parity. It also risks bypassing Harness approval. Scripts remain ordinary user-invoked commands and are not a Computer Use backend.

## Closed Protocol and Framing

Protocol v1 defines branded `RequestId`, `ControlLeaseId`, `BrowserRef`, `ComputerRef`, and `PngTransferId` values, reuses the official Harness `SessionId`, and carries `leaseRevision` wherever an active lease is scoped. Brands are not interchangeable. A checked-in machine-readable v1 manifest is the closed roster, field-matrix, and limit source used to generate or validate both TypeScript and Rust definitions; it cannot contain a generic schema escape. A strict decoder rejects duplicate JSON keys, unknown fields, unknown discriminants, wrong versions, and forbidden generic fields. No request or result accepts a generic `command`, `script`, `selector`, `javascript`, `method`, `args`, `env`, `cwd`, `path`, `channel`, `ipc`, `payload: unknown`, `data: unknown`, `Record`, or index signature.

Every cross-process value uses one outer binary frame. Tag `0x01` is followed by a UTF-8 JSON payload of at most 65,536 bytes, so the complete JSON frame is at most 65,537 bytes. Tag `0x02` is followed by a 16-byte transfer UUID and at most 4,194,304 raw PNG bytes, so the complete PNG frame is at most 4,194,321 bytes. JSON screenshot metadata declares `transferId`, `byteLength`, `sha256`, `width`, and `height`; the immediately following frame must be the matching PNG, and orphaned, late, mismatched, incorrectly hashed, or dimension-invalid PNG frames fail closed. Base64 is forbidden. Node IPC uses `serialization: 'advanced'` and sends exactly one `Uint8Array` frame per IPC message. Rust stdin/stdout prefixes that frame with a four-byte big-endian length whose value includes the tag and body; the reader rejects zero and values above 4,194,321 before allocation, then accepts split header/body reads and multiple sequential frames.

The top-level `messageKind` union is exactly `request`, `response`, or `control`. The 27-kind bridge request roster is exactly the internal-only `control.lease.acquire` and `control.lease.release`; `desktop.status`; `browser.snapshot`, `browser.navigate`, `browser.click`, `browser.type`, `browser.key`, `browser.select`, `browser.scroll`, `browser.wait`, `browser.back`, `browser.forward`, `browser.reload`, and `browser.stop`; and `computer.status`, `computer.list`, `computer.snapshot`, `computer.focus`, `computer.click`, `computer.double-click`, `computer.drag`, `computer.type`, `computer.key`, `computer.scroll`, `computer.wait`, and `computer.stop`. The two `control.lease.*` values are ordinary request discriminants used only by `desktop-control-host` and its Service consumers, not out-of-band control messages or model tools. Control messages are exactly `request.cancel`, `session.revoke`, `lease.revoke`, and `parent.shutdown`. A response is exactly `ok` or `error` and echoes `requestKind`. Error codes are limited to `NOT_SUPPORTED`, `UNAUTHORIZED`, `LEASE_EXPIRED`, `LEASE_REVOKED`, `STALE_REF`, `TARGET_CLOSED`, `PERMISSION_DENIED`, `POLICY_DENIED`, `DUPLICATE_REQUEST`, `TOO_MANY_PENDING`, `QUOTA_EXCEEDED`, `BINARY_MISMATCH`, `BUSY`, `TIMEOUT`, `CANCELLED`, `DISCONNECTED`, and `INTERNAL`; its UTF-8 `message` is at most 512 bytes and `retryable` is boolean.

Every bridge request has the official `sessionId`, request ID, request kind, protocol version, message kind, and deadline base. `control.lease.acquire` adds `surfaceKind` from exactly `browser-ephemeral`, `browser-human-persistent`, or `native-application`; a duplicate-free `capabilities` array drawn only from `observe`, `pointer`, and `keyboard`; and a closed `targets` array of `{ appId, windowIds[] }` entries that preserves each app/window relationship. Browser-surface targets must be empty. A native target request contains at least one app and at least one currently enumerated window per app and remains within the manifest's app, window, list, identifier, and JSON-byte limits. Electron intersects this desired subset with its current enumeration, ordinary allowlist, and fixed policy before showing its native challenge.

An acquire response is an immutable descriptor containing only `leaseId`, `leaseRevision`, `surfaceKind`, effective targets, effective capabilities, `idleExpiresAfterMs`, and `hardExpiresAfterMs`. It neither accepts nor returns quotas, absolute or monotonic clock values, `approved`, or an action digest. Electron responds only after the native challenge succeeds and, for native control, the helper acknowledges `lease.install`; an install failure returns no lease. `control.lease.release` adds only `leaseId` and `leaseRevision` to the common base and returns `{ released: true }` only after awaited revoke, queue clearing, browser/helper cleanup, and known-input release acknowledgement. Model tool schemas never expose either internal request or any transport, session, lease, revision, approval, quota, clock, or digest field; trusted providers derive the official session and populate those fields internally.

The helper request roster is exactly `status`, `list`, `snapshot`, `focus`, `click`, `double-click`, `drag`, `type`, `key`, `scroll`, `wait`, `stop`, `lease.install`, and `input.release`; `lease.revoke` is the idempotent high-priority control. Bridge requests carry `deadlineUnixMs`; Electron accepts only the strict interval `nowUnixMs < deadlineUnixMs <= nowUnixMs + 30,000`, captures `nowUnixMs` once for that decision, and may only shorten a valid deadline. For an active lease, the effective helper timeout is the minimum of the valid bridge time remaining, 30 seconds, and the hard-lease time remaining. The helper receives that positive duration as `timeoutMs` and immediately converts it to a local monotonic `Instant`. Every helper request contains `requestId`, `sessionId`, and `timeoutMs`. Requests scoped to an installed lease also contain `leaseId` and `leaseRevision`; only requests scoped to a target contain `appId`, `windowId`, and `snapshotRevision`. `input.release` is an Electron-only, approval-free recovery request with no lease fields; the child and model cannot issue it.

The Electron-authored snapshot carried by `lease.install` preserves targets as `{ appId, windowIds[] }` pairs instead of independent app and window sets, so an app from one grant cannot be combined with a window from another. It carries one total `operations` quota plus the existing `snapshots`, `pointerActions`, `keyActions`, and `textBytes` categories. Every lease-scoped request deducts one `operations` unit before dispatch and additionally deducts its applicable categories before their native calls. The child and model cannot propose quotas. `agentId` is display metadata only and is never used as authority or identity. Aggregate semantic text is capped at 49,152 UTF-8 bytes, and the complete encoded JSON payload, including all structural fields, must still fit within 65,536 bytes.

Electron permits exactly one process-wide active lease. Electron and the helper measure lease idle and hard expiry only with their local monotonic clocks and expire at the exact `>=` five-minute idle or `>=` twenty-minute hard boundary. Only an accepted lease-scoped action refreshes idle time; rejection, status, listing, acquisition, and release do not, and hard expiry never moves. Generation-bound timers cannot revoke a replacement lease. `leaseRevision` increases as a safe integer and fails closed instead of wrapping. Child wall time cannot extend any limit. The helper checks revocation between every native event and deducts the relevant event/action budget before each native call.

Malformed JSON, duplicate keys, unknown fields or discriminants, wrong versions, oversized JSON or PNG data, and invalid frame sequencing close the dedicated control channel. That closure rejects its control work but does not terminate Harness or impair ordinary chat.

The Host bridge, not the codec, owns the stateful request ledger. It permits at most 32 pending requests, rejects duplicate IDs, propagates cancellation, and retains bounded terminal tombstones so late replies cannot settle newer work. Each entry binds the request identity, kind, official session, child generation, deadline, and cancellation state; when and only when the validated request carries lease fields, it also derives and retains the optional exact `{ leaseId, leaseRevision }` tuple. A `lease.revoke` affects only entries whose session, lease ID, and lease revision all match, never an unleased request, another session, another lease, or another revision. Every child has a generation; listeners close over the exact child and generation and reject messages unless both still match the current owner, so an old child cannot answer for a replacement.

## Dedicated Harness/Electron IPC Link

Desktop retains the existing `spawn()`-based Harness launch and changes only its stdio contract to `['ignore', 'pipe', 'pipe', 'ipc']` with `serialization: 'advanced'`. Before spawning, it copies the ambient environment and removes inherited `NODE_CHANNEL_FD` and `NODE_CHANNEL_SERIALIZATION_MODE`; Node then creates fd 3 and its internal channel plumbing solely from the `ipc` entry. Application code never assigns either variable, opens fd 3, or converts the launch to `fork()`. One Node IPC message is exactly one copied, unprefixed raw `Uint8Array` protocol frame. The four-byte big-endian length prefix belongs only to the later Electron/helper stdin/stdout link and never appears on the Node IPC link.

Each link and direction has a separate fail-closed allowlist:

| Direction | Allowed messages |
| --- | --- |
| Harness → Electron | All 27 `BRIDGE_REQUEST_KINDS`, including the two trusted-provider-only lease requests; control only `request.cancel` for the same session and request, and `session.revoke` on Harness session disposal. Responses, PNG frames, helper-only requests, `lease.revoke`, and `parent.shutdown` are forbidden. |
| Electron → Harness | Only the closed bridge response union, followed immediately by its correlated screenshot PNG when metadata declares one; control only `lease.revoke`, which makes the child terminate matching-lease pending and future work, and `parent.shutdown`, which closes the client. Requests, `request.cancel`, and `session.revoke` are forbidden. |
| Electron → helper | All 14 `HELPER_REQUEST_KINDS`, including authority-only `lease.install` and `input.release`; all four control kinds are allowed only from Electron and are high priority. |
| helper → Electron | Only the closed helper response union, followed immediately by its correlated screenshot PNG when declared. Requests and controls are forbidden. |

Direction is validated on every decoded JSON frame before the image correlator may enter PNG-pending state. Therefore a wrong-direction image-bearing response closes the dedicated control link immediately even if its declared PNG never arrives; an orphan or wrong-direction PNG does the same. An unknown, malformed, or wrong-direction message never kills the Harness process, closes the ordinary Web transport, or impairs chat. Task 5 implements the two Node directions; Task 9 implements the helper directions without widening this table.

One `desktop-control-host` plugin instance creates one process-wide IPC client and one lease cache shared by the Browser Control and Computer Control providers. Both Service seams expose an internal `acquireLease` operation that reuses the protocol acquire DTO/result. A provider derives transport fields and the official session, requests the desired subset, caches only Electron's returned descriptor, and then issues the ordinary action. Snapshot methods return a typed immutable service envelope `{ result, png? }`: `result` owns the bounded protocol metadata, `png` is an `ImmutablePng`, and `result.image` and `png` are either both absent or both present after transfer ID, byte length, SHA-256, and dimensions have been correlated. No Service exposes mutable raw screenshot bytes. This flow adds no third Service and never exposes lease acquisition or authority fields to a model schema.

The Desktop-only Cordis patch is the host's only production mount; the Desktop manifest, project references, dependency lock, staging allowlist, staged-runtime assertions, package documentation, and generated module graph all include the same package. Desktop main keeps `@deepseek-ai/dsh-desktop-control-protocol` external in `apps/desktop/tsdown.config.ts`, so its runtime-relative `protocol-v1.json` remains beside the package. A stage-shaped import smoke and the staging allowlist require the protocol package's `package.json`, `lib/index.js`, `lib/invariant.js`, and `protocol-v1.json`; the Host package's `package.json`, `lib/index.js`, and `lib/invariant.js`; and the Browser/Computer Service packages' `package.json`, `lib/index.js`, and `lib/invariant.js`. A missing or disconnected control link leaves the providers unavailable but does not stop Harness startup.

The client and server each serialize whole JSON-plus-optional-PNG envelopes through one send-callback queue. They copy every frame before enqueue and do not begin the next envelope until every frame of the current envelope has completed its send callback, so concurrent screenshots cannot interleave. A transport decoder accepts one raw frame at a time, validates JSON direction before entering correlation state, and then keeps the required JSON/PNG adjacency state.

The ledger permits exactly 32 pending requests and retains at most 256 terminal request-ID tombstones. Each entry binds `requestId`, `requestKind`, official `sessionId`, child generation, deadline, cancellation state, and an optional lease tuple derived only from validated lease-bearing request fields. A response settles work only when its request ID and kind match the current pending entry; cancellation must also match that entry's session, while `lease.revoke` must match session, lease ID, and lease revision exactly. An exact revoke invalidates the shared cache before settling matching pending work once with `LEASE_REVOKED`; unrelated or unleased entries survive, a duplicate revoke does not refresh FIFO order or settle twice, and late responses are discarded through the existing tombstone. Electron rejects unless `nowUnixMs < deadlineUnixMs <= nowUnixMs + 30,000`, may shorten a valid deadline, converts only its positive remaining duration to `timeoutMs`, and never lengthens it.

Generation checks cover inbound messages, asynchronous provider completions, timeout and abort continuations, and send callbacks. Replacing a child increments the generation before any new listener is active; completions or callbacks captured by an older generation can only discard their detached copies. An unexpected process-level `disconnect` rejects all control pending work with `DISCONNECTED`, clears the bounded queues/listeners, and leaves the owned Harness process and ordinary chat running.

The Host uses the real awaited lifecycle boundary `agent/turn-stopping` for the normal path: it synchronously invalidates the matching lease cache and awaits a bounded `control.lease.release` tail before returning. Because `session/event` is post-commit fire-and-forget and error/cancellation paths need not reach `agent/turn-stopping`, the `turn/end` observer only invalidates synchronously and enqueues an idempotent per-session fallback release tail; it cannot guarantee release before the `turn/end` commit. The awaited `session/flush` listener drains that tail before the next checkpointed model or top-level tool side effect. `session/disposed` synchronously invalidates and enqueues `session.revoke`, while the plugin effect disposer and parent shutdown drain all release/revoke tails before detaching listeners. Transport cleanup failures make control unavailable but settle these listeners rather than breaking ordinary chat.

Normal application shutdown preserves the authority boundary of Task 6: Electron first stops admission, revokes sessions and leases, and awaits downstream browser/helper queue cleanup plus known-input release. A `HarnessProcess.beforeStop` hook owns the remaining control shutdown and is invoked by every internal or external stop path, including startup failure, retry, and quit; only then does it enqueue `parent.shutdown`, await its send callback within a bound, disconnect the exact Node IPC link, detach its listeners, and allow `HarnessProcess.stop()` to terminate the process tree. Task 5 supplies the transport hooks but does not mint leases or release native input. Transport logging is metadata-only: it may record direction, generation, bounded counts, and a closed reason code, but never frame bytes, decoded request/result content, semantic text, page or field values, PNG data, cookies, tokens, or absolute user paths.

## Browser Control Architecture

Electron main owns one global, exclusive Agent browser surface through a `BrowserSurfaceManager`; the process-wide lease coordinator rejects a second session with `BUSY`. Every mount has a surface generation and mount token, so a stale hide or cleanup callback cannot affect a replacement. An Agent-created surface is visible and uses a unique non-persistent partition that is cleared at teardown. The human workbench remains a persistent signed-in partition. **Give to Agent** creates only a main-owned intent that allows the next official child acquire request to present confirmation for the currently visible instance; the renderer neither mints a lease nor supplies session authority, and no cookie, local-storage value, or credential is exported.

Each `browser_snapshot` returns the URL, title, navigation revision, a bounded semantic tree of interactive elements, and a screenshot attachment only when a vision-capable model requests one. The adapter starts with `Accessibility.getRootAXNode` and performs bounded breadth-first `Accessibility.getChildAXNodes` traversal: at most 2,000 raw nodes, depth 32, 512 CDP calls, 2,000 ms wall time, and 300 projected actionable nodes. It may use allowlisted, read-only `DOM.describeNode` only to classify `type`, `autocomplete`, `disabled`, and `readonly`; `Runtime`, JavaScript evaluation, and selectors remain forbidden. Editable values are omitted by default, and uncertain sensitivity is denied.

Element references are opaque and tied to the surface generation and navigation revision. Debugger detach, surface destruction, main-document navigation, same-document navigation, or a material tree change invalidates them and discards late CDP replies. Browser actions accept only current refs; browser coordinate actions do not exist. `browser.wait` accepts only the closed mode `duration`, `navigation`, or `loading-idle`, with `durationMs` capped at 10,000. Screenshots may support model vision but never create a coordinate action path.

The manager tracks `attachedByUs`. If another debugger owns the surface, control returns `BUSY` and never detaches it; Stop awaits detach, view cleanup, partition clearing, and lease revocation before completing. Agent navigation rejects URL userinfo and loopback, link-local, or private destinations, including every redirect hop, unless the user has explicitly allowlisted that destination.

Page content is always untrusted. Page text cannot grant permissions, expand allowlists, approve sensitive actions, or instruct Harness to bypass policy. Popups, downloads, camera, microphone, location, clipboard reads, new windows, file inputs, uploads, and file choosers are rejected in 0.4.3.

## Computer Use Architecture

`computer_snapshot` binds to one authorized application and window, returning its accessibility tree and an optional screenshot. Semantic refs bind the process, window, snapshot revision, and display scale; a changed window makes old refs fail closed. The Agent prefers semantic refs. Coordinate actions are available only when no usable accessibility element exists and the selected model supports image input.

On Windows, target identity includes HWND, PID, and process-creation identity so reused handles or PIDs cannot revive a stale ref. The adapter refuses UIPI-blocked, high-integrity, and secure-desktop targets and never requests elevation.

The native helper implements only the closed helper roster and field matrix defined above. `status` does not invent target fields, `list` does not invent window or snapshot fields, and target-scoped actions carry only the target fields they require. The installed lease retains pair-preserving targets rather than independent app and window sets. Electron keeps a conservative journal of only keys and buttons known to be held. If the helper exits unexpectedly, Electron starts a fresh verified helper with the same binary hash and, in signed builds, the same code-signing identity, then uses Electron-only `input.release` to emit only the corresponding key/button-up events.

Normal shutdown is fixed as revoke lease → clear queues → release known input → receive release acknowledgement → close stdin with EOF → await exit → use a bounded terminate/kill ladder. `DesktopApplication` awaits this composite control shutdown before stopping Harness on quit, retry, helper crash recovery, and session disposal. Whole-machine power loss or simultaneously force-killing Electron and the helper cannot guarantee input release.

Models without image input are limited to DOM or accessibility semantics and cannot guess screen coordinates. Screenshots go through the existing Harness attachment service as ImageBlocks, never as unbounded base64 in IPC or logs.

## Authorization and Safety

Settings expose separate Screen Viewing and Assistive Control states. Missing permission produces a clear local status and a manual path to system settings; Harness does not loop prompts or modify system settings automatically.

Electron main mints the single process-wide short-lived `ControlLease` only after completing a native, user-visible approval challenge that Electron owns. The lease binds the official session, pair-preserving effective targets, effective capabilities, Electron-authored quotas, `leaseRevision`, and maximum lifetime. It expires at task completion, session switch, app restart, human takeover, the exact five-minute idle boundary, or the exact twenty-minute hard boundary. Settings can revoke one app or all grants. The child and model cannot submit `approved`, mint a lease, choose quotas, advance `leaseRevision`, or extend any deadline or lease clock.

Harness `ctx.approval` may request the interaction and provide approval UX, but its result alone is not authorization to install a lease or execute a sensitive final action; Electron must complete and verify its own native visible challenge in both cases. The approval coordinator permits one global pending dialog. A missing or hidden owner window, Escape, close, abort, exception, or competing request denies; a late approval must revalidate the official session, current target, lease revision, and allowlist. Installed Host plugins running in the same Harness Node process are part of the trusted computing base. Version 0.4.3 promises only that renderer messages, page text, and model output cannot forge Electron confirmation; it does not claim isolation from malicious in-process Host code.

Known password, secure-text, one-time-code, payment, and file targets are denied directly, as are biometrics, keychains/password managers, OS privacy/security settings, installation/removal, destructive deletion, and downloading or executing files. Page JavaScript can make an apparently ordinary interaction produce an external effect, so 0.4.3 does not claim that AX semantics can classify every sensitive outcome. An ephemeral Agent surface task lease authorizes only the fixed ordinary action roster. On a persistent human surface, every mutating `navigate`, `click`, `type`, `key`, `select`, `scroll`, `back`, `forward`, or `reload` binds to an Electron-owned one-shot action grant: a native challenge over an exact digest that is consumed once. Page content, the model, the renderer, and the child cannot supply, consume, or reuse the digest or grant. Stop is always approval-free.

Control always displays a top status pill with the Agent, current app, action state, and Stop. Version 0.4.3 has no Pause state or control. The menu bar or tray mirrors Stop. The default global emergency shortcut is `CommandOrControl+Shift+F12` and is configurable. It registers only while a lease is active; registration failure fails the grant closed. Rebinding is atomic, unregisters only the accelerator owned by this feature, and never calls `unregisterAll`. Its callback synchronously closes admission and revokes authority before awaiting cleanup. Stop runs the same awaited sequence and records a local audit event without screen content. Close-to-tray cannot hide the window until active-control cleanup completes.

Control settings use an independent strict schema and atomic file replacement. They persist only the ordinary app allowlist, ordinary switches, and accelerator—not window IDs, leases, refs, action digests, screenshots, or session authority. Rotated local audit rows contain only time, a salted session hash, opaque app ID, action class, and outcome; they exclude page or field text, URLs and queries, paths, screenshots, cookies, tokens, and other secrets.

## Prompt Rail

Use the user-approved first visual: a 28–32 px gutter at the left of the transcript with no panel or card timeline. Ordinary prompts use visible but restrained neutral-gray ticks. The active prompt uses a longer DeepSeek-blue tick with a hollow dot. Hover or keyboard focus displays “Prompt N · time,” up to two preview lines, and the current/total count.

The current ordinary tick references an undefined `--dsw-alias-label-quaternary`; replace it with a defined theme token plus fallback. The guide and ticks must remain visible in light, dark, non-Retina, and forced-colors modes. Long histories must not stack 120 overlapping button hitboxes: the rail maps pointer Y to the nearest anchor, while keyboard interaction uses roving tabindex, arrows, Home, and End. Narrow layouts collapse into a small Prompt Navigation button instead of silently removing the feature.

Clicking reads only the required history and scrolls to the exact user prompt, with a short theme-colored location highlight. It never edits history, creates a session, restores a draft, rewinds, deletes, or sends.

## Performance and Privacy

- The native helper starts on demand and exits when idle. With no control task, it performs no capture, accessibility polling, or high-frequency timer work.
- Browser tools prefer semantic diffs. Desktop captures are window-cropped and downsampled to model needs. Active control is capped at 2 FPS and idle capture is 0 FPS.
- Screenshots and semantic snapshots stay in bounded current-session attachments/tool results and never enter telemetry, ordinary logs, memory, or MSE candidates.
- Password values, cookies, local storage, authorization tokens, and hidden-window content are never returned to the model.
- A changed target returns `STALE_REF`; the Agent must snapshot again instead of blindly replaying coordinates.
- Actions per turn, snapshot bytes, semantic nodes, text length, and total lease time all have hard limits.

## UI and Error Handling

Settings add a Browser & Computer Control section matching existing setting cards. It reports platform support, OS permissions, authorized apps, default sharing mode, emergency shortcut, and the last local control state. The marketplace reports the Desktop-owned capability as loaded rather than permanently saying “restart to load.”

The built-in browser gains **Give to Agent / Stop takeover**. An ephemeral Agent browser opens visibly in the workbench. Sharing the current page shows a signed-in-state warning. Computer Use does not steal focus at startup; the first interactive action activates the target app.

Missing permission, closed windows, exited apps, occlusion, capture failures, unavailable accessibility trees, stale refs, non-vision models, and user stops return structured errors. They must not prevent Harness startup, block ordinary chat, or leave a helper, held key, active drag, or BrowserView behind.

## Tests and Acceptance

- Protocol tests validate the shared manifest; byte-exactly decode and re-encode checked-in raw `.bin` frames and a tiny PNG in TypeScript and Rust; and cover duplicate JSON keys; exact UTF-8 byte edges at 49,152 and 65,536 bytes; zero and oversized prefixes; split length headers and bodies; multiple frames; the strict `now < deadline <= now + 30,000` boundary, deadline shortening, and monotonic conversion; all 27 direction-gated requests; direction validation before image correlation, including a wrong-direction image response with no PNG; internal acquire/release fields and results; pair-preserving targets; total and category quotas; PNG correlation, hash, dimensions, orphaning, and lateness; non-interchangeable brands; frozen nested output; immutable PNG copies; and the forbidden generic field vocabulary. Schemas, stale refs, foreign sessions, expired leases, invalid actions, and unknown fields all fail closed.
- Browser tests cover a foreign debugger, detach, same-document races, bounded AX traversal, secure/file denial, stale mount tokens, cross-session `BUSY`, redirect-aware URL SSRF rejection, late CDP replies, ephemeral partition clearing, ordinary CLI/Web startup without a provider, explicit sharing, ref-only click/type/scroll/wait, and hostile page text that cannot authorize.
- Computer tests cover app/window identity, display scaling, semantic refs, coordinate fallback, input release, user stop, helper crashes, and parent disconnects.
- Lease and sensitive tests cover one process-wide lease; exact monotonic idle/hard boundaries; revision overflow; effective timeout; overall quota; exact session/lease-ID/revision revoke isolation; native-dialog pending, cancellation, and race cases; helper-install failure; renderer and `ctx.approval` forgery; persistent-browser one-shot mutations; settings and audit minimization; emergency-shortcut registration/rebind failure; awaited normal-path release at `agent/turn-stopping`; post-commit `turn/end` fallback drained by `session/flush`; disposer drain; and cleanup on session switch/disposal, disconnect, startup failure, close-to-tray, quit, retry, and helper crash. They explicitly do not claim fallback release precedes the `turn/end` commit and prove secure text, codes, payments, sends, installs, deletion, and system settings cannot execute silently under a normal lease.
- Model and Service tests prove typed immutable snapshot envelopes preserve correlated PNG bytes for vision models, while text models receive DOM/AX text only and cannot call coordinate actions.
- Rail tests cover valid theme tokens, light/dark/forced-colors snapshots, dense nearest-anchor hit testing, keyboard navigation, narrow-layout access, exact history reveal, and no side effects.
- Performance tests prove 0 FPS idle, on-demand helper startup, capture throttling, long-task memory bounds, and no surviving process after exit.

## Release Gates

0.4.3 cannot claim Computer Use merely because it launches an app. Release evidence must show a visible multi-step browser task and, on each platform, observation, clicking, typing, and stopping across at least two harmless test applications, with denial branches producing no side effects.

An explicitly labeled unsigned/unnotarized test release is allowed when signing credentials are unavailable, but it cannot promise persistent TCC or SmartScreen trust. When signing is configured, verification requires the nested helper and app to share one Team ID, use hardened runtime signing, and pass notarization; Windows verification likewise requires the signed helper and signed NSIS installer and must disclose SmartScreen status.

Every build comes from the final shared commit and a fresh `desktop-v0.4.3` tag. Public assets must be verified for uploaded state, size, SHA-256, checksum files, and one anonymous re-download. They must contain no keys, cookies, screenshots, user files, `~/.dsh` data, or local permission databases.
