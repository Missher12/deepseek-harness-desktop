# 本地外置大脑设计

[English](2026-08-24-local-external-brain-design.md) | 中文

**日期：** 2026-08-24

**状态：** 已批准实现

**目标：** DeepSeek Harness Desktop 0.3.8，Intel macOS 与 Windows x64

## 目标

为超长项目构建一个完全本地、可持续使用的外置大脑。系统需要跨会话记住项目事实，把重复的已审核记忆固化为短小、可回滚的知识胶囊，并通过 Missher Evolution System（MSE）学习可复用的工作方法。即使累积数万条记忆，它也应保持有效，同时不能把召回内容再次学习成不断自我强化的指令，更不能让后台维护成为 Harness 正常请求链路的依赖。

本次不连接 Obsidian 或任何远程知识库。安装包内置 TencentDB 兼容读取能力，将其作为可选本地旧版来源，但绝不打包用户的 `vectors.db` 或其他真实数据。记忆、学习和 Desktop 继续作为可独立升级的 Harness Bundle 交付，不合并成一个难以维护的核心分叉。

## 产品决策

- `dsh-missher-memory` 负责项目事实和情景记忆。
- `dsh-missher-evolution` 负责程序性规则：偏好、成功方法、失败规避以及 Candidate -> Trial -> Active 晋升。
- 新增 `@deepseek-ai/dsh-missher-brain` Bundle，统一协调检索、注入预算、来源展示和设置界面；它不保存项目事实或 MSE 规则。
- 只有已经审核的记忆可以参与语义固化。待审核候选可以确定性去重，但绝不会被自动批准。
- 新绑定项目默认开启自动固化。它只在空闲时有界运行，任何失败都放行聊天。
- 固化是“认知压缩”，不是破坏性压缩磁盘：原始已审核记忆会被归档并保留来源，只有用户显式操作才能真正删除。
- 固定记忆不会被任何自动维护修改。
- MSE 永不学习召回记忆、注入规则、子 Agent、维护会话或工具原始输出。
- Desktop 安装包内置 TencentDB 只读兼容代码。既有 TencentDB 数据始终位于应用包之外；全新安装不依赖它，系统也绝不写入、迁移、固化或学习其中内容。
- 所有组件都不持久化完整原始会话；继续以现有有界采集和敏感信息拒绝为权威边界。

## 架构

Desktop 组合三个可独立发布的包：

1. **Brain Hub（`@deepseek-ai/dsh-missher-brain`）**
   - 在受管 Desktop 组合中注册唯一的顶层 `agent/pre-step` 注入器。
   - 提供小型 Provider 注册表，并行请求有界贡献。
   - 统一执行总字节/条目预算、Provider 超时、信任标签、排序和来源元数据。
   - 提供统一“外置大脑”设置页面和每轮召回披露。
   - 只在用户修改协调设置后写入 `$DSH_HOME/missher-brain`；默认状态不落盘。

2. **记忆 Provider（`dsh-missher-memory`）**
   - 保留项目绑定、采集、候选审核、已批准记忆、隐私过滤、导出、遗忘和召回。
   - 新增 schema 2 索引检索、知识胶囊、维护记录、可回滚归档状态和迁移历史。
   - 在同一个不可变安装包中附带现有的隔离 `node:sqlite` TencentDB Reader 和 Worker，因此 Desktop 无需另装兼容组件。
   - Brain Hub 存在时向其注册；独立安装且没有 Brain Hub 时继续使用现有独立召回 Hook 和设置页。

3. **进化 Provider（`dsh-missher-evolution`）**
   - 继续独立使用 `$DSH_HOME/missher-evolution` 状态、审计、锁、维护和 Candidate -> Trial -> Active 生命周期。
   - 只向 Brain Hub 提交准备好的程序性规则。Brain Hub 精确确认最终注入的规则后，MSE 才记录已接受注入证据。
   - 没有 Brain Hub 时继续使用现有独立注入和设置页。

Desktop 固定先启动 Brain Hub，再启动两个 Provider。Provider 在启动时只协商一次受管或独立模式，从根源防止重复注入。Provider 缺失或失败只会减少可用背景，不得在配置超时之外拒绝或拖延原始模型决策。

## Provider 契约与每轮数据流

每个 Provider 实现包含四个有界操作的版本化契约：

- `status()` 返回可用于设置页、没有路径的健康状态和计数。
- `prepare(query, project, signal, budget)` 返回不可变贡献句柄、可安全展示的来源元数据和文本。
- `accept(handles)` 只记录被 Brain Hub 实际选中的贡献。
- `cancel(handles)` 释放准备状态且不记录使用。

顶层直接用户回合开始时，Brain Hub 使用已经绑定的项目身份，并行请求记忆和 MSE 贡献。它拒绝跨项目内容、过期准备句柄、敏感输出、超预算内容，以及任何被不可信来源标为命令的贡献。排序优先级依次为固定已审核事实、相关有效胶囊、已验证 Active MSE 规则、Trial 规则和单条已审核记忆，同时仍考虑相关性与新鲜度。

默认总注入上限是六条、4,000 UTF-8 字节，其中事实记忆最多 3,000 字节，程序性规则最多 1,000 字节；硬上限是八条、6,000 字节。所有 Provider 共用一个取消截止时间；超时或失败时原始下游 decision 原样返回。

注入内容明确分成“已审核项目记忆”和“已学习工作规则”。每条可见内容都携带稳定本地引用和记录时间。这些区块只是背景，不是用户或系统命令。子 Agent、委托会话、内部维护以及非第一步不会收到自动外置大脑注入。

## 长期记忆模型

现有 candidates 继续作为审核箱。现有 approved memories 变为不可变来源原子，包含项目、scope、kind、正文、来源候选 ID、固定状态、时间和生命周期状态（`active`、`archived` 或 `forgotten`）。Schema 2 新增：

- `memory_capsules`：带版本的摘要，包含项目、scope、主题键、kind、来源原子 ID、状态、校验和、时间和固化策略版本。
- `memory_fts`：为有效原子和胶囊建立 FTS5 索引；发布的 macOS 与 Windows 运行时必须证明支持 FTS5。中文和混合语言检索使用经过原生 fixture 验证的 tokenizer 配置。
- `maintenance_runs`：只记录开始/结束时间、触发方式、有界计数、结果类别和回滚引用，不记录记忆正文。
- `schema_migrations`：记录已经应用的迁移版本和时间。

v1 -> v2 迁移先创建仅用户可读的备份并验证本地密钥，再在一个事务中完成。失败时 v1 状态继续作为权威，只有新的外置大脑能力被停用。迁移和安装都不会删除候选、已批准记忆、项目绑定或旧版可选来源绑定。

## 内置 TencentDB 兼容能力

记忆安装包包含检查和查询兼容 `vectors.db` 所需的全部代码，因此 macOS 与 Windows 安装后不需要外部运行时、服务、脚本或安装后命令。数据库本身属于用户数据，永远不会进入签名应用、Setup 负载、Git 仓库、日志、测试或 Release 资产。

全新电脑上，该兼容来源显示“未连接（可选）”，内置项目记忆仍保持完整功能。既有来源只能通过当前显式 override 或未来的原生目录选择进行关联，目标必须解析为绝对真实目录。Reader 拒绝根目录/数据库符号链接、路径逃逸、扩展加载、任意 SQL、写操作、schema 不匹配和不安全权限；它在可终止 Worker 中以有界超时精确只读打开数据库。

TencentDB 结果只以单独标注的“旧版记忆”来源参与召回。Brain Hub 可以在当前回合隐藏完全重复或高度近似结果，但不会合并、复制、更新或删除任一存储。当前项目已审核记忆优先于旧版命中；存在矛盾时同时显示双方来源和时间。TencentDB 行绝不会进入候选采集、schema 2 FTS、自动固化、MSE 证据、导出、项目删除或重置。

## 自动固化

每个项目中，符合条件的原子存放七天并处于空闲状态后可以固化；有效已审核记忆超过 64 条或 96 KiB 时也会触发。除非用户点击“立即整理”，同一项目每 24 小时最多执行一次。单批最多包含 24 条同项目、同 scope、kind 兼容的原子，以及 12 KiB 输入。

处理流程：

1. 规范化并确定性合并完全重复内容。
2. 建立有界词法相似组；绝不混合项目、个人/项目 scope 或不兼容 kind。
3. 排除固定、最近编辑、敏感、已经被替代和存在未解决冲突的原子。
4. 至少存在四条兼容原子时，才请求配置的低成本 Harness 模型生成短胶囊。模型不可用时仍完成精确去重，语义固化延后。
5. 校验输出长度、UTF-8、隐私、来源 ID、项目/scope 一致性和标识符忠实度。输出出现所有来源都不存在的新数字、路径、哈希、URL 或代码标识符时，拒绝胶囊。
6. 在一个事务中写入胶囊并归档来源原子。原子继续保留，可以展开、导出或恢复。

模型永远不会收到凭据、绝对项目路径、工具原始输出、待审核候选或完整会话；输入只有有界的已审核原子正文和不透明来源 ID。结果被拒绝、超时或格式错误时只记录固定失败类别，所有来源原子保持有效。

回滚会在一个事务中把胶囊标记为已替代，并重新激活其来源原子。删除胶囊也不会删除来源原子。物理清除已归档来源不会自动执行，属于本次范围之外的独立破坏性操作。

## MSE 集成与反馈隔离

Desktop 把经过审核的 MSE Harness 包作为应用所有的内置回退，同时允许配置目录内更新版本覆盖它。从插件市场移除更新版本后会回退到 Desktop 副本，不删除 MSE 状态。

这里使用的是 Harness 原生 MSE 特供版：由 TypeScript/Cordis 适配器直接消费 Harness 生命周期事件并使用 Harness 本地状态。它不加载 Hermes Python 插件、飞书通知、Cron、Gateway 或 Hermes 运行状态。

MSE 只观察顶层直接用户提示、已经提交的助手结果、顶层工具结果类别和用户明确纠正。Brain Hub 注入的背景不会被当作用户文本。准备规则只能使用一次，且只有 Brain Hub 将其放进最终预算后才被接受。维护、健康检查、MSE 诊断、后台固化、召回记忆和嵌套 Agent 永久排除在学习之外。

事实记忆和程序性规则不会把记录复制到对方存储。项目决策继续属于记忆；重复工作方法只有在独立直接回合证据充分时才可能成为 MSE 规则。该边界可防止召回内容被再次学习成更强规则。

## 用户体验

受管 Desktop 设置中，以一个“外置大脑”页面替换“项目记忆”和“进化”入口；独立安装插件时仍保留各自原生页面。统一页面遵循现有设置几何规范，包含：

- **总览：** 当前项目、Brain Hub 健康、记忆/MSE 健康、可选旧版来源状态、有效数量、最近成功固化和占用空间。
- **记忆：** 采集与召回、候选审核箱、已批准原子、胶囊、固定/遗忘和展开来源。
- **自动整理：** 开关、阈值、最近运行、固定失败类别、“立即整理”、历史和胶囊回滚。
- **学习：** MSE 开关、Candidate/Trial/Active 数量、状态迁移、暂停/退役和最近维护状态。
- **数据：** 项目导出、备份状态、项目删除和显式状态重置边界。

使用外置大脑的助手回合显示类似“2 条记忆 · 1 条学习规则”的紧凑提示。展开后可以看到注入文本、来源类型、本地引用和记录时间，但不会显示文件路径、状态数据库路径、本地密钥或原始会话标识。

## 性能与资源限制

- 在发布参考机器上，缓存准备过程增加的 p95 延迟不超过 50 ms。
- 冷 Provider 工作受现有 1.5 秒 fail-open 截止时间限制，并且永不触发固化。
- SQLite 写入和固化通过串行 Worker 边界运行，不占用 Renderer 或主模型事件循环。
- 活跃聊天、可检测的低电量、应用关闭、数据库争用或已有 Provider 锁会暂停维护。
- 50,000 条原子 fixture 在 Intel macOS 与 Windows x64 CI/参考机器上，索引检索 p95 低于 150 ms，内存占用有界。
- 启动阶段只读取 schema 元数据和小型计数。完整历史和 FTS 分页按需加载，先绘制稳定占位，再填充数据。

## 失败、隐私与恢复

三个 Bundle 对聊天全部 fail-open。状态损坏、版本不兼容、锁定或路径不安全时，只显示不含路径的诊断，不自动重置。继续禁止状态根/数据库符号链接、路径逃逸、扩展加载、任意 SQL、跨项目查询和 Renderer 凭据访问。

隐私过滤在候选写入前、固化输入前、固化输出后和召回注入前分别运行。审计只包含固定动作类别、不透明引用、计数、耗时和结果类别，不包含提示词、记忆正文、规则、凭据或绝对路径。

卸载保留 `$DSH_HOME/missher-brain`、`$DSH_HOME/missher-memory`、`$DSH_HOME/missher-evolution`、会话、凭据和无关插件状态。重置和项目删除继续是带备份与确认要求的停写操作。

## 交付阶段

1. **基础层：** 发布并内置经过审核的 MSE 包；增加版本化 Brain Hub Provider 契约、受管/独立协商、统一预算和禁止双重注入测试，不改变记忆 schema。
2. **长期固化：** 把记忆状态迁移到 schema 2，增加 FTS5、胶囊、空闲 Worker、校验、备份、回滚和长历史测试。
3. **产品集成：** 交付统一设置页、每轮召回提示、插件市场回退、升级/迁移体验，并从同一源码提交生成原生 Desktop 成品。

每个阶段必须可以独立发布，并且在关闭新能力后保持当前 0.3.7 行为。

## 验证

聚焦测试覆盖 Provider 协商、阻止重复注入、共享取消、预算仲裁、跨项目拒绝、子 Agent 排除、MSE 单次接受、召回不参与学习、schema 迁移与回滚、精确去重、胶囊校验、固定记忆排除、冲突处理、审计脱敏和 fail-open。

属性与故障测试覆盖迁移中断、Worker 终止、锁竞争、畸形模型输出、敏感字符串、FTS 查询攻击、大型项目、重复固化和回滚幂等性。包校验拒绝安装脚本、内置状态、数据库、密钥、包含状态样本的 source map 和未声明文件。

Intel macOS 与 Windows x64 原生验收把同一份不可变插件构件安装进隔离 `DSH_HOME`，绑定项目、采集并批准 fixture、固化和回滚胶囊、推进一条 MSE 规则、证明只有一次带可见来源的组合注入，然后执行重启、升级、卸载和状态保留验证。公开 Release 资产必须记录精确大小、SHA-256、uploaded 状态和匿名重下载一致性，并且不得覆盖无关平台资产。

兼容验收另使用一份 fixture `vectors.db`，证明只读打开、有界搜索、来源标注、重复抑制、矛盾展示、超时终止，以及安装、召回、固化、重置、升级和卸载前后数据库内容逐字节一致。另一份全新安装 fixture 不包含 TencentDB 目录，必须显示健康的内置外置大脑且不会创建该目录。

## 不在范围内

Obsidian、远程知识库、云同步、写入或迁移 TencentDB、打包任何真实数据库、新增 Embedding 或托管向量数据库、自动批准候选、自动删除来源原子、未显式绑定的跨项目召回、模型微调、自动修改源码、与 Hermes MSE 共享运行中状态，以及修改官方 Harness 会话格式均不属于本次交付。
