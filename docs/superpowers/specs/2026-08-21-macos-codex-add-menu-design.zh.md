# DeepSeek Harness 0.3.2 Codex 风格添加菜单

[English](2026-08-21-macos-codex-add-menu-design.md) | 中文

## 目标

把输入框原本朴素的 `+` 命令列表替换成 2026-08-21 确认的紧凑 Codex 风格「添加」菜单。保留全部现有命令、Skill、附件、键盘和无障碍行为；只调整入口的组织与呈现。

该功能会进入共用 Web 输入框，但本任务只构建、安装和发布 Intel macOS Desktop 0.3.2 成品。

## 用户可见结构

菜单是锚定在输入框 `+` 按钮上方的紧凑白色浮层。

1. **添加**
   - **文件和文件夹**：打开现有 `@` 引用候选流程，并插入选中的文件或文件夹引用。
   - **添加图片**：打开原生浏览器文件选择器，只接受输入框已有支持的图片格式；选中的图片继续使用现有校验、预览、移除和提交路径。
   - **目标**：进入现有 `/goal` 流程，让用户描述持久目标。
   - **计划模式**：调用现有 `/plan` 行为。
2. **插件**
   - 动态列出当前会话真正可以调用的 Skill 或命令。
   - 每行显示图标、名称和一行描述；过长描述截断，不撑宽浮层。
   - 可用条目较多时，列表在现有高度上限内滚动。

只提供市场界面的 UI 插件不会被列为可调用操作。展示一个无法从聊天中调用的插件会制造无效控件。

## 交互与数据流

- `+` 按钮通过现有会话持有的输入触发控制器打开专用多来源入口。
- 固定添加操作和已安装 Skill 来源共用一个菜单状态，因此键盘高亮、`ArrowUp`／`ArrowDown`、`Enter`、`Escape`、点击外部关闭和文本框焦点保留仍走当前流水线。
- 文件／文件夹转交给现有引用来源，不引入第二套文件浏览器。
- 图片选择把选中的 `File` 对象交给现有 `intakeImages` 路径。因此格式、数量、单文件大小和总大小错误继续使用当前本地化提示。
- 目标和计划复用现有命令；菜单不会创建平行的目标或计划状态。
- Skill 发现复用当前会话 Skill 目录，并继续按照 subagent 与 Agent 预设的能力过滤。

## 呈现

- 紧凑浮层匹配已确认参考：12px 分区标题、32px 行高、克制的 7px 圆角、轻微边框／阴影，以及当前 Harness 主题 token。
- 选中／悬停行使用现有中性互动填充；不使用渐变、粒子特效或超大卡片。
- 主文案和次文案保持单行，描述使用较弱颜色。
- 明暗主题继续由 token 驱动；菜单不能在浅色主题之外硬编码永久白色表面。
- 现有通用键入式 `/` 与 `@` 建议菜单保持当前行为；Codex 风格组织只应用于程序化 `+` 入口。

## 失败处理

- 某个动态来源失败时，其分组使用现有加载／故障安全状态，不阻塞固定添加操作。
- 缺少附件或引用能力时，隐藏或禁用对应操作，不展示无效行。
- 取消文件选择不执行任何操作。
- 命令或 Skill 在显示后、点击前失效时，沿用当前过期 pick 的无操作行为。

## 验收

- 点击 `+` 会渲染确认过的添加／插件层级。
- 文件／文件夹打开现有引用选择并插入有效引用。
- 添加图片接受有效图片、显示现有预览，并通过现有文案拒绝不支持文件。
- 目标和计划进入它们当前的真实命令流程。
- 已安装的可调用 Skill 可见且可选；不会把不可调用的市场页面误标成操作。
- 鼠标和键盘选择均可用，文本框焦点保留，菜单可通过 `Escape` 或点击外部关闭。
- 现有键入式 `/` 与 `@` 菜单、发送／停止、推理等级、会话通信、插件市场、使用统计、工作台和更新器行为保持不变。
- 发布 0.3.2 前，聚焦单元测试、相关 Web／Desktop 测试以及打包后 Intel macOS 烟雾测试全部通过。
