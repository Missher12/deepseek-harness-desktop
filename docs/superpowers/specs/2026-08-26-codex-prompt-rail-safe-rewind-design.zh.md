# Codex 风格发言刻度与安全回退设计

[English](2026-08-26-codex-prompt-rail-safe-rewind-design.md) | 中文

## 目标

在不改写或删除原会话历史的前提下，为 DeepSeek Harness 增加两项跨平台共用能力：

1. Codex 风格的发言刻度（Prompt Rail），用于定位本会话中用户曾经发送的消息。
2. Codex 风格的“编辑并从这里继续”与“从这里继续”，通过创建保留谱系的新会话实现安全回退。

Mac 与 Windows 使用同一套 Web、Client Runtime 和 Host 行为；Desktop 壳层不复制一份平台专属实现。

## 已有基础

Harness 已经具备持久化会话、按消息分页、稳定事件序号、会话谱系和 `session.fork`。已完成轮次的助手消息也已经提供分叉按钮。因此本功能应扩展现有分叉语义与消息操作条，而不是新增一套“回退数据库”或直接裁剪 JSONL／SQLite 历史。

## 交互设计

### 发言刻度

- 刻度位于对话滚动区右侧空白带内，以覆盖层呈现，不压缩消息列，也不改变工作台面板宽度。
- 每个刻度对应一条真实用户输入；普通轮次和轮中追加消息都可导航，但轮中追加消息只提供定位，不提供编辑回退。
- 当前视口附近的刻度高亮；最近一条用户消息使用更强的品牌色。
- 点击刻度精确滚动到对应用户气泡。目标位于尚未加载的旧分页时，按需加载更早历史，期间只在该刻度显示轻量进度，不阻塞当前阅读。
- 悬停或键盘聚焦显示时间和最多 48 个字符的本地预览。预览不包含上下文注入、工具输出、思考过程或附件内容。
- 只有一条用户消息时不显示整条刻度栏；窄窗口保留细刻度和键盘操作，不引起内容重排。
- 支持上下方向键、Home、End 与 Enter；减少动态效果时使用瞬时滚动。

### 消息操作

- 用户气泡沿用现有悬停操作条，增加“编辑并从这里继续”。点击后不自动发送。
- 已完成轮次的助手消息保留现有分叉按钮，用户文案调整为“从这里继续”。
- “编辑并从这里继续”创建一个位于目标用户消息之前的新分支，打开新会话，并把原消息文字与可恢复附件放入输入框供用户修改。
- “从这里继续”创建一个包含该完整已完成轮次的新分支并打开它。
- 原会话、原回复和后续内容始终保留；侧栏中的新会话沿用现有递增标题与 `parentSession` 谱系。
- 当前 Agent 正在运行、目标轮次尚未结束、目标不是轮次首条用户消息或历史尚未持久化时，编辑回退不可用，并显示具体原因。
- 不增加常驻“撤回”大按钮，也不在本阶段提供永久删除历史。

## 数据与接口

### Prompt Anchor

首个 `session.history` 尾页响应在同一次历史读取中附带轻量 `promptAnchors`，避免额外网络往返：

```ts
interface PromptAnchor {
  seq: number
  turn: number
  time: number
  kind: 'turn-opening' | 'steering'
  preview: string
  completed: boolean
}
```

Host 从同一份权威事件切片生成该投影；Client Runtime 在实时 `user/message` 与 `turn/end` 到达时增量更新。该字段只是传输投影，不改变 Session 格式，不触发日志版本升级。大量锚点采用固定高度的虚拟列表，只挂载可见区域，避免长会话产生大量 DOM。

### 安全分叉

现有 `session.fork` 保持默认的 `through-turn` 行为，并增加向后兼容的可选位置：

```ts
type ForkPosition = 'through-turn' | 'before-turn'
```

- `through-turn`：保持现有语义，包含目标消息所属的完整已完成轮次。
- `before-turn`：验证 `atSeq` 确实指向该轮次首条普通用户消息，并将子会话种子截在对应 `turn/start` 之前。
- 第一轮之前允许空种子子会话；仍继承 cwd、Workspace、Agent Preset、父会话谱系，以及目标轮次当时使用的 provider、model 与 reasoning effort。
- Host 是最终鉴权和竞态裁决者。即使 Client 按钮尚未刷新，Host 也会拒绝运行中、开放轮次、非法序号和非轮次首消息。
- 同一手势只允许一次在途分叉，防止双击产生两个子会话。

### 草稿交接

Client 在创建分支前从源会话读取目标消息；图片通过源会话现有附件授权读取为临时草稿数据，在新会话发送时重新进入正常附件持久化流程。无法完整读取附件时不创建分支，并给出可重试提示。分叉成功但页面切换失败时，子会话仍保留在侧栏并明确提示，不自动重试创建。

## 状态流

1. 打开会话时，尾页历史和完整轻量锚点一次返回。
2. 点击刻度仅导航；需要旧分页时串行按需补页，并保持阅读锚点。
3. 点击“编辑并从这里继续”后，Client 先准备草稿，再请求 `before-turn` 分叉。
4. Host 验证源会话和边界，创建并持久化带谱系的子会话，附加到同一 Workspace。
5. Client 打开子会话并注入尚未发送的草稿；只有用户再次点击发送，才开始新的模型轮次。
6. 任一步失败都不修改源会话。

## 性能与兼容

- 锚点在既有尾页历史读取中折叠，不增加启动或打开会话的第二次请求。
- 不后台加载全部消息正文；只有用户点击尚未加载的旧刻度时才补页。
- 刻度栏使用 `IntersectionObserver` 和虚拟窗口，不采用持续轮询或逐帧全列表测量。
- 不改变会话事件格式、现有 `session.fork` 调用方、跨会话通信、归档、记忆、插件市场或模型选择逻辑。
- 子会话继续使用现有持久化与恢复路径，官方 Harness 后续升级只需处理普通可选 RPC 字段和 UI 投影。

## 不采用的方案

### 直接裁剪原会话历史

问题：破坏恢复能力，并会牵涉 JSONL、SQLite、投影、附件、统计和遥测的一致性。

影响：一旦边界或写入中断处理错误，原项目内容可能永久丢失。

推荐方案：以 `parentSession` 分支表达回退，原历史只读保留。

### 只做前端假回退

问题：隐藏旧消息但仍把它们发送给模型，或者刷新后重新出现。

影响：用户看到的上下文与模型实际收到的上下文不一致。

推荐方案：由 Host 创建具有精确种子边界的新会话。

### 打开会话时预加载全部正文

问题：超长会话会放大磁盘、传输、渲染与内存成本。

影响：违背现有分页和加载速度目标。

推荐方案：一次返回轻量锚点，正文仅按需分页。

## 验收标准

- 普通会话、长会话、归档后恢复的会话均显示准确刻度；上下文注入和工具输出不产生刻度。
- 点击已加载和未加载刻度都能落到精确用户消息，分页前后无滚动跳变。
- 缩放窗口、切换工作台工具、切换会话后刻度位置稳定，不挤压消息列。
- 首轮、中间轮、末轮的 `before-turn` 分叉均得到正确种子；源会话事件和持久化文件保持逐字节不变。
- 子会话继承 cwd、Workspace、Preset、模型和思考等级；新消息只在用户确认发送后进入模型。
- 运行中、开放轮次、steering、坏序号、重复点击、附件读取失败和 Workspace 附加失败均有确定行为且不产生重复分支。
- 键盘、屏幕阅读器、减少动态效果和中英文文案验收通过。
- 现有分叉、历史分页、消息操作、跨会话通信、归档与打包 smoke 全部通过。
- Mac 与 Windows 原生成品必须来自同一提交；安装验收只验证本功能的共同源码行为，不引入平台分叉。
