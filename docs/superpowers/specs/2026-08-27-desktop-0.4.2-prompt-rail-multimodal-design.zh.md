# Desktop 0.4.2 发言刻度与自定义多模态模型设计

[English](2026-08-27-desktop-0.4.2-prompt-rail-multimodal-design.md) | 中文

## 目标

以公开 0.4.1 源码为基线，使用同一份源码提交交付 Mac Intel 与 Windows x64 Desktop 0.4.2：加入 Codex 风格的发言导航刻度，但不加入回退语义；同时允许用户准确声明自定义模型是否支持图片输入。

## 范围与非目标

- 保留 0.4.1 的全部会话数据、插件、设置、模型路由、推理控制和原有官方分支行为。
- 在聊天记录左侧增加已完成用户发言与 steering 消息的导航刻度。
- 删除旧 0.4.2 新增的“从此处编辑”、轮次前分支、草稿恢复和回退入口。刻度不会创建会话、改变历史、恢复草稿或发送消息。
- 为自定义 `pi-ai` 模型增加“输入能力”设置：自动、仅文本、文本与图片。
- 只有上游明确返回可识别的能力元数据时，才采纳自动发现的输入模态；模型名称和 ID 不能作为能力证据。
- NewAPI 专用上下文窗口发现和其他供应商改动不属于本版本。

## 发言锚点数据

Host 从初始历史响应使用的同一份不可变会话事件切片中，投影轻量的全历史 `promptAnchors` 索引。每个锚点包含事件序号、有长度上限的规范化预览，以及该消息是开启新轮次还是在运行轮次中 steering。初始索引已经覆盖该切片内所有可达发言，因此向前翻页只需传递消息正文。

Client 将锚点与渲染后的消息组分开保存。点击锚点时，只调用现有历史分页能力读取到包含目标序号为止，然后滚动到准确的用户消息。目标已被压缩或无法取得时显示无副作用的不可用状态，不能跳到相邻消息代替。

锚点投影仅用于导航，不改变会话日志格式、模型可见上下文、轮次分组、分支边界或源会话内容。

## 发言刻度体验

刻度位于聊天记录左侧的独立窄边栏，不覆盖消息，也不改变消息列宽度。开启新轮次的发言使用较长刻度，steering 发言使用较短刻度；最接近视口中心的锚点使用 DeepSeek 主题色。超长会话按需合并相邻锚点，只渲染有上限的刻度，同时保留最早与最新可达区域，并记录每个可交互刻度所代表的准确锚点。

鼠标悬停或键盘聚焦时显示统一风格的预览浮层，内容为规范化并截断后的发言文本。点击、Enter 和 Space 都可跳转。当前刻度根据消息在视口中的实际位置更新，而不是仅记录最后一次点击。系统开启“减少动态效果”时取消动画滚动；窄屏直接隐藏刻度，不能覆盖正文。

刻度没有编辑、回退、删除后续内容、创建子会话、恢复草稿或自动发送操作。被替换的旧 0.4.2 所新增的“从此处编辑”控件不进入本实现。

## 自定义模型输入能力

每个已声明的 `pi-ai` 模型提供“输入能力”选择：

- 自动：省略模型级 `input` 字段，继承可信的已安装目录条目或路由默认值。
- 仅文本：保存 `input: ["text"]`。
- 文本与图片：保存 `input: ["text", "image"]`。

编辑器修改能力时保留其他现有字段与未来字段。没有 `input` 的旧配置继续保持“自动”，因此不会重写用户模型文件，也不会静默打开图片能力。

模型发现通过 Host API 传递可选输入模态。供应商解析器只识别支持的顶层字段或 architecture 字段中明确返回的文本与图片模态，规范化已知别名，并忽略缺失、空值和未知值。采纳模型时仅在存在可靠元数据的情况下写入发现结果；不得根据 `vision`、`vl` 等名称片段或供应商名称推断视觉能力。

解析后的模型能力仍是附件准入的权威依据。自定义模型解析结果包含 `image` 时允许图片附件；仅文本模型继续在发送请求前拒绝图片。

## 失败处理与兼容

- 历史分页失败不影响继续聊天，并将所选锚点显示为不可用。
- 重复、畸形或乱序锚点在 API 与 Client 边界拒绝或去重。
- 未知发现元数据不能扩大模型权限。
- 本版本不读取、输出、迁移或打包供应商凭据。
- 任何操作都不得删除或重写 `~/.dsh`、Desktop 用户数据、会话、记忆数据库或已安装外部插件。
- Mac 与 Windows 安装包来自同一源码提交。发布环境没有签名凭据时，继续明确未签名或未公证边界。

## 验收

- Host 测试覆盖最近与分页锚点、steering 分类、文本规范化、顺序、去重和超长历史。
- Client 与 UI 测试覆盖数量上限、首尾可达、当前刻度更新、悬停和键盘预览、准确分页与滚动、目标不可用、窄屏和减少动态效果。
- 回归测试证明刻度操作不会调用编辑、分支、草稿恢复、发送、删除或历史修改路径。
- 模型配置测试覆盖自动、仅文本、文本与图片、目录继承、路由默认回退和其他字段保留。
- 发现与 API 测试覆盖支持的明确元数据、别名、空值、未知值和采纳往返。
- 附件测试证明声明图片能力的自定义模型可以接收图片，仅文本模型仍会拒绝。
- 打包前通过无密钥产品快照、聚焦单元测试、类型检查、Lint、构建和文档检查。
- Mac DMG 通过 packaged smoke 与 `hdiutil verify`。Windows Setup 必须从同一提交通过原生可见安装、启动、关闭、卸载、快捷方式清理和 Harness 数据保留验收。
- 替换本机 Mac 应用时先备份已安装的 0.4.1，保留 `~/.dsh`，安装已验收的 0.4.2，并在删除备份前验证版本、架构、Harness 就绪和数据不变。

## 发布替换

只有修正版源码合并且两端原生安装包都验收通过后，才替换已经公开的 `desktop-v0.4.2` Release。删除前重新解析现有 Release 与 tag 的准确目标；替换 tag 必须指向最终共同源码提交。公开资产以 `uploaded` 状态、准确大小、SHA-256、校验文件验证和每个平台一次匿名下载为准。

复用 0.4.2 存在兼容代价：已经安装旧 0.4.2 的客户端可能不会识别同版本替换，中间缓存也可能短暂返回旧文件。Release 说明必须写明这一边界，并提供按 SHA 校验的手动替换方式。本机当前为 0.4.1，因此可以正常识别更高版本的 0.4.2。
