# `dsh-lark` Harness 命令中心设计

[English](2026-08-26-dsh-lark-command-center-design.md) | 中文

**日期：** 2026-08-26

**状态：** 已批准实现

## 目标

把已配对的飞书私聊变成可独立移除的 Harness 远程开发命令中心。所有者发送精确文本 `/` 后，机器人必须立即返回完整命令目录且不调用模型。所有者随后可以选择当前项目和 Session、新建或重命名 Session、查看或切换模型与推理档位、执行明确允许的 Harness 命令、查看 skill、工具、后台任务、subagent、token 用量和诊断，并继续把普通开发消息发送到同一个 Harness Session。

## 交互约定

飞书不会把文本框里尚未发送的按键暴露给机器人。因此支持的交互是：所有者输入 `/` 并发送，然后收到一张命令中心卡片。`/进入` 与 `/切换` 保留项目和 Session 选择器。需要自由文本的命令继续使用文本形式，因为按钮不能安全地猜测标题、目标或计划内容。

命令中心按类别显示所有受支持命令及其精确语法。按钮覆盖安全且无需参数的操作，例如进入项目、新建 Session、打开模型或推理选择器、压缩上下文，以及查看状态、skill、工具、任务、用量或诊断。每个回调都绑定所有者、私聊、代次、有效期和一次性 nonce。

## 命令范围

首个版本暴露以下所有者命令：

- Session：`/进入`、`/切换`、`/新建`、`/重命名 <标题>`、`/解绑`、`/状态`、`/停止`。
- 模型与执行：`/模型`、`/推理`、`/压缩`、`/目标 <内容>`、`/计划 [内容|off]`、`/权限 [预设]`、`/插话 <内容>`。
- 发现：`/技能`、`/工具`、`/任务`、`/用量`、`/诊断`、`/帮助`。

Harness 原生英文形式 `/compact`、`/goal`、`/plan` 和 `/permission` 通过同一固定远程安全桥接受。只有当精确名称出现在当前 Session 的用户可调用 skill 目录中时，才接受 `/skill-name ...`；随后它会作为普通可见用户消息进入既有的持久化 Lark FIFO，由 Harness 的 skill 前置步骤负责调用。

不复制 OpenClaw 独有的网关、频道、语音、浏览器、OAuth、配置、重启和管理命令。仍然排除仅浏览器可用的 `/export`、持久权限提升、任意命令透传、任意工具执行、shell 快捷命令，以及从 Harness 主机上传文件。

## Harness 原生数据流

每条命令都先通过现有的配对所有者门禁。绑定 Session 的操作会重新读取持久化绑定，并通过既有 Harness 普通 Session 策略解析精确的普通 Agent 后才执行。

Session 新建使用已绑定的 `workspaceId` 调用 `sessions.create`，然后只在校验项目成员关系和 cwd 后绑定返回的精确普通 Session。重命名、模型目录、模型选择、推理选择、skill 列表和 subagent 列表使用既有 Host API。原生命令通过固定白名单调用当前 Agent 的 `ctx.commands` 注册表。工具名称来自当前 Agent 作用域内的 `ctx.tools` schema。后台任务来自可选的所有者作用域 `ctx.jobs` 视图。命令中心操作不会修改 Harness 核心或 Desktop 会话存储。

普通文本和已准入的 skill 调用继续进入 `DurableLarkInbox`：每个飞书事件一条持久化记录、预分配 Harness Message ID、严格 FIFO 的领取/终态栅栏，以及重启对账。因此消息仍会作为普通用户消息显示在 Harness 会话中，而不是隐藏的上下文注入。

## 模型和推理卡片

`/模型` 读取新鲜的 Session 模型目录，并渲染提供方/模型按钮，同时标记当前路由。模型回调只携带提供方和模型标识，并在点击时由 `sessions.selectModel` 重新校验。`/推理` 读取同一个目录，找到当前精确路由，并且只渲染该模型声明的推理档位。卡片标记当前值和默认值，绝不臆造不支持的档位。

大型模型目录拆成提供方卡片和模型卡片，使飞书卡片大小保持有界。回调数据继续遵守现有四键上限。失败的提供方目录只做摘要，不暴露凭据或端点配置。

## 只读视图

`/技能` 显示当前用户可调用 skill 及有界描述。`/工具` 只显示作用域内的工具名称，不显示 schema、参数、结果或密钥。`/任务` 显示所有者可见的后台任务和直接 subagent，并限制标签长度与生命周期状态。`/用量` 折叠有界的最近 Session 历史，只报告最新已完成 assistant 消息的真实用量，不估算缺失数据，也不重复计算分片。`/诊断` 仅以脱敏布尔值或数量显示连接、配对、绑定、队列、Agent 状态、模型可路由性和能力可用性；绝不显示凭据、卡片 nonce、飞书身份或原始工具 payload。

## 失败与隔离

业务错误渲染为简短的所有者提示。命令失败不会加入模型轮次、修改其他 Session 或禁用传输。Session 新建是唯一的多步骤写操作：如果新建成功但绑定异常失败，回复会说明新建已提交并提示所有者手动切换；插件不会通过删除新 Session 来补偿。

该功能仍完全位于可独立移除的 `@deepseek-ai/dsh-lark` Bundle 内。既有打字机流式输出、终态合并交付、模型和 token 信息、审批、持久队列恢复、设置停用和卸载行为保持不变。

## 验证

聚焦测试固定裸 `/` 路由、完整目录渲染、固定命令白名单、skill 准入、新建 Session 绑定、模型/推理回调重新校验、有界只读视图、诊断脱敏和旧回调拒绝。随后既有 Lark 测试套件必须保持全绿，并继续执行包类型检查、Bundle 构建、文档配对、diff 检查、tarball Profile 安装、Harness 重启状态和已安装字节校验。真实飞书所有者私聊仍是最终网络验收边界。
