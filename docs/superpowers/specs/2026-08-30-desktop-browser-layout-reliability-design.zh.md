# 桌面浏览器布局与可靠性设计

[English](2026-08-30-desktop-browser-layout-reliability-design.md) | 中文

## 目标

让 Browser Control 能在复杂页面上实际使用，同时确保普通桌面宽度下的会话、输入框、左侧导航与可见浏览器工作台都能独立使用。同一版本还必须让 Windows 安装器显示有意义的进度，并保留既有的失败关闭授权模型。

## 布局契约

壳层绝不把右侧工作台覆盖在会话之上。右侧工作台先缩小到下限，之后左侧导航只在渲染层临时让位为紧凑栏，不改写用户保存的宽度。真正的小窗口回退会聚焦显示单个表面，而不是把面板叠在一起。两个分隔条都可拖动，浏览器工作台可以扩大到视口允许的范围；除非用户明确调整，否则浏览器内容保持 100% 缩放。

会话滚动区把粘性输入框作为一个整体测量。提示轨提示与状态行必须位于这个已测量区域之上或之内，不能绘制到输入卡片上。

## 浏览器快照契约

无障碍树遍历继续保持有界，但达到原始节点、语义文本、可操作引用或 JSON 预算时，应返回有用且确定的部分快照，而不是让整个操作失败。遍历优先保留可见的可操作控件，并让线上结果继续处于既有帧上限之内；不会把无界页面内容发送给模型。冷启动渲染器具有边界并可重试；页面已完成加载时立即返回；导航等待具有有界成功回退；初始非 Web 历史项被视为没有可用历史，而不是受保护目标。由 main 持有的 CDP Overlay 标记会显示下一次点击或滚动目标，但不注入页面脚本、selector，也不把权限交给 renderer。

官方 Browser Control 失败对直接 shell 回退的禁用只覆盖当前操作窗口。官方操作成功或 Browser Stop 后会清除该守卫。

## Windows 安装器契约

NSIS 详情区域会显示提取、安装、快捷方式、注册与完成等明确且有界的阶段信息。它绝不打印用户数据、私有绝对路径、令牌或浏览器内容。

## 安全与验收

自动验收使用大型本地 B 站形态夹具，不执行公开发帖、消息或账号写入。完成条件为：复杂快照在现有线上上限内返回可操作引用；首次导航有界；wait/back/Stop 回归通过；组装后的壳层在用户反馈分辨率下不存在面板或输入框重叠；Mac 包可安装并启动；Windows 打包与安装器 smoke 在 Windows 工作流中通过。
