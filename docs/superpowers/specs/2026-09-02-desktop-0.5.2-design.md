# Desktop 0.5.2 Interface, Permission, Startup, and Footprint Design

English | [中文](2026-09-02-desktop-0.5.2-design.zh.md)

## Goal and baseline

Desktop 0.5.2 starts from the exact released `desktop-v0.5.1` commit
`b8595d75a9f94fb332689e28aef70cf5b7d72d4f` and must ship Intel macOS and
Windows x64 from one final source commit.

This release contains two independently acceptable workstreams:

1. Restore and polish the conversation navigation rail, refine the existing sidebar toward ChatGPT's visual rhythm, arrange the existing Workbench as a fixed right column, and add a safe session-scoped no-more-prompts action.
2. Measure and shorten cold startup, remove only proven-unneeded installed bytes, and fix Windows small-icon, taskbar, and tray rendering.

The Harness core remains `0.1.1-rc.2`. An upstream-core refresh is intentionally deferred to a later release so upstream migration risk is not mixed into this UI and performance release.

## Features and surfaces

### Left sidebar

- Preserve the current Workspace/Project tree, session status, rename, archive, fork, drag ordering, search, and hover information. Do not create a parallel ChatGPT data model.
- Follow ChatGPT's visual rhythm with quieter borders, consistent 32–34px rows, a restrained selected pill, and clear group spacing.
- Keep about 4px between a project row and its session list and 6–8px between project groups so adjacent items no longer appear fused.
- Keep titles single-line and ellipsized. Status and action slots must not compete with text or alter drag hit targets.
- Collapsed mode, narrow windows, long Chinese and English titles, dark mode, zoom, and keyboard focus remain supported.

### PromptRail

Desktop 0.5.2 restores the first-class `desktop-v0.4.11` navigation structure inside the current `ui-conversation` architecture:

- The rail occupies the transcript's left gutter. It is not part of the project sidebar and is not a floating preview feature.
- It sits about 16px from the conversation pane's left edge while the transcript keeps its current centered measure.
- A quiet vertical line, short marks, and an active long mark plus dot communicate position.
- Hover or keyboard focus reveals turn, time, and a one-line content preview without covering the composer.
- ArrowUp/ArrowDown/Home/End, focus recovery, the 120-item render bound, reachable endpoints, and compact narrow-pane behavior are retained.
- It only navigates existing history and adds no delete, edit, rewind, resend, or fork semantics.

### Fixed right Workbench

- Reuse the fixed, resizable `desktop-workbench` pane and layout service. It must not become a popover or a second Side Chat.
- Inside the pane, present vertical rows for Review, Terminal, Browser, and Files. Each row uses its existing icon, label, and shortcut hint, with a quiet selected state.
- The list is navigation inside the right pane; the selected existing Mode content renders in that same pane.
- Preserve the 320–720px width bounds and stored drag width. Persist the most recent Mode, but do not automatically open the pane for every new session.
- Escape, keyboard up/down plus Enter, screen-reader semantics, and reduced motion require tests.

### No more prompts for this session

The approval protocol currently has only `allowed-once`; it has no safe parameter-scoped permanent grant model. Desktop 0.5.2 therefore adds neither global “always allow” nor tool-name-only silent grants.

The approval card exposes Reject, Allow once, and Do not ask again this session. The final action:

1. displays the same Full access risk confirmation as the permission selector;
2. executes the existing `/permission danger-full-access` command in the current Session;
3. answers the pending approval as `allowed-once` only after that command succeeds;
4. avoids later approval prompts in that Session because the preset resolves to `approval: never`; and
5. remains reversible through the existing composer permission selector.

Session events remain the permission authority. Browser `localStorage` is not a permission store, `ApprovalOutcome` is unchanged, and the grant does not cross Session boundaries. OS permissions, site permissions, and future independent risk domains may still ask separately.

## Data and interfaces

- `PromptAnchor` remains the rail's sole source, using only `seq`, `turn`, `time`, `kind`, and `preview`; the rail does not fetch conversation content again.
- `WorkbenchSnapshot` continues to own `open`, `mode`, `width`, and `sessionId`; a versioned Mode preference key is added while the width key remains compatible.
- The approval takeover receives a bounded current-Session command face through `conversation.composer`. The permission selector and approval action share the same command implementation instead of duplicating Session lookup and transport.
- Startup logs contain only fixed milestone names and durations. Fixed Host phase timing may be added, but paths, URLs, Profile content, commands, credentials, and session data are forbidden.
- Package inventories contain relative paths, byte counts, categories, and SHA-256 only and never read or package the user's `DSH_HOME`.

## Startup and footprint

Current evidence places the dominant delay between `fallback-ready` and `url-reported`, inside Harness Loader activation rather than the loading page. `dsh web:` currently means required routes have mounted and must not simply be printed early.

Implementation order:

1. Record five isolated cold starts and five same-install warm starts against a temporary `DSH_HOME`, using the existing fixed milestones.
2. Add non-sensitive Host phase evidence and identify the actual slow synchronous initialization.
3. Defer only work outside first paint, core API, approval, and session restoration, or coalesce proven duplicate reads. Preserve Loader failure propagation and true readiness.
4. Re-run on the same machine, parent revision, and fixture. The target is at least a 15% cold-start median improvement with no P95, warm-start, or recovery regression. Never trade true readiness for a better number; remove ineffective changes and retain the evidence.

The reported roughly 500MB Windows size is installed footprint, not the roughly 154MB Setup download. First inventory `app.asar`, `app.asar.unpacked`, Electron runtime, locales, native prebuilds, and dependency resources. Remove only target-inaccessible binaries, debug/type/map data, non-retained locales, or resources proven unreachable from entrypoints. Physical package roots required by Profile module fallback must remain.

The target is at least a 5% installed-footprint reduction on the same Windows runner without increasing Setup size. If Electron plus real runtime dependencies establish the floor, report categorized byte evidence. Do not fake savings with first-run downloads, moving bytes into the user home, removing license material, or losing offline capability.

## Windows icon

- macOS keeps `icon.icns`. Windows uses a dedicated crop rather than directly shrinking the transparent-padded 1254px macOS-style source.
- The ICO contains reviewed 16, 20, 24, 32, 40, 48, 64, 128, and 256px layers. Small layers prioritize a legible whale silhouette and fill the canvas without touching its edges.
- BrowserWindow/taskbar uses the Windows ICO; Tray uses dedicated 16/20/24/32px PNG assets instead of the 1254px source.
- Setup, uninstaller, Start menu, desktop shortcut, taskbar, and tray require native Windows screenshot acceptance.

## Ownership

- The Mac execution task owns shared UI and permission implementation plus Intel Mac native visual and interaction acceptance.
- The Windows execution task owns shared startup and footprint implementation plus Windows icon, NSIS, Setup, and native lifecycle acceptance.
- The other platform consumes shared commits only after the commander supplies them and must not implement the same shared feature independently.
- The commander alone owns versioning, release documentation, integration, the final SHA, tag, and Release.

## Acceptance

- Sidebar hierarchy, status, menus, drag behavior, and search regressions pass; visual evidence shows group spacing and no long-text collisions.
- PromptRail works across wide/narrow panes, side-pane combinations, long histories, keyboard input, and both themes; it retains the v0.4.11 structure on current data flow.
- The right side is a fixed resizable pane with four vertical entries, no Side Chat, and no popover substitute.
- Allow once remains one-shot. Do not ask again this session resolves the current approval only after the Full access command succeeds, suppresses later prompts in the same Session, becomes prompt-capable again after switching back, and does not affect another Session.
- Startup and footprint have same-machine before/after evidence; readiness, failure page, retry, exit, and process-tree cleanup do not regress.
- Every Windows small-icon surface is legible while the Mac icon is unchanged.
- The same final SHA completes Mac DMG and Windows x64 Setup installation, startup, interaction, shutdown, replace/uninstall, and user-data preservation before `desktop-v0.5.2` may be published.
