# Desktop 0.5.3 Official Sync, Navigation, BrowserSkill, and Delivery Acceleration Design

English | [中文](2026-09-03-desktop-0.5.3-core-navigation-browser-acceleration-design.zh.md)

**Status:** User approved starting with the recommended approach on 2026-09-03

**Desktop baseline:** `7384b863e88b005b3309e49a0aebb7a2ea91d4c3` (public `desktop-v0.5.2`)

**Official target:** `dsh-v0.1.2-alpha.5` / `db6bdc3576c2d4e7c965e8e3ed0c2a731eed87f5`

**Target Desktop version:** `0.5.3`, accepted layer by layer through three internal candidates `alpha.1`, `alpha.2`, `alpha.3`

## Goals

1. Migrate the built-in Harness from `0.1.1-rc.2` to official `0.1.2-alpha.5`, preserving existing Desktop functionality and real user upgrade data.
2. Use piano-key-style complete history navigation on the left side of session body; previews must never obscure the input box.
3. Organize the existing Desktop Workbench into an extensible, on-demand-loaded fixed right sidebar, without duplicating a second terminal, file, or browser runtime.
4. Bundle the BrowserSkill Harness plugin and dual-platform CLI, but do not start by default or take over tabs; browser extensions remain explicitly installed and authorized by users.
5. Shorten development delivery wait: build once, multiple native acceptance groups reuse the artifact in parallel; intermediate candidates go through quick gates, only the final SHA undergoes complete dual-platform release acceptance.
6. Continue optimizing real startup bottlenecks without prematurely declaring readiness or skipping Loader validation.

## Non-goals

- Do not copy the entire `DSH-better-sidebar` package into Desktop, nor retain two sets of right sidebars simultaneously.
- Do not inject hidden official navigation via DOM-hashed class names; do not mount official, self-developed, and `dsh-session-nav` navigators simultaneously.
- Do not auto-install Chrome/Edge extensions, do not read or reuse user's ordinary windows, do not borrow tabs without confirmation.
- Do not treat first-start online downloads, license removal, or moving runtimes to `DSH_HOME` as package-size optimization.
- Do not print `dsh web:` early to chase numbers or treat the loading page as real Desktop ready.

## Verified facts and design decisions

### Official sync must come first

Moving from `0.1.1-rc.2` to `0.1.2-alpha.5` is large-scale upstream evolution, not a single-point fix. The target version adds complete session Turn outline, pagination jumps, and TurnNavigator, and alpha.5 fixes potential startup failures or session title loss when upgrading from older versions.

Therefore the sync order is fixed: legacy data migration RED → official code sync → Desktop extension porting → legacy data GREEN → dual-platform temporary Home and real upgrade copy smoke. UI and BrowserSkill can be implemented only based on post-sync interfaces.

The existing `codex/desktop-049-official-core-sync` branch contains alpha.2 sync experience and may serve only as conflict/compatibility reference; new candidates must be established from the released 0.5.2 baseline and ultimately include the exact upstream ancestry of alpha.5 or an auditable equivalent import.

### Left-side complete session navigation

Data authority uses official `turnOutline` and `TurnNavigator`: one item corresponds to one Turn, containing `turn`, `seq`, bounded `prompt`, bounded `response`, loading old history through official `loadThrough`/pagination channels when needed.

Visual reference is `kiligzzz/dsh-session-nav`, but implementation stays in first-party components:

- Navigation cluster sits in the session body's left gutter, maintaining 10px regular spacing, 2px visual keys, 6px static length.
- Hover keys are 26px, adjacent three levels依次 20/14/10px; current key changes only color, does not push body text rightward.
- Preview shows one line of user content and at most three lines of reply, maximum width 300px.
- Navigation visible height must use `conversation viewport - composer height`, preview `top` clamped within that height; when near the bottom, collapse upward, must not enter composer, QueueDock, or stats row.
- Keyboard, reduced motion, light/dark themes, long-session internal scrolling, and narrow-window hide/compact mode continue using official semantics.
- After sync, delete or deactivate rc.2 branch's `PromptAnchor`/`PromptRail` duplicate implementations, keeping only one navigation truth.

### Fixed right-side Workbench

Continue using existing `layout.utility`, Electron `WebContentsView` browser, terminal, review, and file panels. Reference `DSH-better-sidebar`'s service-oriented tabs, fixed sidebar, and on-demand loading, but do not introduce its full dependency tree.

Add internal registry contract:

```ts ignore-check
export interface DesktopWorkbenchTabDefinition {
  readonly id: 'review' | 'terminal' | 'browser' | 'files' | 'agent-browser'
  readonly titleKey: string
  readonly icon: WorkbenchIcon
  readonly order: number
  readonly load: () => Promise<{ default: ComponentType<WorkbenchModeProps> }>
}
```

- Built-in four pages generate vertical entries through the same registry, heavy modules load only on first selection.
- When BrowserSkill is enabled, add `agent-browser` status page; it displays connection, extension install, Agent Window, and borrow status, not duplicating ordinary web browsers.
- Right sidebar remains a fixed, resizable single surface; no floating previews, Side Chat, or second Terminal.
- Entries and text have independent layout slots, long Chinese/English truncate to single line, 100%, 150%, 200% zoom must not squeeze each other.

### BrowserSkill bundling boundaries

BrowserSkill has three layers: Harness plugin, platform `bsk` CLI, Chrome/Edge extension. Desktop bundles only the first two layers; the third layer must be explicitly installed by users in browser stores.

```ts
export interface DesktopBrowserSkillState {
  readonly enabled: boolean
  readonly cli: 'bundled-ready' | 'missing' | 'incompatible' | 'unhealthy'
  readonly extension: 'connected' | 'disconnected' | 'unknown'
  readonly ownedSessions: number
  readonly borrowedTabs: number
  readonly lastErrorCode?: string
}
```

- Adopt only publicly released versions with fixed SHA-256/integrity; do not directly package unreleased content from `main`.
- `bsk` starts only when user enables or model actually invokes BrowserSkill; Desktop cold start does not probe browsers or start daemons.
- DSH plugin exposes only structured `browser_*` capabilities; does not open arbitrary JS/CDP/evaluate.
- Default operation targets the plugin-created Agent Window. Borrowing ordinary tabs requires BrowserSkill native confirmation, returning after completion; exiting Desktop cleans up only sessions owned by this instance.
- When Extension is disconnected, return actionable install/connection guidance without infinite retries.
- Mac ships only x86_64 CLI; Windows ships only x86_64 CLI, prohibiting the other platform's binary in the final artifact.

### Startup and delivery acceleration

Existing Windows 0.5.2 same-machine evidence shows typical cold start 4257ms, hot start 3271ms; main controllable phases are `profile-compose → loader-mount` about 1.2s, and first Desktop surface after Harness ready about 0.9–1.2s. Module fallback repeated governance is only about 64–66ms, not worth bypassing security validation.

Runtime strategy:

- Resample the Loader after sync, do not infer optimizations from old version numbers.
- Cache only rebuildable graphs keyed by profile, bundle, patch, package lock, and version-precise digests; still validate digest, physical package root, and failure propagation each time.
- On-demand load non-first-screen extensions like Workbench, BrowserSkill, Markdown re-preview; session restore, authorization, routing, Client manifest cannot be delayed.
- Target: same-machine 10 cold/10 hot comparison, at least one of cold/hot median improves by 15%, the other degrades no more than 5%, P95 degrades no more than 10%; otherwise revert product optimizations but retain measurement tools.

Delivery pipeline:

```ts
export interface DesktopCandidateDescriptor {
  readonly sourceSha: string
  readonly platform: 'mac-x64' | 'win-x64'
  readonly productInputSha256: string
  readonly artifactSha256: string
  readonly mode: 'quick' | 'full'
}
```

- Build job assembles once and uploads immutable staged/DMG/Setup candidate.
- Lifecycle, visual, performance download the same candidate in parallel on independent runners; each job first verifies descriptor, filename, bytes, and SHA.
- `quick` runs only compilation, critical contracts, one install-launch-close; `full` runs baseline performance, dual zoom, complete uninstall, and public release gates.
- Test script fixes allow re-verifying locked product artifacts, but final tag/Release must still rebuild once from the final source SHA and redo dual-platform full.
- Mac and Windows workflows dispatch simultaneously; expected Windows full wall-clock target 10–13 minutes, an engineering goal not a release promise.

## Phases and ownership

### `0.5.3-alpha.1`: Official sync and pipeline foundation

- Mac execution task: sole shared official core sync owner; migrate Desktop extensions and provide Mac Intel quick smoke.
- Windows execution task: Windows pipeline acceleration owner; first deliver reusable build/quick/full contracts on 0.5.2 baseline, consuming after shared core commit arrives.
- Commander: specification, integration, conflict ownership, candidate SHAs, and phase conclusions.

### `0.5.3-alpha.2`: Left/right navigation and Workbench

- Mac execution task: sole shared UI implementation owner; implement TurnNavigator left-side styling, composer clamp, Workbench registry and lazy loading.
- Windows execution task: consume shared UI only, complete 100%/150%/200% DPI, taskbar and input box non-overlap acceptance.

### `0.5.3-alpha.3`: BrowserSkill

- Windows execution task: sole shared BrowserSkill Desktop adaptation owner; implement version locking, plugin mounting, CLI location, state, and Windows x64 acceptance.
- Mac execution task: consume shared commit only, integrate Intel CLI and complete Mac native guidance/connection/cleanup acceptance.

### `0.5.3`: Final release

- Commander exclusively owns version, README/PROJECT_CONTEXT, integration, tag, and Release.
- Mac DMG and Windows Setup from the same final SHA must both be full GREEN; any source change invalidates old artifacts.

## Acceptance criteria

1. Both rc.2 and alpha.3 real-format upgrade fixtures launch, Session titles, events, Workspace, Memory/Evolution data remain byte-for-byte intact; damaged caches are only backed up and rebuilt, never deleting original records.
2. Left-side navigation covers complete Turn history, accurately jumping after loading old pages; previews do not overlap input area under various composer heights and zooms.
3. Right sidebar is fixed, resizable, on-demand loaded; four original functions have no regression, BrowserSkill page appears only when enabled.
4. BrowserSkill provides guidance without extension; isolated tests with extension control only Agent Window; borrow/return, cancellation, exit cleanup, and cross-instance ownership all fail closed.
5. Plugin and binaries have fixed sources, licenses, versions, and SHAs; final artifact does not contain the other platform's binary.
6. Artifact binding, failure propagation, and final SHA rebuild contracts for quick/full pipeline have automated tests; Mac/Windows run in parallel without sharing writable user Home.
7. Readiness, failure page, retry, exit process tree, uninstall, and user data retention do not regress.
8. Release report distinguishes typical startup, P95, Setup/DMG download size, and post-install footprint; do not write "all faster" based on improvement in just one metric.

## Rollback

- Core sync completes on an independent branch; do not enter UI branch without passing upgrade-state smoke.
- UI can revert to official TurnNavigator default position and original Workbench static entries, without rolling back core data migration.
- BrowserSkill disabled by profile switch; disabling does not delete extensions, user browser profiles, or BrowserSkill's own state.
- New pipeline retains old full workflow until first same-SHA dual-platform GREEN, then removes old entrypoints.
