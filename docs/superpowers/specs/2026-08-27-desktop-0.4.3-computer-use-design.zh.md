# Desktop 0.4.3 浏览器控制、Computer Use 与发言刻度设计

[English](2026-08-27-desktop-0.4.3-computer-use-design.md) | 中文

## 目标

以修正版 Desktop 0.4.2 提交 `5998cfbe523f98809c6170a5d67bce499e684728` 为基线，交付同一源码的 Mac Intel 与 Windows x64 Desktop 0.4.3。0.4.3 增加两类可观察、可撤销的 Agent 能力：对内置浏览器进行结构化控制，以及在用户授权后控制多个本机软件；同时把发言导航刻度调整为用户确认的 Codex 风格高可见版本。

功能不能把 Electron 渲染进程、任意 JavaScript、远程调试端口、AppleScript、PowerShell 或无约束的鼠标键盘接口直接暴露给模型。现有 Harness 审批、会话所有权、工具生命周期和应用退出清理仍是权威边界。

## 范围

- Browser Control：导航、页面语义快照、可选截图、点击元素引用、输入、按键、选择、滚动、等待以及前进、后退、刷新和停止。
- Computer Use：列出可授权应用与窗口、激活应用、无障碍语义快照、可选窗口截图、点击、双击、拖动、输入、按键、组合键、滚动和等待。
- 多软件控制：用户可维护应用白名单；一个任务可在多项已授权软件之间切换。
- 一次任务授权：普通动作在短时 `ControlLease` 内连续执行；敏感动作仍逐次确认或直接拒绝。
- 可见接管：控制期间显示应用、窗口、会话、状态与“停止控制”，并提供全局紧急停止快捷键。
- 发言刻度：只负责浏览历史，不增加编辑、回退、删除、分支、草稿恢复或自动发送语义。
- 0.4.3 同一源码支持 macOS 与 Windows；平台原生适配器分别实现，不能用 shell 脚本冒充跨平台支持。

## 非目标

- 不重写 Harness、Electron 主程序或现有工具系统。
- 不复制现有 Bash、PowerShell、Terminal、Jobs、Workflow、文件工具或 sandbox。
- 不允许读取密码、验证码、支付卡信息、密钥链内容或操作系统安全凭据。
- 不自动批准付款、发布、发送、安装、卸载、删除、清空回收站或系统权限变更。
- 不在后台静默控制，也不允许插件绕过状态指示器与停止机制。
- 首版不提供任意脚本注入、任意 CSS/XPath selector、任意 IPC、任意进程注入或任意原始操作系统 API。

## 方案选择

### 采用：双能力 Seam + 平台原生适配器

新增独立 `browserControl` 与 `computerControl` Service Definition、Host Adapter 和模型工具 Consumer。`desktop-control-protocol` 是所有跨 Harness/Electron 或 Electron/helper 进程边界的操作、结果和品牌化 ID DTO 的唯一真源；服务包复用或重新导出这些类型，不得复制。Harness 子进程与 Electron 主进程通过专用、强类型、封闭词汇的 IPC 通信。浏览器适配器复用内置 `WebContentsView`；桌面适配器仅把受限动作转发给按需启动的原生 helper。

macOS helper 使用 AXUIElement 获取应用、窗口和控件语义，使用 ScreenCaptureKit 或 CoreGraphics 捕获获准窗口，使用 CGEvent 执行封闭动作。Windows helper 使用 UI Automation 获取语义树，使用 Windows Graphics Capture 捕获获准窗口，使用 SendInput 执行封闭动作。helper 适合用 Rust 实现，以获得稳定的原生类型、进程隔离和跨平台协议；这不是用 Rust 重写整个 Harness。

### 不采用：独立 Playwright 浏览器

独立 Playwright Bundle 易于隔离，但会重复交付 Chromium、增加安装包与内存，并且不能自然控制用户正在查看或已经登录的内置浏览器页面。它可以作为测试依赖，不作为产品主路径。

### 不采用：shell、AppleScript 或 PowerShell 拼接控制

脚本方案实现快，但元素定位、窗口身份、缩放、取消、审计和多平台一致性都不可靠，也容易绕过 Harness 审批。脚本只保留为用户显式运行的普通命令，不作为 Computer Use 后端。

## 封闭协议与 framing

协议 v1 定义品牌化的 `RequestId`、`ControlLeaseId`、`BrowserRef`、`ComputerRef` 和 `PngTransferId` 值，复用 Harness 官方 `SessionId`，并在所有活跃 lease 作用域中携带 `leaseRevision`。不同品牌不能互换。严格 decoder 拒绝重复 JSON key、未知字段、未知判别值、错误版本和被禁止的通用字段。任何请求或结果都不接受通用 `command`、`script`、`selector`、`javascript`、`method`、`args`、`env`、`cwd`、`path`、`channel`、`ipc`、`payload: unknown`、`data: unknown`、`Record` 或索引签名。

每个跨进程值都使用一种统一外层二进制 frame。Tag `0x01` 后跟不超过 65,536 字节的 UTF-8 JSON payload。Tag `0x02` 后跟 16 字节 transfer UUID 和不超过 4,194,304 字节的原始 PNG。JSON 截图元数据声明 `transferId`、`byteLength`、`sha256`、`width` 和 `height`；紧接着的下一帧必须是匹配的 PNG，遗留、迟到、不匹配、哈希错误或尺寸无效的 PNG frame 均 fail closed。禁止 base64。Node IPC 使用 `serialization: 'advanced'`，每条 IPC 消息恰好发送一个 `Uint8Array` frame。Rust stdin/stdout 在相同 frame 前加四字节大端 frame 长度，并支持拆分的 header/body 读取与连续多帧。

顶层 `messageKind` 联合类型只能是 `request`、`response` 或 `control`。请求清单准确限定为 `desktop.status`；`browser.snapshot`、`browser.navigate`、`browser.click`、`browser.type`、`browser.key`、`browser.select`、`browser.scroll`、`browser.wait`、`browser.back`、`browser.forward`、`browser.reload` 和 `browser.stop`；以及 `computer.status`、`computer.list`、`computer.snapshot`、`computer.focus`、`computer.click`、`computer.double-click`、`computer.drag`、`computer.type`、`computer.key`、`computer.scroll`、`computer.wait` 和 `computer.stop`。控制消息准确限定为 `request.cancel`、`session.revoke`、`lease.revoke` 和 `parent.shutdown`。响应只能是 `ok` 或 `error`，并回显 `requestKind`。错误码只允许 `NOT_SUPPORTED`、`UNAUTHORIZED`、`LEASE_EXPIRED`、`LEASE_REVOKED`、`STALE_REF`、`TARGET_CLOSED`、`PERMISSION_DENIED`、`POLICY_DENIED`、`DUPLICATE_REQUEST`、`TOO_MANY_PENDING`、`QUOTA_EXCEEDED`、`BINARY_MISMATCH`、`BUSY`、`TIMEOUT`、`CANCELLED`、`DISCONNECTED` 和 `INTERNAL`；其 UTF-8 `message` 不超过 512 字节，`retryable` 为布尔值。

helper 请求清单准确限定为 `status`、`list`、`snapshot`、`focus`、`click`、`double-click`、`drag`、`type`、`key`、`scroll`、`wait`、`stop` 和 `lease.install`；`lease.revoke` 是幂等的高优先级控制。每个 helper 请求都包含 `requestId`、`sessionId` 和 `deadlineMs`。作用于已安装 lease 的请求还包含 `leaseId` 和 `leaseRevision`；只有作用于目标的请求才包含 `appId`、`windowId` 和 `snapshotRevision`。配额只出现在 `lease.install` 携带、由 Electron 编写的 lease 快照中；子进程和模型不能提议配额。聚合语义文本上限为 49,152 个 UTF-8 字节，包括所有结构字段在内的完整编码 JSON payload 仍必须不超过 65,536 字节。

畸形 JSON、重复 key、未知字段或判别值、错误版本、超限 JSON 或 PNG 数据以及无效 frame 顺序都会关闭专用控制通道。通道关闭会拒绝其中的控制工作，但不会终止 Harness 或影响普通聊天。

Host bridge 而非 codec 拥有有状态请求 ledger。它最多允许 32 个 pending 请求，拒绝重复 ID、传播取消，并保留有界终态 tombstone，使迟到响应不能结算新工作。每个子进程都有 generation；listener 闭包捕获准确的子进程和 generation，除非二者仍与当前 owner 相同，否则拒绝消息，因此旧子进程不能替代新子进程响应。

## Browser Control 架构

Agent 默认获得会话级临时浏览器分区，不继承用户登录 Cookie。用户在内置浏览器点击“交给 Agent”后，可以把当前可见页面签发给本次会话；授权只包含当前 BrowserView 控制权，不导出 Cookie、localStorage 或凭据。

每次 `browser_snapshot` 返回：页面 URL、标题、导航修订号、可交互元素的有界语义树，以及视觉模型显式请求时的截图附件。元素引用是绑定导航修订号的短期 opaque ref；导航、DOM 大改或页面关闭后立即失效。点击和输入只接受当前快照中的 ref，不接受模型提供的 JavaScript、selector 或坐标字符串。坐标点击仅作为视觉兜底，并绑定截图修订号与可见 BrowserView 边界。

页面内容始终标记为不可信。网页文字不能签发授权、扩大白名单、确认敏感动作或要求 Harness 绕过策略。弹窗、下载、摄像头、麦克风、定位、剪贴板读取和新窗口默认拒绝；文件上传只接受用户通过原生选择器明确选出的短期文件句柄。

## Computer Use 架构

`computer_snapshot` 必须绑定一个已授权应用与窗口，返回无障碍树和可选截图。语义节点引用绑定进程身份、窗口身份、快照修订号和显示缩放；窗口改变后，旧引用 fail closed。Agent 优先使用语义引用，只有没有可用无障碍节点且模型支持图片输入时才允许使用坐标操作。

原生 helper 只实现上文定义的封闭 helper 清单和字段矩阵。`status` 不虚构目标字段，`list` 不虚构窗口或快照字段，目标作用域操作只携带其所需的目标字段；父进程断开、应用退出、会话结束或 lease 撤销时立即释放输入能力并退出。

不支持图片输入的模型只能使用 DOM 或无障碍语义模式，不能猜测屏幕坐标。截图通过 Harness 附件服务保存并作为 ImageBlock 传递，不能把无限 base64 放进 IPC 或日志。

## 授权与安全

首次使用在设置中显示两项独立权限：屏幕查看与辅助控制。未授权时工具返回明确的本地状态和打开系统设置的人工入口，不循环弹窗、不自动修改系统设置。

Electron 主进程只有在完成其自行拥有、用户可见的原生审批 challenge 后，才签发短时 `ControlLease`。lease 绑定 Harness 官方会话、允许的应用、窗口集合、能力集合、配额、`leaseRevision` 和最大时长。默认在任务结束、会话切换、应用重启、用户接管、五分钟无动作或二十分钟硬上限时撤销。设置页可以撤销单个应用或全部授权。子进程和模型不能提交 `approved`、签发 lease、选择配额或推进 `leaseRevision`。

Harness `ctx.approval` 可以请求交互并提供审批 UX，但仅凭其结果不能授权安装 lease，也不能授权执行敏感最终动作；两类操作都必须由 Electron 完成并验证自己的原生可见 challenge。同一个 Harness Node 进程内已安装的 Host 插件属于受信执行代码。0.4.3 不声称隔离恶意进程内插件，但页面文本、模型输出和 renderer 消息仍不能伪造 Electron 的用户确认。

以下操作不能由普通 lease 自动批准：密码与 secure text 字段、一次性验证码、生物认证、密钥链与密码管理器、系统隐私/安全设置、付款与下单、对外发送或发布、安装/卸载、删除与覆盖数据、下载并执行文件。能够可靠识别的凭据输入直接拒绝；其余高影响动作在最终提交前显示动作、目标应用、控件名称和影响，并逐次询问。

控制期间始终显示顶部状态胶囊，至少包含 Agent 名称、当前应用、动作状态、暂停与停止。菜单栏/托盘同步提供停止入口；默认全局紧急停止快捷键为 `CommandOrControl+Shift+F12`，可由用户修改。任何停止都会撤销 lease、清空排队动作、释放按键和鼠标状态，并记录不含屏幕正文的本地审计事件。

## 发言刻度

采用用户确认的第一版视觉：聊天正文左侧保留约 28–32px 的独立窄 gutter，无底板、无卡片式时间线。普通发言使用可见但克制的中性灰短刻度，当前项使用 DeepSeek 蓝长刻度与空心圆点；hover 或键盘聚焦时显示“第 N 条发言 · 时间”和最多两行预览，底部显示当前位置计数。

现有普通刻度引用了不存在的 `--dsw-alias-label-quaternary`，必须改为已定义的主题 token 并提供 fallback。轨道和普通刻度在浅色、暗色、非 Retina 与高对比度模式下都必须可辨认。超长会话不让 120 个重叠按钮争抢点击：轨道根据指针 Y 选择最近锚点，键盘采用 roving tabindex、方向键、Home 与 End。窄窗口不再静默删除能力，而是收起为小型“发言导航”按钮。

点击刻度只读取必要历史并滚动到准确用户发言，目标消息短暂显示主题色定位提示。它不会修改历史、创建会话、恢复草稿、回退、删除或发送消息。

## 性能与隐私

- helper 按需启动，闲置时退出；没有控制任务时不截图、不轮询无障碍树、不保持高频计时器。
- 浏览器优先返回语义差异；桌面截图按窗口裁剪并按模型需求降采样。连续动作默认最高 2 FPS，静止时为 0 FPS。
- 截图与语义快照只进入当前会话的有界附件/工具结果；不得写入 telemetry、普通日志、记忆插件或 MSE 候选。
- 密码字段值、Cookie、localStorage、授权 token 和隐藏窗口内容永不返回模型。
- 页面或应用发生变化时返回 `STALE_REF`，Agent 重新获取快照，不能盲重试旧坐标。
- 单轮动作数、快照字节、语义节点数、文本长度和总控制时长均有硬上限。

## UI 与错误处理

设置页增加与现有设置卡片一致的“浏览器与电脑控制”区，显示平台支持、系统权限、已授权应用、默认共享方式、紧急停止快捷键和最近一次本地控制状态。插件市场只显示它由 Desktop 内置且已加载，不显示永久的“重启后加载”假状态。

内置浏览器增加“交给 Agent/停止接管”按钮。Agent 使用临时浏览器时自动打开可见工作台；共享当前页面前展示登录态提示。Computer Use 启动时不抢焦点，第一项需要交互的动作才激活目标应用。

权限缺失、窗口关闭、应用退出、目标被遮挡、截图失败、无障碍树不可用、stale ref、模型无视觉能力或用户停止，都返回结构化错误。错误不能导致 Harness 启动失败，不能阻塞普通聊天，也不能遗留 helper、按键状态、鼠标拖动或 BrowserView。

## 测试与验收

- 协议测试使用 Rust/TypeScript 共享 fixture，并覆盖重复 JSON key；49,152 和 65,536 字节的精确 UTF-8 边界；拆分的长度 header 与 body；连续多帧；PNG 关联、哈希、尺寸、遗留与迟到；不同品牌不可互换；冻结的嵌套输出；不可变 PNG 副本；以及被禁止的通用字段词汇。schema、stale ref、外来会话、过期 lease、非法动作与未知字段全部 fail closed。
- Browser 测试：隔离分区、显式共享、DOM/无障碍快照、点击/输入/滚动/等待、导航失效、弹窗/下载/权限拒绝、文件句柄上传、恶意网页提示无法授权。
- Computer 测试：应用/窗口身份、显示缩放、语义引用、坐标兜底、输入释放、用户停止、helper 崩溃与父进程断开。
- 敏感测试：secure text、验证码、付款、发送、安装、删除和系统设置不能被普通 lease 静默执行。
- 模型测试：视觉模型收到有界图片；文本模型只收到 DOM/AX 文本，不能调用坐标动作。
- 刻度测试：主题 token 存在、浅/暗/高对比快照、高密度最近锚点命中、键盘导航、窄屏入口、精确历史定位和无副作用。
- 性能测试：闲置 0 FPS、按需 helper、快照限流、长任务内存上限以及退出后零残留进程。
- 产品测试：普通聊天、插件、记忆、MSE、系统更新、侧边工作台、现有 shell/terminal/jobs 和 `~/.dsh` 数据全部保持。
- 原生验收：同一源码提交分别在 Intel Mac 与 Windows x64 完成安装、权限引导、浏览器受控任务、多软件受控任务、敏感拒绝、紧急停止、应用退出、进程清理、卸载和数据保留。

## 发布门禁

0.4.3 不以“能打开软件”冒充 Computer Use 完成。发布必须提供真实可见任务证据：浏览器至少完成一次多步骤页面操作；每个平台至少控制两个无害测试软件完成观察、点击、输入和停止；拒绝分支不得产生副作用。

macOS 当前未签名/未公证构建无法保证 TCC 权限跨覆盖安装稳定保留。没有 Developer ID 时可以发布明确标注的测试版，但不能宣称权限永久稳定；正式 Computer Use Release 推荐在签名、公证、权限说明与升级身份稳定后发布。Windows 同样需要明确 SmartScreen/代码签名边界。

所有构建必须来自最终共同提交和全新 `desktop-v0.4.3` tag。公开资产要验证上传状态、大小、SHA-256、校验文件以及一次匿名重下载；不得包含密钥、Cookie、截图、用户文件、`~/.dsh` 数据或本机权限数据库。
