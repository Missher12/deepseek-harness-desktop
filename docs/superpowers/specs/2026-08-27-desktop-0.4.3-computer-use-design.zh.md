# Desktop 0.4.3 浏览器控制、Computer Use 与发言刻度设计

[English](2026-08-27-desktop-0.4.3-computer-use-design.md) | 中文

## 目标

以修正版 Desktop 0.4.2 提交 `5998cfbe523f98809c6170a5d67bce499e684728` 为基线，交付同一源码的 Mac Intel 与 Windows x64 Desktop 0.4.3。0.4.3 增加两类可观察、可撤销的 Agent 能力：对内置浏览器进行结构化控制，以及在用户授权后控制多个本机软件；同时把发言导航刻度调整为用户确认的 Codex 风格高可见版本。

功能不能把 Electron 渲染进程、任意 JavaScript、远程调试端口、AppleScript、PowerShell 或无约束的鼠标键盘接口直接暴露给模型。现有 Harness 审批、会话所有权、工具生命周期和应用退出清理仍是权威边界。

## 范围

- Browser Control：导航、页面语义快照、可选截图、点击元素引用、输入、按键、选择、滚动、等待以及前进、后退、刷新和停止。
- Computer Use：列出可授权应用与窗口、激活应用、无障碍语义快照、可选窗口截图、点击、双击、拖动、输入、按键、组合键、滚动和等待。
- 多软件控制：用户可维护应用白名单；一个任务可在多项已授权软件之间切换。
- 临时任务一次授权：普通动作在短时 `ControlLease` 内连续执行；已知敏感目标直接拒绝，持久化人工浏览器 surface 上的变更操作必须经过 Electron 拥有的一次性动作 challenge。
- 可见接管：控制期间显示应用、窗口、会话、状态与“停止控制”，并提供全局紧急停止快捷键。
- 发言刻度：只负责浏览历史，不增加编辑、回退、删除、分支、草稿恢复或自动发送语义。
- 0.4.3 同一源码支持 macOS 与 Windows；平台原生适配器分别实现，不能用 shell 脚本冒充跨平台支持。

## 非目标

- 不重写 Harness、Electron 主程序或现有工具系统。
- 不复制现有 Bash、PowerShell、Terminal、Jobs、Workflow、文件工具或 sandbox。
- 不允许读取密码、验证码、支付卡信息、密钥链内容或操作系统安全凭据。
- 不自动批准付款、发布、发送、安装、卸载、删除、清空回收站或系统权限变更。
- 不在后台静默控制，也不允许插件绕过状态指示器与停止机制。
- 首版不提供任意脚本注入、任意 CSS/XPath selector、任意 IPC、任意进程注入或任意原始操作系统 API。

## 方案选择

### 采用：双能力 Seam + 平台原生适配器

新增独立 `browserControl` 与 `computerControl` Service Definition、Host Adapter 和模型工具 Consumer。`desktop-control-protocol` 是所有跨 Harness/Electron 或 Electron/helper 进程边界的操作、结果和品牌化 ID DTO 的唯一真源；服务包复用或重新导出这些类型，不得复制。Harness 子进程与 Electron 主进程通过专用、强类型、封闭词汇的 IPC 通信。浏览器适配器复用内置 `WebContentsView`；桌面适配器仅把受限动作转发给按需启动的原生 helper。

macOS 14+ helper 使用 AXUIElement 获取应用、窗口和控件语义，只通过使用 `SCContentFilter` 与 `SCStreamConfiguration` 的 `SCScreenshotManager` 捕获画面，并使用 CGEvent 执行封闭动作。CoreGraphics 只用于窗口身份、坐标和 CGEvent 支持，绝不作为截图 fallback。Windows helper 使用 UI Automation 获取语义树，使用 Windows Graphics Capture 捕获获准窗口，使用 SendInput 执行封闭动作。helper 适合用 Rust 实现，以获得稳定的原生类型、进程隔离和跨平台协议；这不是用 Rust 重写整个 Harness。

### 不采用：独立 Playwright 浏览器

独立 Playwright Bundle 易于隔离，但会重复交付 Chromium、增加安装包与内存，并且不能自然控制用户正在查看或已经登录的内置浏览器页面。它可以作为测试依赖，不作为产品主路径。

### 不采用：shell、AppleScript 或 PowerShell 拼接控制

脚本方案实现快，但元素定位、窗口身份、缩放、取消、审计和多平台一致性都不可靠，也容易绕过 Harness 审批。脚本只保留为用户显式运行的普通命令，不作为 Computer Use 后端。

## 封闭协议与 framing

协议 v1 定义品牌化的 `RequestId`、`ControlLeaseId`、`BrowserRef`、`ComputerRef` 和 `PngTransferId` 值，复用 Harness 官方 `SessionId`，并在所有活跃 lease 作用域中携带 `leaseRevision`。不同品牌不能互换。提交到仓库的机器可读 v1 manifest 是封闭清单、字段矩阵与上限的真源，TypeScript 和 Rust 均由它生成或验证定义；manifest 不能包含通用 schema escape。严格 decoder 拒绝重复 JSON key、未知字段、未知判别值、错误版本和被禁止的通用字段。任何请求或结果都不接受通用 `command`、`script`、`selector`、`javascript`、`method`、`args`、`env`、`cwd`、`path`、`channel`、`ipc`、`payload: unknown`、`data: unknown`、`Record` 或索引签名。

每个跨进程值都使用一种统一外层二进制 frame。Tag `0x01` 后跟不超过 65,536 字节的 UTF-8 JSON payload，因此完整 JSON frame 不超过 65,537 字节。Tag `0x02` 后跟 16 字节 transfer UUID 和不超过 4,194,304 字节的原始 PNG，因此完整 PNG frame 不超过 4,194,321 字节。JSON 截图元数据声明 `transferId`、`byteLength`、`sha256`、`width` 和 `height`；紧接着的下一帧必须是匹配的 PNG，遗留、迟到、不匹配、哈希错误或尺寸无效的 PNG frame 均 fail closed。禁止 base64。Node IPC 使用 `serialization: 'advanced'`，每条 IPC 消息恰好发送一个 `Uint8Array` frame。Rust stdin/stdout 在相同 frame 前加四字节大端长度，其值包括 tag 与 body；读取方在分配前拒绝零值和超过 4,194,321 的值，随后支持拆分的 header/body 读取与连续多帧。

顶层 `messageKind` 联合类型只能是 `request`、`response` 或 `control`。27 项 bridge 请求清单准确限定为仅供内部使用的 `control.lease.acquire` 与 `control.lease.release`；`desktop.status`；`browser.snapshot`、`browser.navigate`、`browser.click`、`browser.type`、`browser.key`、`browser.select`、`browser.scroll`、`browser.wait`、`browser.back`、`browser.forward`、`browser.reload` 和 `browser.stop`；以及 `computer.status`、`computer.list`、`computer.snapshot`、`computer.focus`、`computer.click`、`computer.double-click`、`computer.drag`、`computer.type`、`computer.key`、`computer.scroll`、`computer.wait` 和 `computer.stop`。两个 `control.lease.*` 值是只供 `desktop-control-host` 及其 Service consumer 使用的普通请求判别值，不是带外控制消息，也不是模型工具。控制消息准确限定为 `request.cancel`、`session.revoke`、`lease.revoke` 和 `parent.shutdown`。响应只能是 `ok` 或 `error`，并回显 `requestKind`。错误码只允许 `NOT_SUPPORTED`、`UNAUTHORIZED`、`LEASE_EXPIRED`、`LEASE_REVOKED`、`STALE_REF`、`TARGET_CLOSED`、`PERMISSION_DENIED`、`POLICY_DENIED`、`DUPLICATE_REQUEST`、`TOO_MANY_PENDING`、`QUOTA_EXCEEDED`、`BINARY_MISMATCH`、`BUSY`、`TIMEOUT`、`CANCELLED`、`DISCONNECTED` 和 `INTERNAL`；其 UTF-8 `message` 不超过 512 字节，`retryable` 为布尔值。

每个 bridge 请求都包含官方 `sessionId`、请求 ID、请求类型、协议版本、消息类型和 deadline 基础字段。`control.lease.acquire` 另外包含：只能取 `browser-ephemeral`、`browser-human-persistent` 或 `native-application` 的 `surfaceKind`；只能由 `observe`、`pointer` 和 `keyboard` 组成且不得重复的 `capabilities` 数组；以及保持应用/窗口对应关系的封闭 `{ appId, windowIds[] }` `targets` 数组。浏览器 surface 的 targets 必须为空。原生目标请求至少包含一个应用且每个应用至少包含一个当前枚举到的窗口，同时满足 manifest 中应用数、窗口数、列表、标识符和 JSON 字节上限。Electron 在显示原生 challenge 前，会把这一期望子集与当前枚举结果、普通 allowlist 和固定策略取交集。

acquire 响应是不可变 descriptor，只包含 `leaseId`、`leaseRevision`、`surfaceKind`、生效后的 targets 与 capabilities、`idleExpiresAfterMs` 和 `hardExpiresAfterMs`。它既不接受也不返回配额、绝对或单调时钟值、`approved` 或动作 digest。只有原生 challenge 成功，并且在原生控制场景中 helper 已确认 `lease.install` 后，Electron 才响应；安装失败时不得返回 lease。`control.lease.release` 只在公共基础字段之外增加 `leaseId` 和 `leaseRevision`，并且只有等待撤销、清空队列、浏览器/helper 清理与已知输入释放确认全部完成后，才返回 `{ released: true }`。模型工具 schema 永远不暴露这两个内部请求，也不暴露 transport、session、lease、revision、审批、配额、时钟或 digest 字段；受信 provider 在内部取得官方 session 并填入这些字段。

helper 请求清单准确限定为 `status`、`list`、`snapshot`、`focus`、`click`、`double-click`、`drag`、`type`、`key`、`scroll`、`wait`、`stop`、`lease.install` 和 `input.release`；`lease.revoke` 是幂等的高优先级控制。bridge 请求携带 `deadlineUnixMs`；Electron 只接受严格区间 `nowUnixMs < deadlineUnixMs <= nowUnixMs + 30,000`，并为该次判定只读取一次 `nowUnixMs`，之后只能缩短合法 deadline。存在活跃 lease 时，有效 helper timeout 取合法 bridge 剩余时间、30 秒和 lease 硬到期剩余时间三者的最小值。helper 以正数 `timeoutMs` 接收该时长，并立即转换为本地单调 `Instant`。每个 helper 请求都包含 `requestId`、`sessionId` 和 `timeoutMs`。作用于已安装 lease 的请求还包含 `leaseId` 和 `leaseRevision`；只有作用于目标的请求才包含 `appId`、`windowId` 和 `snapshotRevision`。`input.release` 是 Electron 专用、无需批准且没有 lease 字段的恢复请求；子进程和模型不能发起。

`lease.install` 携带由 Electron 编写的快照，其中 targets 保持为 `{ appId, windowIds[] }` 配对，而不是互相独立的应用集合与窗口集合，避免把一个授权中的应用与另一个授权中的窗口交叉组合。快照包含总量 `operations` 配额，以及既有的 `snapshots`、`pointerActions`、`keyActions` 和 `textBytes` 分类。每个 lease 作用域请求在 dispatch 前先扣减一个 `operations` 单位，并在各次原生调用前额外扣减对应分类。子进程和模型不能提议配额。`agentId` 只用于显示，绝不作为权威或身份。聚合语义文本上限为 49,152 个 UTF-8 字节，包括所有结构字段在内的完整编码 JSON payload 仍必须不超过 65,536 字节。

Electron 在整个进程中只允许一个活跃 lease。Electron 与 helper 只用各自的单调时钟度量 lease 空闲和硬到期，并在准确的空闲 `>=` 五分钟或硬时长 `>=` 二十分钟边界到期。只有已接受的 lease 作用域动作才刷新空闲时间；拒绝、状态、枚举、申请与释放均不刷新，硬到期永不后移。绑定 generation 的 timer 不能撤销替代 lease。`leaseRevision` 以安全整数递增，溢出时 fail closed 而不是回绕。子进程墙上时间不能延长任何限制。helper 在每个原生事件之间检查撤销状态，并在每次原生调用前扣减相应事件/动作预算。

畸形 JSON、重复 key、未知字段或判别值、错误版本、超限 JSON 或 PNG 数据以及无效 frame 顺序都会关闭专用控制通道。通道关闭会拒绝其中的控制工作，但不会终止 Harness 或影响普通聊天。

Host bridge 而非 codec 拥有有状态请求 ledger。它最多允许 32 个 pending 请求，拒绝重复 ID、传播取消，并保留有界终态 tombstone，使迟到响应不能结算新工作。每条记录绑定 request 身份、kind、官方 session、子进程 generation、deadline 与取消状态；当且仅当已验证 request 携带 lease 字段时，还从中派生并保存可选的准确 `{ leaseId, leaseRevision }` tuple。`lease.revoke` 只影响 session、lease ID 与 lease revision 三者全部匹配的记录，绝不影响无 lease 请求、其他 session、其他 lease 或其他 revision。每个子进程都有 generation；listener 闭包捕获准确的子进程和 generation，除非二者仍与当前 owner 相同，否则拒绝消息，因此旧子进程不能替代新子进程响应。

## 专用 Harness/Electron IPC 链路

Desktop 保留现有基于 `spawn()` 的 Harness 启动方式，只把 stdio 约定改为 `['ignore', 'pipe', 'pipe', 'ipc']`，并设置 `serialization: 'advanced'`。启动前先复制环境并剔除继承的 `NODE_CHANNEL_FD` 与 `NODE_CHANNEL_SERIALIZATION_MODE`；随后 Node 只根据 `ipc` 项自行创建 fd 3 和内部通道管线。应用代码绝不设置这两个变量、手动打开 fd 3，也不把启动方式改成 `fork()`。每条 Node IPC 消息恰好是一个已复制、无前缀的原始 `Uint8Array` 协议 frame。四字节大端长度前缀只属于后续 Electron/helper 的 stdin/stdout 链路，绝不能出现在 Node IPC 链路上。

每条链路的每个方向都有独立的 fail-closed 白名单：

| 方向 | 允许的消息 |
| --- | --- |
| Harness → Electron | 全部 27 个 `BRIDGE_REQUEST_KINDS`，包括两个只供受信 provider 使用的 lease 请求；control 只允许匹配同一 session 与 request 的 `request.cancel`，以及 Harness session dispose 时的 `session.revoke`。禁止 response、PNG frame、helper 专用 request、`lease.revoke` 和 `parent.shutdown`。 |
| Electron → Harness | 只允许封闭的 bridge response 联合类型；如果元数据声明截图，其后必须紧邻关联 PNG；control 只允许 `lease.revoke`（使子进程立即终止该 lease 的 pending 与后续工作）和 `parent.shutdown`（关闭 client）。禁止 request、`request.cancel` 和 `session.revoke`。 |
| Electron → helper | 全部 14 个 `HELPER_REQUEST_KINDS`，包括仅限权威方的 `lease.install` 与 `input.release`；四种 control 仅允许由 Electron 发出，并且都是高优先级。 |
| helper → Electron | 只允许封闭的 helper response 联合类型；声明截图时其后必须紧邻关联 PNG。禁止 request 和 control。 |

每个已解码 JSON frame 都必须在 image correlator 进入 PNG-pending 状态前完成方向验证。因此，方向错误且声明 image 的 response 即使永远不发送 PNG，也会立即关闭专用控制链路；孤立或方向错误的 PNG 同样如此。未知、畸形或方向错误的消息绝不终止 Harness 进程、关闭普通 Web transport 或影响聊天。任务 5 实现 Node 两向链路；任务 9 按相同表实现 helper 两向链路，不得扩大白名单。

一个 `desktop-control-host` 插件实例只创建一个进程级 IPC client 和一个 lease cache，并由 Browser Control 与 Computer Control provider 共享。两个 Service seam 都公开内部 `acquireLease` 操作，复用协议中的 acquire DTO/result。provider 在内部取得 transport 字段与官方 session、请求期望子集、只缓存 Electron 返回的 descriptor，再发出普通动作。snapshot 方法返回类型化的不可变 Service envelope `{ result, png? }`：`result` 持有有界协议 metadata，`png` 是 `ImmutablePng`；只有在 transfer ID、字节长度、SHA-256 与尺寸全部完成关联验证后，`result.image` 和 `png` 才会同现或同缺。任何 Service 都不暴露可变的原始截图字节。该数据流不新增第三个 Service，也不会向模型 schema 暴露 lease acquisition 或权威字段。

Desktop 专用 Cordis patch 是 host 唯一的生产挂载点；Desktop manifest、项目引用、依赖锁、staging allowlist、stage 后运行时断言、包文档和生成的 module graph 都必须包含同一个包。Desktop main 在 `apps/desktop/tsdown.config.ts` 中把 `@deepseek-ai/dsh-desktop-control-protocol` 保持为外部依赖，使运行时相对定位的 `protocol-v1.json` 留在包旁。stage-shaped import smoke 和 staging allowlist 必须检查 protocol 包的 `package.json`、`lib/index.js`、`lib/invariant.js`、`protocol-v1.json`，Host 包的 `package.json`、`lib/index.js`、`lib/invariant.js`，以及 Browser/Computer Service 包各自的 `package.json`、`lib/index.js`、`lib/invariant.js`。控制链路缺失或断开时只让 provider 变为不可用，不得阻止 Harness 启动。

client 与 server 都通过单一 send-callback 队列串行发送完整的 JSON 加可选 PNG envelope。每个 frame 在入队前必须复制；当前 envelope 的所有 frame 都完成 send callback 后，才能开始下一个 envelope，因此并发截图不能互相穿插。transport decoder 每次只接收一个原始 frame，在进入关联状态前验证 JSON 方向，随后维护 JSON/PNG 必须相邻的状态。

ledger 准确允许 32 个 pending request，并最多保留 256 个终态 request-ID tombstone。每条记录绑定 `requestId`、`requestKind`、官方 `sessionId`、子进程 generation、deadline、取消状态，以及只从已验证 lease-bearing request 字段派生的可选 lease tuple。只有 request ID 与 kind 都匹配当前 pending 记录的 response 才能结算工作；取消还必须匹配该记录的 session，而 `lease.revoke` 必须准确匹配 session、lease ID 与 lease revision。准确 revoke 会先让共享 cache 失效，再以 `LEASE_REVOKED` 只结算一次匹配的 pending 工作；无关或无 lease 的记录继续存活，重复 revoke 不刷新 FIFO 顺序且不重复结算，迟到响应由既有 tombstone 丢弃。Electron 只接受 `nowUnixMs < deadlineUnixMs <= nowUnixMs + 30,000`，可以缩短合法 deadline，只把正数剩余时长转换为 `timeoutMs`，绝不延长。

generation 检查必须覆盖入站消息、异步 provider completion、timeout/abort continuation 和 send callback。替换子进程时，必须先推进 generation，再启用任何新 listener；旧 generation 捕获的 completion 或 callback 只能丢弃其隔离副本。意外的进程级 `disconnect` 会用 `DISCONNECTED` 拒绝所有控制 pending 工作并清空有界队列/listener，但保留已拥有的 Harness 进程和普通聊天继续运行。

Host 在正常路径使用真实可等待的 `agent/turn-stopping` 边界：先同步让匹配 lease cache 失效，再等待有界的 `control.lease.release` tail 后返回。由于 `session/event` 是提交后的 fire-and-forget，且错误/取消路径不一定经过 `agent/turn-stopping`，`turn/end` observer 只负责同步失效并排入幂等的逐 session fallback release tail；它无法保证 release 先于 `turn/end` commit。可等待的 `session/flush` listener 会在下一次受 checkpoint 保护的模型或顶层工具副作用前 drain 该 tail。`session/disposed` 同步失效并排入 `session.revoke`；插件 effect disposer 与 parent shutdown 在移除 listener 前 drain 全部 release/revoke tail。transport 清理失败会使控制不可用，但这些 listener 仍需完成，不能因此破坏普通聊天。

正常应用关闭必须保持任务 6 的权威边界：Electron 先停止接收新工作，撤销 session 与 lease，并等待下游浏览器/helper 队列清理和已知输入释放完成。`HarnessProcess.beforeStop` hook 拥有剩余控制关闭，并被启动失败、retry 和 quit 等每条内部或外部 stop 路径调用；随后才入队 `parent.shutdown`，在有界时间内等待其 send callback，断开准确的 Node IPC 链路并移除 listener，最后才允许 `HarnessProcess.stop()` 终止进程树。任务 5 只提供 transport hook，不签发 lease，也不释放原生输入。transport 日志只能记录元数据，例如方向、generation、有界计数和关闭原因码；绝不记录 frame 字节、已解码 request/result 内容、语义文本、页面或字段值、PNG 数据、Cookie、token 或绝对用户路径。

## Browser Control 架构

Electron 主进程通过 `BrowserSurfaceManager` 拥有一个全局排他的 Agent 浏览器 surface；进程级 lease coordinator 对第二个会话返回 `BUSY`。每次 mount 都有 surface generation 和 mount token，陈旧的隐藏或清理回调不能影响替代实例。Agent 创建的 surface 可见，并使用在 teardown 时清除的唯一非持久化 partition。人工 workbench 保持持久化登录 partition。“交给 Agent”只创建由主进程拥有的 intent，让下一个官方子进程 acquire 请求可以针对当前可见实例显示确认；renderer 既不签发 lease，也不提供 session 权威，并且不导出 Cookie、localStorage 或凭据。

每次 `browser_snapshot` 返回：页面 URL、标题、导航修订号、可交互元素的有界语义树，以及视觉模型显式请求时的截图附件。适配器从 `Accessibility.getRootAXNode` 开始，以有界广度优先方式遍历 `Accessibility.getChildAXNodes`：最多 2,000 个原始节点、32 层深度、512 次 CDP 调用、2,000 ms 墙上时间和 300 个投影后的可操作节点。内部只允许使用白名单内、只读的 `DOM.describeNode` 判定 `type`、`autocomplete`、`disabled` 和 `readonly`；仍禁止 `Runtime`、JavaScript 求值和 selector。默认不返回可编辑值，无法确定是否敏感时直接拒绝。

元素引用是绑定 surface generation 和导航修订号的短期 opaque ref。debugger detach、surface 销毁、主文档导航、same-document 导航或语义树大改都会使引用失效，并丢弃迟到 CDP 响应。浏览器操作只接受当前 ref；不存在浏览器坐标操作。`browser.wait` 只接受封闭模式 `duration`、`navigation` 或 `loading-idle`，其中 `durationMs` 不超过 10,000。截图可以支持模型视觉，但不会创建坐标操作路径。

manager 跟踪 `attachedByUs`。如果其他 debugger 已拥有 surface，控制返回 `BUSY` 且绝不 detach 它；Stop 必须等待 detach、视图清理、partition 清除与 lease 撤销全部结束后才完成。Agent 导航拒绝带 userinfo 的 URL，以及 loopback、link-local 或私网目标，并对每次 redirect 重复检查；只有用户明确加入 allowlist 的目标可以例外。

页面内容始终标记为不可信。网页文字不能签发授权、扩大白名单、确认敏感动作或要求 Harness 绕过策略。0.4.3 拒绝弹窗、下载、摄像头、麦克风、定位、剪贴板读取、新窗口、file input、upload 和文件 chooser。

## Computer Use 架构

`computer_snapshot` 必须绑定一个已授权应用与窗口，返回无障碍树和可选截图。语义节点引用绑定进程身份、窗口身份、快照修订号和显示缩放；窗口改变后，旧引用 fail closed。Agent 优先使用语义引用，只有没有可用无障碍节点且模型支持图片输入时才允许使用坐标操作。

在 Windows 上，目标身份包含 HWND、PID 和进程创建身份，因此句柄或 PID 重用不能让陈旧 ref 复活。适配器拒绝受 UIPI 阻止、高完整性和 secure desktop 目标，且绝不请求提权。

原生 helper 只实现上文定义的封闭 helper 清单和字段矩阵。`status` 不虚构目标字段，`list` 不虚构窗口或快照字段，目标作用域操作只携带其所需的目标字段。已安装 lease 保留配对 targets，不使用彼此独立的应用与窗口集合。Electron 保守记录且只记录已知处于按下状态的按键与按钮。如果 helper 意外退出，Electron 启动一个二进制 hash 相同，并且在签名构建中代码签名身份相同的新 helper，再通过 Electron 专用的 `input.release` 只发送相应的按键/按钮 up 事件。

正常关闭顺序固定为：撤销 lease → 清空队列 → 释放已知输入 → 收到释放确认 → 以 EOF 关闭 stdin → 等待退出 → 使用有界 terminate/kill ladder。`DesktopApplication` 在退出、重试、helper 崩溃恢复和会话 dispose 时，都会先等待这套组合控制关闭完成，再停止 Harness。整机断电或同时强制终止 Electron 与 helper 时，不保证能够释放输入。

不支持图片输入的模型只能使用 DOM 或无障碍语义模式，不能猜测屏幕坐标。截图通过 Harness 附件服务保存并作为 ImageBlock 传递，不能把无限 base64 放进 IPC 或日志。

## 授权与安全

首次使用在设置中显示两项独立权限：屏幕查看与辅助控制。未授权时工具返回明确的本地状态和打开系统设置的人工入口，不循环弹窗、不自动修改系统设置。

Electron 主进程只有在完成其自行拥有、用户可见的原生审批 challenge 后，才签发进程内唯一的短时 `ControlLease`。lease 绑定 Harness 官方会话、保持配对的生效 targets、生效 capabilities、Electron 编写的配额、`leaseRevision` 和最大时长。它会在任务结束、会话切换、应用重启、用户接管、准确的五分钟空闲边界或准确的二十分钟硬边界撤销。设置页可以撤销单个应用或全部授权。子进程和模型不能提交 `approved`、签发 lease、选择配额、推进 `leaseRevision`，也不能延长任何 deadline 或 lease 时钟。

Harness `ctx.approval` 可以请求交互并提供审批 UX，但仅凭其结果不能授权安装 lease，也不能授权执行敏感最终动作；两类操作都必须由 Electron 完成并验证自己的原生可见 challenge。审批 coordinator 全局只允许一个 pending dialog；owner 窗口缺失或不可见、Escape、关闭、abort、异常或并发请求都会拒绝。迟到批准必须重新校验官方 session、当前 target、lease revision 和 allowlist。同一个 Harness Node 进程内已安装的 Host 插件属于可信计算基。0.4.3 只保证 renderer 消息、页面文本和模型输出不能伪造 Electron 确认，并不声称隔离恶意的进程内 Host 代码。

已知密码、secure text、一次性验证码、付款和文件目标直接拒绝；生物认证、密钥链与密码管理器、系统隐私/安全设置、安装/卸载、删除数据，以及下载或执行文件也直接拒绝。页面 JavaScript 可以让表面普通的交互产生外部影响，因此 0.4.3 不声称仅凭 AX 语义就能分类每一种敏感结果。临时 Agent surface 的任务 lease 只授权固定的普通动作清单。在持久化人工 surface 上，每个会产生变更的 `navigate`、`click`、`type`、`key`、`select`、`scroll`、`back`、`forward` 或 `reload` 都绑定由 Electron 拥有的一次性 action grant：对准确 digest 显示原生 challenge，并且只能消费一次。页面内容、模型、renderer 和子进程都不能提供、消费或复用 digest 或 grant。Stop 永远无需批准。

控制期间始终显示顶部状态胶囊，至少包含 Agent 名称、当前应用、动作状态与停止。0.4.3 没有 Pause 状态或控件。菜单栏/托盘同步提供停止入口；默认全局紧急停止快捷键为 `CommandOrControl+Shift+F12`，可由用户修改。只有活跃 lease 存在时才注册快捷键；注册失败会让授权 fail closed。重新绑定必须原子完成，只注销本功能拥有的 accelerator，绝不调用 `unregisterAll`。其 callback 先同步关闭 admission 并撤销权威，再等待清理。任何停止都执行相同的可等待顺序，并记录不含屏幕正文的本地审计事件。close-to-tray 在活跃控制清理完成前不能隐藏窗口。

控制设置使用独立 strict schema 与原子文件替换，只持久化普通 app allowlist、普通开关和 accelerator，不持久化窗口 ID、lease、ref、action digest、截图或 session 权威。本地审计按规则轮换，每行只包含时间、加盐 session hash、opaque app ID、动作类别与结果；不得包含页面或字段文字、URL 与 query、路径、截图、Cookie、token 或其他秘密。

## 发言刻度

采用用户确认的第一版视觉：聊天正文左侧保留约 28–32px 的独立窄 gutter，无底板、无卡片式时间线。普通发言使用可见但克制的中性灰短刻度，当前项使用 DeepSeek 蓝长刻度与空心圆点；hover 或键盘聚焦时显示“第 N 条发言 · 时间”和最多两行预览，底部显示当前位置计数。

现有普通刻度引用了不存在的 `--dsw-alias-label-quaternary`，必须改为已定义的主题 token 并提供 fallback。轨道和普通刻度在浅色、暗色、非 Retina 与高对比度模式下都必须可辨认。超长会话不让 120 个重叠按钮争抢点击：轨道根据指针 Y 选择最近锚点，键盘采用 roving tabindex、方向键、Home 与 End。窄窗口不再静默删除能力，而是收起为小型“发言导航”按钮。

点击刻度只读取必要历史并滚动到准确用户发言，目标消息短暂显示主题色定位提示。它不会修改历史、创建会话、恢复草稿、回退、删除或发送消息。

## 性能与隐私

- helper 按需启动，闲置时退出；没有控制任务时不截图、不轮询无障碍树、不保持高频计时器。
- 浏览器优先返回语义差异；桌面截图按窗口裁剪并按模型需求降采样。连续动作默认最高 2 FPS，静止时为 0 FPS。
- 截图与语义快照只进入当前会话的有界附件/工具结果；不得写入 telemetry、普通日志、记忆插件或 MSE 候选。
- 密码字段值、Cookie、localStorage、授权 token 和隐藏窗口内容永不返回模型。
- 页面或应用发生变化时返回 `STALE_REF`，Agent 重新获取快照，不能盲重试旧坐标。
- 单轮动作数、快照字节、语义节点数、文本长度和总控制时长均有硬上限。

## UI 与错误处理

设置页增加与现有设置卡片一致的“浏览器与电脑控制”区，显示平台支持、系统权限、已授权应用、默认共享方式、紧急停止快捷键和最近一次本地控制状态。插件市场只显示它由 Desktop 内置且已加载，不显示永久的“重启后加载”假状态。

内置浏览器增加“交给 Agent/停止接管”按钮。Agent 使用临时浏览器时自动打开可见工作台；共享当前页面前展示登录态提示。Computer Use 启动时不抢焦点，第一项需要交互的动作才激活目标应用。

权限缺失、窗口关闭、应用退出、目标被遮挡、截图失败、无障碍树不可用、stale ref、模型无视觉能力或用户停止，都返回结构化错误。错误不能导致 Harness 启动失败，不能阻塞普通聊天，也不能遗留 helper、按键状态、鼠标拖动或 BrowserView。

## 发布门禁

0.4.3 不以“能打开软件”冒充 Computer Use 完成。发布必须提供真实可见任务证据：浏览器至少完成一次多步骤页面操作；每个平台至少控制两个无害测试软件完成观察、点击、输入和停止；拒绝分支不得产生副作用。

没有签名凭据时允许交付明确标记为未签名/未公证的测试版，但不能承诺 TCC 持久或 SmartScreen 信任。配置签名后，验证要求嵌套 helper 与 app 使用同一个 Team ID、采用 hardened runtime 签名并通过公证；Windows 验证同样要求签名 helper 和签名 NSIS 安装器，并明确 SmartScreen 状态。

所有构建必须来自最终共同提交和全新 `desktop-v0.4.3` tag。公开资产要验证上传状态、大小、SHA-256、校验文件以及一次匿名重下载；不得包含密钥、Cookie、截图、用户文件、`~/.dsh` 数据或本机权限数据库。
