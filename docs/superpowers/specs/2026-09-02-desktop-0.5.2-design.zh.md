# Desktop 0.5.2 界面、权限、启动与体积设计

[English](2026-09-02-desktop-0.5.2-design.md) | 中文

## 目标与基线

从已发布的 `desktop-v0.5.1` 精确提交 `b8595d75a9f94fb332689e28aef70cf5b7d72d4f` 开始，用同一份最终源码提交交付 Intel macOS 与 Windows x64 Desktop 0.5.2。

本版同时完成两组可独立验收的工作：

1. 恢复并美化会话导航线、整理 ChatGPT 风格左侧栏、把现有工作台整理为固定右侧栏目，并提供安全的“本会话不再询问”。
2. 量化并缩短冷启动、减少可证明不需要的安装内容，并修复 Windows 小尺寸图标与任务栏/托盘显示。

Harness 核心版本继续保持 `0.1.1-rc.2`。0.5.2 不在发布途中追逐新的官方版本；官方同步另开后续版本，避免把 UI、性能和上游迁移风险混在一起。

## 功能与页面

### 左侧栏

- 保留现有 Workspace/Project 树、会话状态、重命名、归档、分叉、拖拽排序、搜索与悬浮信息卡；不复制一套 ChatGPT 数据模型。
- 视觉参考 ChatGPT：弱化边框、统一 32–34px 行高、使用轻量选中胶囊和清晰的分组节奏。
- 项目行与其会话列表之间保留 4px 左右的视觉间距；不同项目组之间保留 6–8px 间距，解决“全部粘在一起”的问题。
- 标题继续单行省略，状态点与操作按钮保留独立槽位；任何美化都不得挤压文字或改变拖拽命中区。
- 折叠侧栏、窄窗口、长中文/英文标题、深色模式、缩放与键盘焦点必须保持可用。

### PromptRail 定位线

0.5.2 恢复 `desktop-v0.4.11` 的一等导航结构，并迁移到当前 `ui-conversation` 架构：

- 定位线属于会话正文左侧沟槽，不属于项目侧栏，也不是悬浮预览组件。
- 它距离会话面板左边约 16px；正文仍使用当前居中宽度，不被定位线压缩。
- 细竖线、小刻度、当前轮次长刻度和圆点共同表达位置。
- 鼠标悬停或键盘聚焦才显示轮次、时间与单行内容预览；预览不覆盖正文输入框。
- 支持 ArrowUp/ArrowDown/Home/End、焦点恢复、120 条渲染上限、首尾可达及窄窗紧凑模式。
- 只导航到现有历史消息；不增加删除、编辑、回退、重发或分叉语义。

### 固定右侧工作台

- 复用现有 `desktop-workbench` 和布局系统的固定、可调整宽度右栏；禁止实现成悬浮菜单或第二个 Side Chat。
- 栏内入口按纵向列表呈现：审阅、终端、浏览器、文件。每行使用图标、名称和现有快捷键信息，选中行有低对比背景。
- 入口列表是右栏内部导航；选中后仍在同一个右栏中显示现有 Mode 内容。
- 保留 320–720px 宽度边界和拖拽宽度持久化；增加最近 Mode 的持久化，但不自动为每个新会话弹开右栏。
- Escape 关闭、键盘上下移动/Enter 选择、屏幕阅读器语义与减少动态效果必须有测试。

### 本会话不再询问

现有审批协议只有 `allowed-once`，没有足以安全表达工具参数范围的永久授权规则。因此 0.5.2 不新增全局“永远允许”，也不按工具名静默记忆授权。

审批卡增加三个清晰动作：拒绝、允许一次、本会话不再询问。最后一个动作：

1. 展示与当前权限选择器一致的 Full access 风险确认；
2. 确认后在当前 Session 执行现有 `/permission danger-full-access`；
3. 只有命令成功后，才把当前待审批回答为 `allowed-once`；
4. 该 Session 后续因权限预设为 `approval: never` 而不再弹同类审批；
5. 用户可随时通过输入框权限选择器切回 Workspace Write。

权限状态继续由 Session 事件持久化，不引入浏览器 `localStorage` 权限真相，不改变 `ApprovalOutcome` 协议，也不把授权扩散到其他 Session。操作系统权限、站点权限或未来独立高风险域仍可单独询问。

## 数据结构与接口

- `PromptAnchor` 仍是定位线唯一数据源；只使用 `seq`、`turn`、`time`、`kind`、`preview`，不二次读取会话内容。
- `WorkbenchSnapshot` 继续拥有 `open`、`mode`、`width`、`sessionId`；新增版本化 Mode 偏好键，宽度键保持兼容。
- 审批卡通过 `conversation.composer` 的受限注入取得当前 Session 的命令面；该命令面与输入框权限选择器共享同一实现，避免复制 Session 查找和命令发送逻辑。
- 启动日志只记录固定里程碑和耗时。允许增加固定、无用户数据的 Host 启动阶段计时；禁止记录路径、URL、Profile 内容、命令、凭据或会话数据。
- 包体清单以相对路径、字节数、类别和 SHA-256 为证据；不读取或打包用户 `DSH_HOME`。

## 启动与包体

当前日志表明主要等待发生在 `fallback-ready` 到 `url-reported`，即 Harness Loader 插件树启动，而不是加载页。`dsh web:` 目前是所有必要路由挂载后的就绪信号；不得直接提前打印。

实施顺序：

1. 在临时 `DSH_HOME` 上记录五次隔离冷启动和五次同安装热启动，并统计现有固定里程碑。
2. 对 Host 启动增加无敏感信息的阶段证据，找出实际最慢的同步初始化。
3. 只延迟不属于首屏/核心 API/审批/会话恢复的初始化，或者合并重复读取；任何优化都必须保留 Loader 失败传播和真正的 readiness。
4. 同一机器、同一提交父版本、同一 fixture 复测；目标是冷启动中位数至少改善 15%，且 P95、热启动和失败恢复不退化。达不到时不得用假就绪换数字，必须保留证据并撤销无效优化。

Windows 所称约 500MB 是安装后占用，不是约 154MB 的 Setup 下载大小。包体优化先生成 `app.asar`、`app.asar.unpacked`、Electron runtime、locales、native prebuilds 和依赖资源清单；只删除当前目标平台不可达的二进制、调试/类型/映射文件、非保留语言包或经过入口图证明未使用的资源。不得破坏 Profile module fallback 所依赖的物理包目录。

目标是在同一 Windows runner 上使安装后占用至少减少 5%，同时 Setup 不增大。若 Electron 与真实运行依赖构成硬下限，报告分类字节证据；不得通过首次启动在线下载、把内容搬进用户目录、删除许可证或牺牲离线能力伪造缩小。

## Windows 图标

- Mac 继续使用现有 `icon.icns`；Windows 使用独立的裁切源，不再直接缩放带大透明外边距的 1254px Mac 风格源图。
- Windows ICO 必须包含经人工检查的 16、20、24、32、40、48、64、128、256px 图层；小尺寸优先保持鲸鱼轮廓清楚，图案填充画布但不触边。
- BrowserWindow/任务栏使用 Windows ICO；托盘使用专门的 16/20/24/32px PNG，不把 1254px 源图直接交给 `Tray`。
- Setup、卸载器、开始菜单、桌面快捷方式、任务栏和托盘均需在原生 Windows 截图验收。

## 平台归属

- Mac 执行任务是共享 UI/权限实现所有者，同时完成 Intel Mac 构建和原生视觉/交互验收。
- Windows 执行任务是共享启动/包体实现所有者，同时完成 Windows 图标、NSIS、Setup 与原生生命周期验收。
- 另一平台只能在总指挥给出共享提交后消费并做平台适配，禁止双方重复修改同一共享功能。
- 总指挥独占版本号、发布文档、集成、最终 SHA、tag 与 Release。

## 验收标准

- 左侧项目/会话层级、状态、菜单、拖拽和搜索回归全部通过；视觉截图证明组间有间距且长文字不碰撞。
- PromptRail 在宽/窄窗口、左右栏开关、长会话、键盘、深浅主题下均正确，结构与 v0.4.11 一致但使用当前数据流。
- 右侧是固定可拖宽栏目，四个入口纵向排列，无 Side Chat、无浮层替代物。
- “允许一次”仍只允许一次；“本会话不再询问”只在 Full access 命令成功后关闭当前审批，同 Session 后续不再询问，切回后恢复询问，其他 Session 不受影响。
- 冷启动与包体均有同机前后数据； readiness、失败页、重试、退出和进程树清理不退化。
- Windows 所有小尺寸图标和安装入口原生可辨识；Mac 图标不被 Windows 调整改变。
- 同一最终 SHA 的 Mac DMG 与 Windows x64 Setup 分别完成安装、启动、操作、关闭、卸载/替换和用户数据保留验收，随后才允许发布 `desktop-v0.5.2`。
