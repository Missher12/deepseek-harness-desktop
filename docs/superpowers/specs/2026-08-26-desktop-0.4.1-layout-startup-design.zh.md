# Desktop 0.4.1 布局与启动优化设计

[English](2026-08-26-desktop-0.4.1-layout-startup-design.md) | 中文

## 目标

使用同一份源码提交交付 Mac Intel 与 Windows x64 Desktop 0.4.1：修复大量模型时推理弹窗的排版问题，并在不改变模型能力发现、模型请求语义、用户 Profile 或 Harness 数据的前提下，优化可量化的 Desktop 启动速度。

## 范围

- 保留现有六档推理滑块、自适应向上/向下 Portal 定位、模型选择与角色滑块偏好。
- 弹窗改为三个区域：不滚动的推理区、独立滚动的模型区、不收缩的角色滑块底栏。
- 先记录本地启动阶段，只优化已证实的串行或重复工作。
- Mac 安装包验收与 Windows 原生安装器验收必须来自同一提交。
- 本地验证全部通过前不连接 GitHub；最后只做一次同步、一次推送和一次发布工作流。

NewAPI 和其他供应商能力发现改动明确不属于 0.4.1。

## 推理弹窗

弹窗继续使用固定定位 Portal，最大高度仍由现有定位控制器计算；弹窗根节点不再滚动，内部调整为：

1. `effortPane`：固定尺寸的滑块或“不支持推理”状态。
2. `modelPane`：`flex: 1`、`min-height: 0`、`overflow-y: auto`，承载模型、加载态和空态。
3. `preferenceFooter`：固定尺寸底栏，带独立分隔线和菜单背景。

这样可保持默认向下、空间不足时向上翻转的行为，同时避免模型过多时角色滑块被挤进模型行。焦点顺序仍为滑块、模型、底栏；Escape、Tab 返回、点击外部关闭和减少动态效果均保持不变。

## 启动优化

记录以下启动里程碑：Electron 就绪、窗口前置数据就绪、本地加载页可见、模块回退准备完成、Harness URL 输出、Harness 页面就绪、Desktop 可用。日志只记录阶段名称和耗时，不记录用户数据。

允许实施三项边界明确的优化：

1. 创建 BrowserWindow 前并行读取 Desktop 偏好与已保存窗口尺寸。
2. 为 Desktop 增加可选的模块回退缓存。缓存以安装位置、Desktop 版本和根 manifest 身份为键，只保存包名与链接目标；命中时逐项校验真实链接。缓存缺失、损坏、应用移动或链接不一致时执行现有完整修复，并原子更新缓存。CLI 行为不变。
3. 合并同一时刻重复的推理模型目录加载；首次加载刚结束就打开弹窗时不立即再请求一次，稍后重新打开仍正常刷新。

任何没有改善隔离启动基准、或者削弱恢复能力的优化都不保留。

## 安全与兼容

- 不新增供应商密钥的读取或写入。
- 不删除或重写 Profile 组合包、外部插件、会话、记忆或用户配置。
- 回退缓存只是加速索引；真实文件系统链接仍是权威，任何不一致都回到现有完整修复。
- 弹窗仅调整展示和加载合并；发送给 Host 的模型 ID 与推理等级不变。
- 除非现有发布流水线已提供签名凭据，否则 0.4.1 继续保持未签名、未公证边界。

## 验收

- 使用足够多模型触发溢出的回归测试：只有模型区滚动，角色滑块始终位于固定底栏。
- 现有定位、鼠标、触摸、键盘、偏好与模型选择测试全部通过。
- 模块回退缓存覆盖：命中、未命中、损坏、应用移动、链接丢失或被修改、原子更新、Windows junction 路径。
- 生命周期测试证明偏好和窗口尺寸读取是并行的。
- 加载合并测试证明并发只发起一次，稍后的真实刷新仍执行。
- Mac 打包版执行五次隔离冷启动与五次热启动，记录各阶段中位数；总启动时间不得退化，热启动 Desktop 包装阶段应有改善。
- Mac DMG packaged smoke 与 `hdiutil verify` 通过。
- Windows Setup 必须从同一提交完成构建、可见安装、启动、关闭、卸载、快捷方式清理与 Harness 数据保留验收。
- 发布资产在 CI 内验证，避免本机反复下载大文件。
