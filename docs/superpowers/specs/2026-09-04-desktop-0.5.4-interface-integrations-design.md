# Desktop 0.5.4 Interface and Integrations Design

English | [中文](2026-09-04-desktop-0.5.4-interface-integrations-design.zh.md)

**Status:** Approved by the user on 2026-09-04; implementation pending

**Desktop baseline:** `0da8093092c9a29f5cebdfc094d0b58d97b56219` (`desktop-v0.5.3`)

**Target:** Desktop `0.5.4` with Harness `0.1.2-rc.1`

## Goal

Make the installed Desktop feel coherent at its normal window size: preserve the macOS titlebar safe area, keep the Turn rail on the left, dock a readable ChatGPT-like Workbench on the right, surface callable skills near the top of `@` and `+`, and make the real BrowserSkill and Open Design integrations discoverable without adding startup work.

## Product model

- The Desktop remains a three-surface product: sidebar, conversation, and one right Workbench. No second side-chat or duplicate browser surface is introduced.
- `@` is a focused discovery surface. Goal and Plan appear first, then callable skills/plugins, then dynamic Cordis plugins, files, and sessions. A typed query searches all groups; ordinary commands remain under `/`.
- `+` retains files/images first, Goal and Plan second, and callable skills/plugins next. It no longer floods the first viewport with every ordinary slash command.
- BrowserSkill remains the bundled `@wxg-prc-cpg/browser-skill-dsh-plugin`. Its `browser-skill` entry is the real executable skill and its six tools remain lazy until invocation.
- Open Design remains an independently installed official application and official `@open-design/dsh-runtime` companion in the isolated `open-design` DSH profile. Desktop may report that sanitized installed fact on demand, but must not copy it into the default `web` profile, manufacture a fake skill, or expose filesystem paths.

## Native chrome

- The context-isolated preload bridge is the durable source of the native titlebar presentation. A login redirect may drop URL query parameters but must not drop the macOS hidden-inset safe area.
- macOS keeps native traffic lights and a 38px draggable strip. Sidebar, conversation header, Workbench controls, and close buttons start below that strip.
- Windows keeps its current native frame with no synthetic top inset.

## Turn rail

The separate left-rail specification remains authoritative. In particular, the rail is visible in the default 1012px window when the Workbench is closed, floats outside transcript flow, and hides only when the center column falls below 680px.

## Workbench

- A labeled icon button makes the Workbench obvious; its accessible name still announces open/close state.
- With the sidebar auto-collapsed, a 1012px window docks a 300–360px Workbench and preserves a 640px conversation floor. Below the exact fit threshold it becomes the existing overlay drawer.
- The vertical launcher remains Review, Terminal, Browser, Files, Plugins. The existing persisted `browserSkill` mode id is retained for compatibility, but its user-facing label becomes Plugins.
- The Plugins page contains the explicit BrowserSkill check and a read-only Open Design companion status. BrowserSkill process/extension probing runs only after the user presses Check. Open Design status performs only a bounded manifest read when the Plugins page is opened.

## Data and interfaces

- `DesktopApi.presentation` is an immutable preload fact with a closed titlebar vocabulary.
- `DesktopApi.getIntegrations()` returns a closed, sanitized snapshot for Open Design: `installed` or `missing`, fixed profile name, and optional companion version. It returns no path, command, environment value, or credentials.
- Input candidates gain explicit goal, plan, skill, and plugin icons. Candidate ordering stays source-owned and deterministic.
- Existing session-scoped approval persistence remains unchanged and receives a regression test; this release does not broaden approval authority.

## Performance boundary

No integration discovery may run a daemon, browser, CLI, profile probe, or network request during Desktop startup. Skill catalogs keep their existing session prewarm; Open Design is inspected only when the Plugins page opens, and BrowserSkill is probed only on explicit Check.

## Acceptance

1. After the auth redirect, macOS still exposes `data-dsh-titlebar="hidden-inset"`; no sidebar/header/Workbench control intersects the native traffic-light zone.
2. The default window shows the left Turn rail when the Workbench is closed. Opening a preview does not move transcript text.
3. At 1012px with the sidebar collapsed, the Workbench is a docked column, not an overlay; at genuinely narrow widths it becomes the existing drawer and restores the saved width when space returns.
4. Bare `@` shows Goal/Plan and `browser-skill` before file/session results. `+` shows only the curated Add, Goal/Plan, and Plugins sections. Selecting `browser-skill` inserts its canonical `/browser-skill` invocation.
5. The Plugins page exposes BrowserSkill and reports the locally installed Open Design companion without revealing paths. Neither integration performs startup probes.
6. Mac Intel and Windows x64 package smoke tests cover titlebar/platform differences, 100%/150% geometry, the left rail, docked/drawer Workbench, plugin discovery, and complete process cleanup.

## Rollback

The titlebar bridge, rail positioning, Workbench geometry, launcher ordering, and integration-status surface land as separable commits. Rolling one back must not remove the BrowserSkill package, Open Design profile, user sessions, memory, evolution data, approval state, or Desktop preferences.
