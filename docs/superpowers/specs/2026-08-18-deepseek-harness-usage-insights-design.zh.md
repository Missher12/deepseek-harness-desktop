# DeepSeek Harness 使用统计设计

[English](2026-08-18-deepseek-harness-usage-insights-design.md) | 中文

**日期：** 2026-08-18

**状态：** 已批准实施

**目标平台：** Intel macOS 上的 DeepSeek Harness Desktop

## 目标

DeepSeek Harness Desktop 在设置中新增“使用统计”页面，采用用户提供的紧凑活动仪表盘布局。页面统计所有持久化会话的真实本地历史，包括归档会话和子智能体会话；派生索引不上传分析数据，也不保留消息内容。

页面包含五项顶部指标、一套可切换每日／每周／累计悬停口径的 12 个月 Token 颗粒图、活动洞察与最常用 Skill／工具排行。现有设置外壳、会话日志与应用生命周期仍是权威来源。

## 产品决策

- 设置导航在“模型”和“插件”之间新增一个 `usage` 页面，继续使用现有外壳、主题 token、排版与滚动行为。
- 页面首次加载时回填 `DSH_HOME` 中的全部持久化会话；后续读取每个会话的轻量持久化 revision，只重新计算新增、变化或已删除的会话。
- 归档会话和子智能体会话都计入；fork 会话排除继承的 seed 前缀，避免同一份提供方用量和调用在父会话与各后代中重复统计。
- 日期分桶使用 Mac 当前本地时区；时区变化会让日期派生缓存失效，并从日志重新构建。
- 派生索引只保存会话身份与 revision 信息、日期、时长、Token 数值桶、模型与推理强度标识，以及 Skill／工具名称和次数；绝不保存提示词、助手回复、工具参数或结果、标题、工作目录、凭据或附件。
- 提供方上报的 usage 是 Token 权威；缺失用量不做估算，页面会标明未计入的会话，而不是把估算值展示成精确数据。
- 历史日志会记录工具名和显式 Skill 身份，但无法可靠证明某个工具当时属于哪个 Loader 插件。因此排行榜命名为“最常用的功能”，逐行标记 Skill 或工具，不虚构插件归属。

## 指标口径

顶部依次展示五项数据：

1. **累计 Token 数：**提供方上报的未缓存输入、缓存读取、缓存写入与输出桶之和；推理 Token 已是输出的细分项，不重复相加。
2. **峰值 Token 数：**单个本地自然日的最高 Token 总数。
3. **最长会话时长：**单个会话内每段已完成 `turn/start` 到对应 `turn/end` 的时长之和；轮次之间的空闲时间不计入。
4. **当前连续天数：**截至今天连续存在至少一条真人消息的自然日数；如果今天尚未开始聊天，则从昨天向前计算。
5. **最长连续天数：**上述活跃日形成的最长连续区间。

活动图覆盖按周日对齐的 53 个自然周，提供三个标签。所有标签都保留同一套 53 列 × 7 行颗粒场；未使用日期以及当前周尚未来到的日期也显示灰色颗粒：

- **每日：**53 列 × 7 行的日历热力图；颜色按可见区间非零日期的 Token 数分成稳定的五档。
- **每周：**每列代表一个自然周汇总，在完整灰色底盘上从下向上填充一至七颗蓝色颗粒；悬停显示周日日期与该周 Token 总数。
- **累计：**每列代表截至该周的全历史运行总数，以从下向上的渐进颗粒堆叠展示。早于可见 53 周的 Token 作为第一列基线，因此最后一列与顶部全历史累计值一致。

活动洞察展示缓存命中率、最常用模型、最常用推理强度、已调用 Skill 种数、工具调用总数和聊天总天数。工具调用包含原生调用与 Code Mode 内部调用。Skill 次数合并显式 Skill 调用与能够按固定字段成功解析的 `skill` 工具请求，并且绝不保留原始参数 JSON。

## 架构

功能拆分为 Host provider 与 Client 设置包：

- `@deepseek-ai/dsh-usage-insights` 负责日志折叠、每会话派生行、全局聚合、storage domain 与只读 Remote 方法。
- `@deepseek-ai/dsh-client-ui-settings-usage` 负责设置页注册、加载与部分失败状态、自适应图表、数字格式化、本地化和无障碍。
- Web app bundle 挂载两者；Electron preload 不新增 API、文件系统访问、IPC 方法或权限。

Host 服务通过 `sessionPersistence.listSnapshots()` 获取稳定的会话 revision。未变化的会话从带版本的 `usage_insights` storage domain 读取；新增或变化日志通过持久化服务只读检查，不发布或恢复 Agent。服务只允许一个共享刷新任务并发，移除已不存在日志对应的派生行，且只在完整刷新完成后替换全局快照。

实时 `session/event` 会更新其所属会话的内存派生行；持久缓存写入会合并，并在 `turn/end` 或会话释放时发生，不会跟随流式 chunk 高频写入。首次扫描与实时事件共用同一个纯折叠器，generation 校验防止较晚结束的扫描覆盖更新的实时数据。

Client 在页面挂载时请求一份不可变聚合快照。现有连接取消机制会终止已放弃的读取；错误状态中的重试操作会启动新 generation。设置关闭时不执行后台轮询。

## 展示

页面遵循用户截图中留白充足的组合，不增加额外仪表盘装饰：

- 五项数据放在一个浅色圆角描边容器内，等宽分隔。
- 图表标题与三个文字标签处于同一行；所有口径下月份都与稳定颗粒场对齐。
- “活动洞察”和“最常用的功能”在图表下方形成平衡的双栏。
- 功能排行使用小型类型徽标、准确的 Skill／工具名与右对齐次数。
- 数值按当前语言紧凑格式化；悬停打开圆角可见浮层，并分别使用每日日期、每周周日或累计截止周的对应文案。

现有约 564 像素宽的设置内容列保持不变。日历格会压缩适配，不产生页面横向滚动；窄布局会换行顶部指标并堆叠底部两栏，200% 缩放保持单列可读。浅色和深色都使用 Harness token，含义不只依赖颜色；图表具有键盘可访问摘要、清晰焦点、减少动态效果和文字替代。

## 失败处理

- 尚无索引时，首次回填期间显示加载骨架。
- 派生行损坏或版本不匹配时直接丢弃并重建，永不改写会话日志。
- 单个会话不可读不会让整页失败；快照返回遗漏数量，界面展示有限警告，“重试”重新执行完整刷新。
- 提供方 usage 包含无效或不安全数值时，该样本会被忽略并计入不完整数据。
- 完全没有提供方 usage 时，Token 区域显示不可用，不虚构零值；仍能派生的活跃和调用数据继续显示。
- 刷新取消、应用退出与服务释放会停止未完成工作，并在资源拆除前等待共享刷新结束。

## 考虑过的方案

- **浏览器每次打开都扫描全部日志：**否决，因为 renderer 不应得到文件系统权限或包含消息的日志，而且重复全量扫描无法随历史规模稳定扩展。
- **只从新版本发布后记录遥测：**否决，因为用户明确要求计入全部既有历史，并且并行遥测会成为持久会话事件之外的第二权威。
- **独立分析数据库作为权威：**否决，因为它可能与已删除、替换、修复或 fork 的日志漂移。绑定 revision 且可重建的派生索引既能快速读取，也不会与会话持久化争夺权威。

## 验证

- 纯折叠测试覆盖 Token 桶、重复 usage 替换、日期边界、夏令时与时区重建、轮次时长、当前与最长连续天数、显式和模型加载的 Skill、原生与 Code Mode 内部工具、缺失 usage 及 seed 继承排除。
- 服务测试覆盖完整回填、未变化 revision 复用、会话变化与删除、损坏缓存恢复、并发刷新复用、取消、实时事件竞争和部分失败。
- 真实 Loader 测试在无 API Key 条件下挂载 Host provider、Remote 服务、Client 包、设置 slot、持久化 backend 和 storage domain。
- Client 测试覆盖精确格式化、三个标签都保留 371 颗及其悬停总数、热力档位、空／加载／部分失败／错误状态、窄屏重排、键盘摘要与浅深色 token。
- 浏览器验收在真实 800 像素窗口中打开组装后的设置面板，验证约 564 像素内容宽度、正常与 200% 缩放、无横向溢出和无控制台错误。
- Intel macOS 成品验收使用带确定性历史 fixture 的隔离 `DSH_HOME`，证明已有会话产物字节完全一致，并检查应用退出和监听器清理。
- 针对用户 `~/.dsh` 的真实验收只读会话产物，并在替换或发布应用前用独立折叠结果核对页面总数。

## 验收标准

Mac 应用可从设置打开“使用统计”，并在有限的首次历史回填后展示所有可用会话。每个数字都遵循已记录的事件口径，fork 历史不会重复统计，不完整数据会明确披露，派生索引不包含内容或凭据。页面在真实设置宽度下贴合用户提供的紧凑仪表盘，200% 缩放与深色模式仍可使用，并在安装前通过源码、组装 Web 与 Intel macOS 成品验证。
