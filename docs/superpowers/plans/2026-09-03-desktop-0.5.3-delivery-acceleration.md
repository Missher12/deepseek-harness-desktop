# Desktop 0.5.3 Delivery Acceleration Implementation Plan

English | [中文](2026-09-03-desktop-0.5.3-delivery-acceleration.zh.md)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans, superpowers:test-driven-development, and superpowers:verification-before-completion.

**Goal:** Decompose the current serial, duplicate-build dual-platform validation into "build once, parallel acceptance on the same artifact", shortening feedback time while retaining the complete native release gate for the final SHA.

**Architecture:** Each platform's build job produces one immutable candidate artifact and descriptor; lifecycle, visual, performance jobs may only download and verify that artifact, not repackage. `quick` is for intermediate candidates, `full` for stage/release candidates; the final tag workflow still rebuilds from the final source SHA, prohibiting direct publication of old test artifacts.

**Pinned parent:** `desktop-v0.5.2` / `7384b863e88b005b3309e49a0aebb7a2ea91d4c3`; Mac DMG 182438617 bytes / SHA-256 `11f28a1d24d1d5039a200e26ab2f535fa27120efb9a93998e7162a8267c0b607`; Windows Setup 145768890 bytes / SHA-256 `7694568950fb4812788f28066d22bbf308f88255f82b52e7f0719e0a923b06d7`.

Test-script-only commits may rerun failed verification jobs on the same candidate descriptor; any change to `apps/**/src`, `packages/**/src`, composition, lockfile, asset, or builder invalidates the candidate and requires rebuild. Final release always rebuilds.
