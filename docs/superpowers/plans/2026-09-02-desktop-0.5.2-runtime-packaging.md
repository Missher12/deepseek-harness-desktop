# Desktop 0.5.2 Startup, Footprint, and Windows Icon Implementation Plan

English | [中文](2026-09-02-desktop-0.5.2-runtime-packaging.zh.md)

> **For implementing agents:** You must use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Track progress with the `- [ ]` checkboxes.

**Goal:** Shorten cold startup without fake readiness, reduce only proven-redundant Windows installed bytes while preserving offline operation and Profile module fallback, and make taskbar, tray, and installer icons legible at native small sizes.

**Architecture:** Establish same-machine startup and package baselines before adding non-sensitive diagnostics. Retain only changes with before/after evidence. A staged-tree inventory owns package boundaries. Windows gets dedicated small-size icon assets while Mac assets remain unchanged.

**Stack:** TypeScript, Node.js, Electron 43, electron-builder, Vitest, PowerShell, Playwright packaged smoke, and GitHub Actions.

**Baseline and owner:** The commander's full SHA is the baseline. The Windows execution task solely owns shared startup/footprint implementation and Windows-specific assets. The Mac task may adapt and retest shared commits only after the commander supplies them.
