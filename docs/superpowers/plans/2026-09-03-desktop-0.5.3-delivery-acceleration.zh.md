# Desktop 0.5.3 Delivery Acceleration Implementation Plan

[English](2026-09-03-desktop-0.5.3-delivery-acceleration.md) | 中文

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans, superpowers:test-driven-development, and superpowers:verification-before-completion.

**Goal:** 把当前串行、重复构建的双平台验证拆成“构建一次、同产物并行验收”，缩短反馈时间，同时保留最终 SHA 的完整原生发布门禁。

**Architecture:** 每个平台的 build job 生成一个不可变 candidate artifact 与 descriptor；lifecycle、visual、performance jobs 只能下载并验证该 artifact，不能重新打包。`quick` 用于中间候选，`full` 用于阶段/发布候选；最终 tag workflow 仍从最终源码 SHA 重建，禁止把旧测试产物直接发布。

**Pinned parent:** `desktop-v0.5.2` / `7384b863e88b005b3309e49a0aebb7a2ea91d4c3`；Mac DMG 182438617 bytes / SHA-256 `11f28a1d24d1d5039a200e26ab2f535fa27120efb9a93998e7162a8267c0b607`；Windows Setup 145768890 bytes / SHA-256 `7694568950fb4812788f28066d22bbf308f88255f82b52e7f0719e0a923b06d7`。

- [ ] **Step 3: 实现 create/verify CLI**


**Files:**
- Modify: `.github/workflows/windows-desktop.yml`

- Create: `docs/runbooks/desktop-candidate-validation.md`

- [ ] **Step 1: 固定 quick**

quick 只做 build、编译/关键合同、一次静默安装、真实 desktop surface、关闭及进程树 0；不跑 0.5.2 baseline、双 DPI、全视觉和完整卸载。目标墙钟 6–9 分钟，只是工程目标。

- [ ] **Step 2: 固定 full**

full 必须包含可见 NSIS 四页、快捷方式、100%/150%（UI 阶段补 200%）、完整 packaged smoke、冷/热 10 次、installed inventory、卸载/数据保留与全进程清理。性能比较固定下载并先校验本计划中的 0.5.2 bytes/SHA。

- [ ] **Step 3: 区分源码修复与测试修复**

测试脚本-only commit 可在同一 candidate descriptor 上重跑失败验证 job；任何 `apps/**/src`、`packages/**/src`、composition、lockfile、asset 或 builder 变化都使 candidate 作废并要求重建。最终 release 一律重建。

- [ ] **Step 4: GREEN 与提交**

### Task 4: Windows 原生证明

- [ ] **Step 1: 锁定唯一 quick SHA/run**

push 专属分支后只 dispatch 一次 quick；回报 source SHA、run/job、build artifact digest、各 job 开始/结束时间与结论。失败不自动 retry。

- [ ] **Step 2: 锁定同 SHA full run**

quick GREEN 后同 SHA 只 dispatch 一次 full。验证所有 jobs 的 descriptor/artifact SHA 相同，并与 build job 输出一致。

- [ ] **Step 3: 计算墙钟**

比较 0.5.2 run 33683935433 的完整串行路径与新 full 的 workflow created→completed；同时列出每 job 时长。目标完整 Windows 10–13 分钟；未达标就报告真实值，不删门禁凑数字。

- [ ] **Step 4: 回报共享 descriptor commit**

回报分支、完整 HEAD、quick/full run、Setup bytes/SHA、installed inventory、启动 median/P95、并行 jobs 和风险。不得版本 bump、push main、tag 或 Release。
