# Desktop 0.4.3 Computer Use Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (<code>- [ ]</code>) syntax for tracking.

**Goal:** Ship one-source Desktop 0.4.3 for Intel macOS and Windows x64 with the user-approved Codex-style prompt rail, structured Agent control of the built-in browser, and visible, revocable multi-application Computer Use.

**Architecture:** Keep model tools inside Harness and privileged execution inside Electron main plus an on-demand native helper. Two typed service seams, <code>browserControl</code> and <code>computerControl</code>, cross the unique parent/child Node IPC channel through a strict shared protocol; Electron owns leases and policy, while the native helper mirrors and rechecks them. Browser actions use an in-process CDP wrapper with opaque revision-bound refs; native actions prefer AX/UIA refs and use coordinates only for vision-capable models.

**Tech Stack:** TypeScript, React, CSS Modules, Cordis, Zod/Schemastery, Electron WebContentsView/CDP, Node child-process IPC, Rust, macOS AXUIElement/ScreenCaptureKit/CGEvent, Windows UI Automation/Windows Graphics Capture/SendInput, Vitest, Playwright snapshots, electron-builder, GitHub Actions.

## Final self-review checklist

- Every requirement in the approved design maps to a task above.
- No task adds rewind, message editing, arbitrary selectors, arbitrary JavaScript, shell-based GUI control, credential reads, silent control, or background screenshots.
- Browser refs, AX/UIA refs, screenshots, leases, and approvals have one authoritative owner and explicit expiry.
- Stop and cleanup are implemented and tested before native input is enabled.
- macOS and Windows ship from one commit but use real native adapters and real native acceptance.
- Versioning and GitHub access happen once at the end, after local gates.
