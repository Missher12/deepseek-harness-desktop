# Desktop 0.4.3 Computer Use Implementation Plan

English | [中文](2026-08-27-desktop-0.4.3-computer-use.zh.md)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (<code>- [ ]</code>) syntax for tracking.

**Goal:** Ship one-source Desktop 0.4.3 for Intel macOS and Windows x64 with the user-approved Codex-style prompt rail, structured Agent control of the built-in browser, and visible, revocable multi-application Computer Use.

**Architecture:** Keep model tools inside Harness and privileged execution inside Electron main plus an on-demand native helper. Two typed service seams, <code>browserControl</code> and <code>computerControl</code>, cross the unique parent/child Node IPC channel through <code>desktop-control-protocol</code>, the sole source of every cross-process action, result, and branded ID DTO. Electron owns leases, quotas, and policy, while the native helper mirrors and rechecks them. Browser actions use an in-process CDP wrapper with opaque revision-bound refs; native actions prefer AX/UIA refs and use coordinates only for vision-capable models.

**Tech Stack:** TypeScript, React, CSS Modules, Cordis, Zod/Schemastery, Electron WebContentsView/CDP, Node child-process IPC, Rust, macOS AXUIElement/ScreenCaptureKit/CGEvent, Windows UI Automation/Windows Graphics Capture/SendInput, Vitest, Playwright snapshots, electron-builder, GitHub Actions.

---

Tasks 1–2 are an independent prompt-rail slice. Tasks 3–8 deliver a complete browser-control slice. Tasks 9–13 add Computer Use in the order observe → stop/cleanup → input. Task 14 changes version and release metadata only after every earlier gate is green.
