# Desktop 0.5.3 Official Core Sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将已发布 Desktop 0.5.2 的 Harness `0.1.1-rc.2` 安全同步到官方 `0.1.2-alpha.5`，保留 Desktop 扩展及旧用户数据。

**Architecture:** 从精确 Desktop 基线创建新分支，先固定 rc.2/alpha.3 升级 fixture。由于 Desktop 产品史与官方仓库史没有 Git 共同祖先，先创建一个树不变的双父 provenance commit，只建立精确上游 tag 的可审计祖先关系；随后物化精确 alpha.5 tree，再以 rc.2 为显式语义基线叠加已审计的 Desktop overlay，并在 alpha.5 seam 上重新接入最小 Desktop 能力。同步结果只提供共享 commit，不改 Desktop 版本或发布元数据。

**Tech Stack:** Git、TypeScript、pnpm 11、Vitest、Electron、Playwright、JSONL/storage projection fixtures。

git merge-base --is-ancestor b150a551b8d465e31e418e1b2eaf5e79bbb7d28e dsh-v0.1.2-alpha.5
set +e
git merge-tree --write-tree --name-only --messages \

Expected: 第一条命令确认两条仓库史没有共同祖先；第二条确认 rc.2 是 alpha.5 的祖先。普通 unrelated-history merge-tree 约 46 MB / 1864 conflict sections，禁止作为实施路线。显式以 rc.2 为语义基线后，任务书 HEAD 的只读演算只产生 312 条 conflict message：247 content、56 modify/delete、8 file-location、1 directory-rename-split，其余 Desktop 增量自动叠加到 alpha.5。Task 2 提交后必须用完整不可变 SHA 重算，不能把符号名 `HEAD` 写进冲突 marker。仓库的 translation-pairing merge driver 还会读取当前 index；因此产品 index 上的 preflight 只用于归属审计，Task 3 必须另做 alpha.5 tree/index/runtime 隔离演算并锁定执行态路径集。只把可复核的 tree hash、相对路径、冲突类型与归属统计整理进 compatibility 文档，不提交 `/tmp` 输出、冲突 marker tree 或绝对路径。

- [ ] **Step 0: 冻结 pre-provenance overlay 并演算执行态 merged tree**

先提交并复核最终 compatibility 修订，把该 clean commit（而不是更早的 Task 2 commit）冻结为 `desktop_overlay_head`。使用隔离临时 worktree 与临时 index 同时物化 alpha.5 tracked tree，保留可运行的既有依赖，使 alpha.5 的 translation-pairing driver 可执行；再用完整 `desktop_overlay_head`、rc.2 和 alpha.5 SHA 运行下方显式-base `merge-tree`。记录 out-of-tree 的 tree hash、完整相对路径集和类型统计，预期当前已审计集合为 308 条：243 content、56 modify/delete、8 file-location、1 directory-rename-split。若 driver 报 runtime unavailable 并退化为 312 条普通文本冲突，或路径集与 manifest 不同，立即停止，不得执行 provenance merge 或 `read-tree`。

- [ ] **Step 1: 创建树不变的 provenance merge**

```bash
before=$(git rev-parse HEAD)
git merge -s ours --allow-unrelated-histories --no-ff \
  db6bdc3576c2d4e7c965e8e3ed0c2a731eed87f5 \
  -m "chore(desktop): link official Harness 0.1.2-alpha.5 provenance"
test "$(git rev-parse HEAD^1)" = "$before"
test "$(git rev-parse HEAD^2)" = "db6bdc3576c2d4e7c965e8e3ed0c2a731eed87f5"
git diff --exit-code HEAD^1 HEAD
```

Expected: merge commit 只连接两条历史，第一父保持 Desktop 产品史、第二父精确为官方 alpha.5，提交树与第一父完全相同。这里的 `-s ours` 只能用于拓扑桥，不能作为任何文件的代码选择或测试通过证据。

- [ ] **Step 2: 物化精确 alpha.5 树**

仅在 worktree tracked/untracked 均 clean 时，把 index/worktree 设为 alpha.5 的完整 tracked tree，并证明 tree id 精确相同。这一步保证上游新增和删除都不会被路径清单漏掉；产品历史已由上一步保留，后续 Desktop overlay 会恢复任务书、fixture 与扩展。

```bash
test -z "$(git status --porcelain=v1 --untracked-files=all)"
git read-tree --reset -u db6bdc3576c2d4e7c965e8e3ed0c2a731eed87f5
test "$(git write-tree)" = "$(git rev-parse db6bdc3576c2d4e7c965e8e3ed0c2a731eed87f5^{tree})"
git commit -m "chore(desktop): materialize official Harness 0.1.2-alpha.5 tree"
```

Expected: 该提交的 tree 与官方 alpha.5 完全相同；其祖先同时包含产品史和官方 tag。禁止在非 clean worktree 运行 `read-tree`，禁止用它清理或覆盖任何其他 worktree。

- [ ] **Step 3: 物化显式-base 自动合并树并逐项解决 seam**

以 Step 0 冻结的 pre-provenance Desktop overlay 与官方 rc.2 语义基线重新生成 merged tree；把该 tree 载入当前专属 worktree。`take-upstream` 保持 merged tree 的 alpha.5 内容；`retain-desktop-extension` 保持自动叠回的 Desktop 内容；`reimplement-on-alpha5-seam` 以 alpha.5 contract 为基线，通过 RED→GREEN 接回最小 Desktop 能力。rc.2 自研 PromptRail 不与官方 TurnNavigator 同时挂载。对每个 seam 在 compatibility 文档记录旧入口、新入口和验证测试。

```bash
desktop_overlay_head=<pre-provenance-exact-commit>
node --import tsx/esm scripts/merge-translation-pairing.ts --probe
set +e
git merge-tree --write-tree --name-only --messages \
  --merge-base=b150a551b8d465e31e418e1b2eaf5e79bbb7d28e \
  "$desktop_overlay_head" db6bdc3576c2d4e7c965e8e3ed0c2a731eed87f5 \
  > /tmp/desktop-053-alpha5-semantic-merge-final.txt
merge_status=$?
set -e
test "$merge_status" = 1
merged_tree=$(sed -n '1p' /tmp/desktop-053-alpha5-semantic-merge-final.txt)
test "$merged_tree" = "<Step-0-execution-tree>"
test "$(rg -c '^CONFLICT ' /tmp/desktop-053-alpha5-semantic-merge-final.txt)" = 308
git read-tree --reset -u "$merged_tree"
```

Expected: 实际演算与 Step 0 的 tree hash、308 条路径及类型逐字节一致后，自动合并内容才进入 index/worktree；conflict message 清单中的路径逐项人工核对，不得原样提交 merged tree 内的 marker。文件级选择和实现完成后，`git diff --cached --check` 必须拒绝所有遗留 conflict marker。禁止执行普通 unrelated-history merge，禁止用 empty-tree merge，禁止对 seam 批量选择 `ours` 或 `theirs`。真实 execution tree hash在最终冲突解决提交中写回 compatibility 文档；merge 输入始终保持冻结的 pre-provenance SHA，避免自引用。
