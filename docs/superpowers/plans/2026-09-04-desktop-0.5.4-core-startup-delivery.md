# Desktop 0.5.4 Core, Startup, and Delivery Implementation Plan

English | [中文](2026-09-04-desktop-0.5.4-core-startup-delivery.zh.md)

> **Required skills:** `superpowers:executing-plans`, `superpowers:test-driven-development`, and `superpowers:verification-before-completion`.

**Goal:** Sync the exact official Harness `0.1.2-rc.1`, retain Desktop extensions and user state, improve only a measured startup bottleneck, and ship/install one dual-platform `0.5.4` release from a single final SHA.

**Architecture:** Merge exact upstream commit `a66e4702047846cdaa10c66c9d3df3951f5ea70d`. The upstream alpha.5-to-rc.1 tree change is only 252 package-version lines; any additional merge delta is treated as a conflict and audited. Startup readiness never moves earlier. Existing build-once quick/full workflows remain the platform gates.

### Task 1: Sync exact official rc.1

- [ ] Verify alpha.5 is an ancestor, record the 252 one-line version-only upstream diff, and add a manifest RED requiring root/core package alignment to rc.1.
- [ ] Merge `a66e4702047846cdaa10c66c9d3df3951f5ea70d` with ancestry preserved. Reject any unexpected source, lockfile, snapshot, or generated-file delta.
- [ ] Run host/client TypeScript, profile boot, Desktop manifest, stage, BrowserSkill, memory/evolution, and upgrade-state suites.
- [ ] Commit the merge/compatibility result without changing Desktop version.

### Task 2: Measure the startup critical path

**Files:** `packages/boot/app-boot/src/index.ts`, `apps/cli/src/profile-boot.ts`, `apps/desktop/src/startup-timeline.ts`, benchmark parser/tests, and only the measured first-party bottleneck.

- [ ] Add fixed, path-free detailed phases for Loader construction, root include, first-party resolution/import, root activation, settle, and audit. Normal CLI output remains unchanged.
- [ ] Collect 10 cold and 10 warm isolated samples against the public 0.5.3 app and the current candidate on the same machine/runner.
- [ ] Write a RED test for the largest repeat or eager non-critical operation. Implement only one bounded optimization: per-start single-flight/deduplication, safe lazy work, or a content-keyed rebuildable cache.
- [ ] Retain the optimization only if one median improves at least 15%, the other median regresses at most 5%, both P95 regress at most 10%, and all lifecycle/readiness/data-preservation tests pass. Otherwise revert the product shortcut and retain diagnostics only.

### Task 3: Freeze one final release SHA

- [ ] Update Desktop version and release metadata to 0.5.4/core rc.1 only after shared code and tests are green. Update bilingual README/release context and exact checksums only from produced artifacts.
- [ ] Merge platform smoke adaptations without rewriting shared files. Run local gates and require a clean tree.
- [ ] Push one integration SHA and send that exact full SHA to both platform tasks. Any source change invalidates every older run/artifact.

### Task 4: Native Mac and Windows acceptance

- [ ] Mac Intel full: DMG build/mount, x86_64, titlebar exclusion, 100%/150% UI, left rail, Workbench/plugins, cold/warm 10x, launch/close/Dock/Quit/process tree, legacy/user-data preservation.
- [ ] Windows x64 full: Setup/NSIS, shortcuts/icons, 100%/150% UI, left rail, Workbench/plugins, cold/warm 10x, install/launch/close/tray/uninstall/process tree, legacy/user-data preservation.
- [ ] Both tasks report artifact basename, bytes, SHA-256, benchmark median/P95, run/job ids, and bounded visual evidence. Neither task tags or releases.

### Task 5: Publish and install

- [ ] Only after both platforms pass on the same SHA: merge to main, push, create `desktop-v0.5.4`, run the release workflow, and verify public assets by anonymous re-download and SHA-256.
- [ ] Install the verified Intel DMG on this Mac, launch normally, and check titlebar, left rail, Workbench, `@/+`, BrowserSkill, and the Open Design companion status against the user's real profile without changing its data.
- [ ] Report what improved and what did not. Never call startup faster unless the final same-runner numbers pass the gate.
