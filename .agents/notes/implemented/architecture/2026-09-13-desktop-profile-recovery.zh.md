# Agent Note: 原生 Desktop profile 恢复

Status: implemented

[English](2026-09-13-desktop-profile-recovery.md) | 中文

## 问题

Bundle 加载失败可能导致 Web 插件图及其中的恢复控件不可用。恢复需要保留规范配置、插件源码与数据，并区分兼容性故障和用户手动停用。

## 决策

Desktop 保留规范 `web` 作为安装与配置来源。在启动未修改的官方 CLI 前，[组合器](../../../../apps/desktop/src/compatibility/profile-composition.ts)排除已暂停和用户停用的 Bundle，发布自有 `desktop-base` profile。它保留 Bundle 顺序、原补丁身份及规范配置的加载偏好。有效 profile 使用 `startup` 加载策略，配置更改需要重启。组合器通过官方 overlay 加载器将插入模块名锚定到原文件，并用官方 include schema 序列化。显式规范 Bundle 依赖仍是必需项。不支持的动态、include、preset 或已排除模块引用会进入原生恢复状态，不会静默改变其含义。

[状态存储](../../../../apps/desktop/src/compatibility/plugin-state.ts)原子地区分用户启用选择与观察到的兼容情况，保留源码／数据指针，并要求使用当前修订进行修改。可配置的确认次数仅接受可归因的 Bundle 故障类别；无关 provider 和核心故障不计入。当前运行时编排仅在清单发现成功后归因解析出的 Bundle YAML 故障；新的不可读清单仍属于配置恢复情况，因为无法验证其依赖身份。恢复会发现当前安装包身份，在正常 Host 停止后验证候选 Host，再消费进程内不透明回执。验证失败会保留暂停状态和手动选择。

独立原生恢复窗口无需挂载 Web 插件图即可展示安全身份、选择及系统更新。IPC 只接受身份、修订和封闭动作；路径、原始配置、回调及验证回执留在原生层。修改需要原生重启确认。[应用生命周期](../../../../apps/desktop/src/application.ts)将停止后的操作与重试、退出串行化，关闭时等待已接受的修改，并防止退出后继续启动。[进程归属检查](../../../../apps/desktop/src/harness/ownership.ts)同时识别历史 `dsh web` 和当前 profile CLI。进程观察不是阻止后续不合作 CLI 写入者的锁，不能单独授权归档存储维护。

## 考虑过的替代方案

为移除故障 Bundle 而修改规范 web 会改变 CLI 安装来源。删除插件源码或数据会阻止显式恢复。仅放在 Web 插件图中的恢复控件会在该图加载失败时不可用。

## 影响

规范配置、插件代码、插件数据和已提交的 Session 代际不会删除或覆盖。非本应用拥有的有效目录、损坏的全局输入、过期状态修订或未验证恢复会产生恢复状态而非成功。受管状态沿用 atomic-write 工具的 rename 语义；不新增 fsync 崩溃持久性，也不防御同一用户恶意进程实时替换祖先目录。持久策略冲突会明确失败。

## 验证

定向测试覆盖真实文件状态持久化、跨进程并发修订、失败归因、恢复竞争、停止后的生命周期排序、准备阶段退出、安全 IPC 投影，以及插件发现失败时仍可使用更新。组合器测试通过固定官方 API 验证原路径 YAML、解析前排除、必需依赖及规范文件字节保留。原生装配后的聊天、旧 Session 接续、插件停用／恢复、候选 Host 就绪及各平台安装生命周期仍是独立的必需验收证据。
