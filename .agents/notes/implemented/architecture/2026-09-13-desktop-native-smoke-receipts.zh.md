# Agent Note: Desktop 原生 smoke 证据

Status: implemented

[English](2026-09-13-desktop-native-smoke-receipts.md) | 中文

## 问题

基础聊天证据不能证明插件恢复。安装包身份、历史兼容性与自有资源清理需要分别观测。

## 决策

[基础 smoke 驱动](../../../../apps/desktop/tests/packaged-base-smoke.ts)记录实际启动的安装包、官方运行时清单、真实旧数据与自有进程清理结果。[验证器](../../../../scripts/verify-desktop-base-smoke.ts)拒绝将开发 stage 或未完成后续检查的回执当作正式安装包验收。证据始终绑定受测字节；后续源码或安装包变化需要匹配的验收。

## 平台基线

[共享描述符](../../../../scripts/desktop-base-contract.ts)将 Mac 和 Windows 固定到已发布的 Desktop 0.5.5，将不存在 0.5.5 资产的 Linux 固定到已发布的 0.5.7。旧数据夹具必须由旧生产应用通过公共 API 生成并重新打开。合成插件探针明确标为替代件，不能证明独立插件算法兼容。已有已提交的 Session 代际保持逐字节检查。

直接 AppImage 验收在挂载期间记录外部镜像、原生可执行文件、内核挂载及完整的必需运行文件。由于退出会使运行时挂载消失，驱动在退出前将这些文件复制到私有证据目录。后续验证同时检查外部镜像与副本；副本不会被启动来代替直接 AppImage 运行。无法绑定到精确镜像的挂载来源会被拒绝，等待原生证据。

[Linux 核心续验](../../../../apps/desktop/tests/linux-core-native.ts)在已安装应用中重开历史 Session，核对官方侧栏中的会话身份、选中状态与原始消息正文。直接 AppImage 续验将新挂载与已记录的必需文件字节核对。它复核每个声明的受保护文件，将自身进程和端口纳入核心清理证据，再进行验证与卸载。此范围中的插件恢复保持未执行。

## 考虑过的替代方案

仅检查版本不能证明已安装字节的身份。将基础聊天当作恢复证据会遗漏恢复序列。启动复制或解压后的 UI 文件不能证明直接 AppImage 启动。因此，验证器要求对应的安装包与原生观测。

## 影响

默认的完整范围要求另行完成 Bundle 失败、暂停、CLI 变更和验证恢复序列。正式恢复记录必须包含真实的原生确认点击。拦截对话框仍属开发证据。原生旧会话重开以及全部自有进程与端口关闭分别检查；标记文件或单元测试结果不能替代这些观测。

进程发现失败时，即使根进程已经退出，原生静止状态仍属未知。恢复设置与规范 profile 前，完整观测到的进程树必须停止；空 PID 清单不能授权恢复。文件选择自动化在错误或超时后等待真实子进程关闭。缩放验证将固定的 100% 或 150% 参数直接传给同一可执行文件，并记录原生缩放、参数与渲染器 DPR。

AppImage 恢复将每次新的 UI 挂载重新绑定到原外部安装包及必需字节清单。另一个明确归属的只读挂载在 UI 启动之间提供公共 CLI。其真实 Linux 进程身份与挂载命名空间需要通过检查；释放该挂载并完成最终清理后，才能输出恢复通过回执。证据副本不会被执行。

在补全和验证 API 中显式传入 `scope: "core"`，或在验证 CLI 中使用 `--scope core`，仍要求原生旧历史重开、聊天、重启、清理和数据保留，仅允许 `pauseRecovery: not-run`。结果标记为 `core-passed`，CLI 在 `unverifiedChecks` 中列出恢复；它不证明插件恢复已通过。恢复尝试标记或场景文件会阻止排除该阶段。已执行的恢复检查仍须具备完整证据并确认实际进程和端口清理，失败或未知检查仍然失败。

共享启动等待使用受控夹具明确的欢迎声明与凭据预期。预期声明仍在加载时，已经绘制的输入框不能使等待提前完成。官方欢迎步骤先于 DeepSeek 凭据引导；还原后的无密钥夹具通过正常的“继续”和“稍后配置”按钮操作，并验证视口命中与对话框移除。未知对话框仍会阻塞，处于 inert 状态或被遮罩的输入框不能通过试探交互。点击走公开 UI，smoke 驱动不直接写入确认键或凭据。源码顺序和单元时序检查不能证明条件性的凭据对话框已在原生运行中出现。
