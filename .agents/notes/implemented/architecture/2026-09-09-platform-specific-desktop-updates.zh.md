# Agent Note: 按平台区分的 Desktop 更新

Status: implemented

[English](2026-09-09-platform-specific-desktop-updates.md) | 中文

## 问题

同一个 Release 可以包含多种原生安装包，官方也可能发布更新的 Harness 核心，但这并不改变当前安装的应用。把这些安装包当作可互换产物，或把辅助进程交接成功称作安装完成，会给用户错误的版本或安装保证。接受渲染端提供的路径或命令，还会把更新桥接变成高权限启动器。

## 决策

原生[发布校验器](../../../../apps/desktop/src/update/release.ts)只选择一个准确的平台、架构和安装格式。macOS 保留 schema-1 manifest（元数据清单）名称；Windows Setup、Linux `.deb` 和 Linux AppImage 各自使用独立的 schema-2 manifest 名称与准确的 tag URL。manifest 生成器拒绝间接引用的输入文件和跨平台输出名称冲突。官方最新核心元数据只作提示；正在运行的 Desktop 版本与内置 Harness 版本始终是两项独立事实。

主进程只向可信主 frame 提供六项固定、无参数的更新操作。扁平快照只包含展示数据，不包含本地路径或执行权限。[下载服务](../../../../apps/desktop/src/update/service.ts)统计实际流入字节，核对大小、SHA-256、物理文件身份和原生格式，并保留已验证安装包。取消只清理自身拥有的未完成暂存目录。再次检查更新不会丢弃已验证安装包；安装事务覆盖确认、验证和辅助进程准备期间，防止并发检查改变所选状态。

[安装分派器](../../../../apps/desktop/src/update/install.ts)保留现有的受保护 macOS 辅助进程。Windows 先确认保存工作并关闭应用，再准备固定系统 PowerShell 辅助进程，收到其就绪确认后才请求退出应用。辅助进程持有准确的父进程，等待其退出，再次核对物理 Setup 后打开可见向导，不传静默参数。Linux 只展示已验证的上级目录；它不会执行、提权、chmod、修改 AppArmor 或退出应用。类型化结果区分交接、手动安装包就绪、可观察的交接前取消与失败；任何一项都不代表安装完成。

[设置插件](../../../../packages/client/ui-settings-system-update/README.zh.md)展示平台专属操作和真实字节进度。首次状态读取失败时可仅重试状态读取；陈旧响应和已释放的订阅不能覆盖较新状态。macOS 文案不承诺额外的原生确认，只有 Windows 会要求确认。

Windows 辅助进程使用附着的短生命周期引导进程和原生 `Start-Process` 工作进程。引导进程保留工作进程句柄、创建时间和系统可执行文件身份，验证有界的物理 nonce 回执，并且只输出一条准确的就绪行。批准记录完整写入后才发布到私有最终文件名；取消经过串行处理、不可撤销，并在等待已持有的父进程句柄期间持续检查。应用验证完整标准输出及引导进程正常退出后才接受就绪。准备失败会取消交接，并通过准确句柄和身份停止已知工作进程；应用和已验证安装包保持可用。

## 考虑过的替代方案

**所有平台共用一个 manifest 和安装操作。** DMG 替换、可见 NSIS 向导和手动安装 Linux 包具有不同的所有权与完成语义，因此拒绝此方案。原生选择不会猜测格式，也不会在生成时覆盖 Mac manifest。

**由渲染端指定路径或 shell 命令。** 准确的 Release 资产与已验证暂存目录由已安装应用拥有，而不是由网页拥有，因此拒绝此方案。范围狭窄的无参数桥接防止不可信数据参与可执行目标选择。

**直接分离的 PowerShell 或由管道持有的控制台宿主。** 原生探测表明，分离的 PowerShell 可能不执行脚本就退出，而附着的引导进程能够执行。长期附着的子进程依赖创建者的 libuv job 生命周期；由管道持有的控制台宿主也会把关闭与输入管道关联。原生工作进程避开这些依赖，但必须验证由安装版主进程创建、且创建者退出后的行为，不能只由测试驱动启动。

**Windows 静默替换与 Linux 自动更改权限。** 用户需要可见的 Setup 进度，并需要明确掌控 Linux 包管理和准确路径的沙箱策略，因此拒绝此方案。Windows 只报告交接，Linux 保持手动安装。

**下次检查或退出时删除已验证安装包。** 原生辅助进程或重复查看 Linux 安装包仍然需要这些字节，因此拒绝此方案。自动删除仅限自身拥有的未完成下载；保留期限策略不在本实现范围内。

## 结果与影响

没有此桥接的已安装 Windows 版本需要先手动运行 Setup。验证失败会保持应用打开并移除安装权限，但不会删除已保留文件。Windows 交接前取消会保持当前应用打开；外部向导内的取消或失败不能作为可观察的安装结果。辅助进程确认就绪不等于升级完成。

## 测试

平台矩阵测试使用具有原生格式的惰性安装包，覆盖错误大小／哈希／格式、取消、文件保留及较早异步响应。受控 Promise 测试在并发检查运行时，分别暂停 Windows 确认、再次验证和交接。界面测试覆盖所有平台操作、首次状态重试、陈旧／已释放后的拒绝与本地化文案。仅 Windows 执行的辅助进程测试会解析真实 PowerShell，并通过自身拥有的临时父进程核对就绪与错误哈希拒绝；测试在惰性安装包可能被执行之前停止辅助进程。

这些测试不能证明真实 Setup 升级。原生验收还必须覆盖最终同一 SHA 的安装版应用、真实设置桥接、进程退出后的可见 Setup 交接、安装生命周期和用户数据保留。平台无关的测试通过或辅助进程确认就绪，都不能替代这些证据。

交接驱动在安装版 Electron 主进程内部创建生产引导进程，核对观测到的主进程、引导进程、工作进程身份链，关闭创建者，再核对工作进程到 Setup 的身份、可见欢迎页与受控取消。观察进程保持附着于仍在运行的测试驱动。该路径必须在原生 Windows 执行；本地信号、取消及解析器源码检查不能证明工作进程存活或向导可见。
