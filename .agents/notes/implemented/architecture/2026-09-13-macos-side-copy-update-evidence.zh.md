# Agent Note: Mac 侧副本证据区分适配器完成与原生验收

Status: implemented

[English](2026-09-13-macos-side-copy-update-evidence.md) | 中文

## 问题

更新器可能启动 helper，却没有完成应用替换或使用目标运行目录重启。旧 profile 也可能继续从保留的应用备份解析包，因此窗口启动成功不能证明迁移后的独立运行。复用日常安装或私有 Session 内容的测试无法安全覆盖这些失败。

## 决定

[Mac 驱动](../../../../apps/desktop/tests/macos-side-copy-update.ts)拥有私有可丢弃产物副本和显式合成 profile 输入。原生更新、ready 验证和静止退出均作为测试依赖注入，不定义另一套产品 helper 或 ready 协议。本地结果始终包含 `nativeAcceptance: false`，包括全部回调完成的情况。

驱动绑定源产物哈希与最终源码 SHA，复制时保留相对包链接，拒绝绝对或越界链接。保护数据检查保留每个原路径和字节，只允许预先精确声明的新代新增路径。清理、ready、源完整性和数据保留失败分别记录。证据目录保留供检查，不因成功路径而删除。

[原生输入消费者](../../../../apps/desktop/tests/macos-side-copy-native-adapter.ts)使用共享基础 descriptor 验证器，检查可信摘要与候选 ASAR，将抽象资源路径映射到 Contents/Resources，并拒绝被重定向到外部的必需文件。明确要求原生执行时，缺失输入会失败，不会变成跳过验收。独立历史性能工具继续限定原版本对照，不约束当前产品 manifest。

打包 Mac 消费者执行共享基础生命周期以及独立的旧历史 UI、原生目录选择续验。它显式使用核心记录范围，将暂停恢复保留为未验收；100% 和 150% 使用同一实际可执行文件与各自独立的历史夹具，UI 失败时等待所属进程退出。干净的最终源码版本及实际原生运行仍是验收前提，离线消费者测试不证明原生成功。

Mac 目录选择分别核验观察到的命令名与可执行映像。只允许根进程下新增且唯一、命令严格匹配的候选；其 PID 专属 lsof 记录必须包含系统 osascript 映像，才能开始 UI 自动化。多候选、映像不符或检查失败均保持失败，原生确认按钮在已有标签之外支持实测中文标签。

人工目录选择是显式且有等待上限的消费者模式。应用仍打开自身经过核验的原生选择器，只有在 picker 退出后出现新的官方工作区记录，且规范化完整路径精确匹配要求目录，才能接受人工操作结果。输出提示文件和用户口头确认不能完成检查。最终 Mac 证据保留交互模式并复核持久化工作区路径；取消、超时及续验错误均保留退出与历史数据验证。

## 考虑过的替代方案

**更新日常安装。** 这会将测试失败与用户数据和运行任务耦合。驱动改为接收显式产物输入，并操作新建的私有副本。

**将 helper 启动等同于更新成功。** 启动完成不能证明重启应用的版本、路径或 Host 就绪，这些检查属于 foundation 适配器和独立原生证据。

**要求迁移后整个目录完全相同。** 有效的新日志代际会新增文件。显式允许的新增条目既保留旧字节，也不会把任意新路径或覆盖旧代视为无害。

## 影响

[离线测试](../../../../apps/desktop/tests/macos-side-copy-update.spec.ts)无需启动 Electron 即可检查复制、路径拒绝、数据保留和失败采集。其合成包与 Session 字节不能证明插件激活、格式迁移或原生安装。完整原生验收仍依赖 foundation 协议、已核验包来源、隔离重启和实际生命周期观察。

Fixture 明确不伪造 lockfile、生成的 Cordis 图、fallback cache 格式或 Evolution 算法状态；原生验收所需的有效运行 fixture 由其所有者提供。独立的[驱动参考](../../../../apps/desktop/tests/macos-side-copy-update.md)说明输入与证据范围。
