# Agent Note: 分别收录转换前的配置输入

Status: implemented

[English](2026-09-22-config-transform-input-catalog.md) | 中文

## 问题

运行时配置转换可以接收旧字段名，再返回不同的字段名。将输入 schema 与插件归一化后的配置比较，会错误拒绝合法别名，并使生成的参考文档遗漏这些输入。

## 决策

[配置目录生成器](../../../../scripts/gen-config-catalog.ts)要求根级 `z.transform` 回调显式声明输入参数类型。生成器同时粘贴输入和归一化后的声明，并根据输入类型检查 schema 路径。schema 别名通过已初始化的本地常量解析；无法解析、可变、循环或不透明的声明均会失败。组合含转换的 schema 时，外层也必须使用声明了输入类型的转换，以明确完整输入。

## 考虑过的替代方案

**将输入键与归一化输出比较。** 被重命名的字段属于合法输入，但按设计不会出现在输出中。

**跳过含转换的 schema。** 这会隐藏合法输入字段，并丢失现有的缺失字段检查。

## 影响

转换的作者需要提供一个显式输入类型。运行时解析行为保持不变，目录记录合法别名，但不会将它们加入归一化配置。生成器测试覆盖合法转换和 schema 别名、缺失的嵌套输入成员、不支持的声明、循环引用以及组合转换。
