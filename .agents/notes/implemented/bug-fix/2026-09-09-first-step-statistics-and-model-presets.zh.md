# Agent Note：首步统计与本地模型预设

Status: implemented

[English](2026-09-09-first-step-statistics-and-model-presets.md) | 中文

## 问题

统计展示把耗时限制在已有完成步骤之后。助手响应可能已经提供 LLM 耗时与首 token 时间，而工具步骤仍未结束，因此第一条响应看起来没有统计数据。模型列表也经常只提供 ID，即使已安装目录知道模型参数，用户仍需手工配置上下文。

## 决策

每个统计指标从第一步开始保留位置，未知值显示本地化占位文字。耗时与计费独立于已完成步骤数展示。持久投影的语义保持不变，其他会话的数值不会填入加载中的空位。

现有模型发现操作接受精确的本地模型 ID。pi-ai 适配器通过 ID 索引查询，不读取凭据或访问网络。已配置路由或精确端点选择其目录限制；否则在兼容协议内匹配相同 ID，采用已知容量最小值，仅在声明一致时返回推理与协议设置。未知 ID 不返回候选，端点元数据优先于目录默认值。

模型编辑器在 ID 字段失焦时补全缺失参数。自动字段保留本地来源记录，便于更改 ID 时清除；显式修改继续保留。只有组件仍挂载、同一行未修改且提供方目标未变化时才接受结果。现有应用操作仍是保存边界。profile 或会话指定的推理强度优先，否则推理模型默认使用自身最高支持等级，包括 DeepSeek Max。

## 考虑过的替代方案

**复用旧统计或虚构零用量。** 这两种方法在加载或计费失败时都会给出错误信息。带名称的占位保留有用结构，不填写没有依据的数值。

**根据模型名称前缀推断全部能力。** 相同 ID 在不同提供方可能具有不同 token 限制和推理协议。精确匹配与保守默认值保留手动控制，也不声称进行过在线能力探测。

## 影响

此改动不会在启动或查询预设期间发起模型请求。目录索引按需构造，避免大型列表的每一行都扫描完整目录。预设代表已安装目录的知识，而非经过验证的网关限额，用户可以调整。较高的默认推理强度可能比较低档增加响应时间和 token 用量，已有显式选择保持不变。

## 测试

组件测试覆盖步骤结束前的首响应耗时、持久占位、会话切换、延迟结果、手动覆盖、ID 更改与不携带凭据的本地预设查询。适配器测试覆盖精确路由与端点、协议不匹配、未知 ID、网关元数据冲突、配置分离、最高支持等级默认值以及显式较低档与关闭选择。测试使用本地夹具和 HTTP 模拟端点，不证明原生启动提速或在线提供方兼容性。
