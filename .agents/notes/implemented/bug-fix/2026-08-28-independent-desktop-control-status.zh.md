# Agent Note: 独立的 Desktop 控制状态

Status: implemented

[English](2026-08-28-independent-desktop-control-status.md) | 中文

## 问题

Desktop 设置投影曾为浏览器控制与电脑控制共用一个 `supported` 布尔值。该值来自原生电脑状态，因此 Helper 缺失或一次 status/list 读取失败时，即使浏览器控制已安装，整个模块也会显示不可用。同一投影还把关闭策略当成能力缺失；任一读取失败时会同时丢弃状态和应用列表。

## 决策

Renderer 快照包含独立的 `browser` 与 `computer` 能力记录。每条记录分别拥有封闭的 `available | unavailable | unknown` 可用状态和持久化 `enabled` 布尔值。能力受支持但关闭时显示为**可用 · 未开启**。

Electron main 从浏览器 Adapter 推导浏览器可用性，从电脑 Adapter 与最近一次有效原生状态推导电脑可用性。原生状态与应用枚举分别完成。Main 进程 UI Authority 只在内存中保留冻结、无路径且最近有效的状态与应用投影；后续读取失败时保留这些值，只用长度受限的通用消息标记对应刷新分支。首次状态读取失败为未知，而不是不可用。Provider 不存在或明确返回不支持时仍为不可用。

Preload 与 Client Validator 只接受精确嵌套快照、普通数据属性、原始 roster 值和长度受限消息。它们拒绝旧的汇总结构、自定义原型、Accessor、可强制转换值和携带授权能力的扩展字段。紧凑设置模块展示能力、macOS 权限、授权应用、紧急停止和当前控制，但不会把任何授权判断移入 Renderer。

## 考虑过的替代方案

**保留汇总布尔值，只修改显示文案。** 不同文案仍会合并两项独立能力，并让开关依赖无关的原生状态，因此改正了数据约定。

**从原生电脑状态推导浏览器可用性。** 浏览器 Adapter 不需要原生 Helper；把两者耦合会保留原来的错误不可用问题。

**任一刷新失败时清除全部展示状态。** 这样实现简单，但会把临时列表或状态失败误报为能力消失。只保留最近一次通过校验的无路径投影，可以在不保留页面、窗口或 Accessibility 内容的前提下维持真实展示。

## 后果

设置 UI 可以准确呈现部分可用和降级状态，默认关闭策略不再看起来像功能缺失。快照约定变大，main 也会保留一份很小的内存投影，但 Preload 边界不会传递授权标识或捕获内容。刷新失败后必须由用户明确重试；UI 不会静默循环，也不会扩大权限。
