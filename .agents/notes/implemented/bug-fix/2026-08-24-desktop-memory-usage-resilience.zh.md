# Agent Note：全新安装记忆与有界用量刷新

Status: implemented

[English](2026-08-24-desktop-memory-usage-resilience.md) | 中文

## 问题

Desktop 已内置项目记忆，却把可选旧 `vectors.db` 状态当作主记忆索引展示。因此，全新安装会显示记忆未配置，尽管插件自有的审核式记忆已经就绪。“使用统计”在某个持久化 Session 检查始终不结束时，还会永久保留同一个共享刷新 Promise，使首次加载占位图永不退出。

## 决策

- “项目记忆”会独立显示插件自有记忆已就绪，并把旧索引明确标成可选只读来源。缺失 `vectors.db` 时绝不创建文件，也不禁用显式项目绑定、捕获、审核或召回。
- 每次 Usage Insights Host 刷新拥有一个 12 秒的 `AbortController` 截止时间。信号会传入 Session 列表与检查；卡住的记录转为省略部分数据，已完成记录保留修订缓存，共享进行中 Promise 始终清理。
- 渲染端在刷新期间继续显示已缓存汇总。没有缓存时，15 秒后仍未结束的请求会转为通用可重试错误；私有 Host 错误与 Session 内容不会进入界面。

## 考虑过的替代方案

**把可选旧数据库当作就绪状态。** 未采用，因为即使没有 `vectors.db`，插件自有的审核记忆也可以正常工作；把两种状态混成一种会让全新安装看起来像是损坏。

**无限等待完整使用数据。** 未采用，因为一个损坏或卡住的 Session 会永久占住共享刷新和渲染端占位图，无法返回诚实的部分快照。

**持久化活动 Session 的最新折叠行。** 未采用，因为实时检查可能看到领先于持久化修订的事件；重启后以旧修订复用该行可能造成重复计数。因此优化只保留在进程内，并绑定事件 generation。

## 安全与归属

本改动不创建、复制、迁移或写入 `vectors.db`。记忆状态仍只会因显式项目修改而创建，“使用统计”仍只持久化有界计数与标识符。取消只改变读取生命期，不改变任一存储的权限或内容。

## 验证

单元测试复现全新客户端缺失旧索引、Session 检查等待取消、超时后刷新重试，以及永不结束的首次渲染加载。Desktop 成品 smoke 同时要求“内置项目记忆已就绪”与“可选旧来源未连接”，并证明仅打开设置不会创建记忆状态数据库。

## 后果

全新安装会如实显示内置记忆已就绪，并把旧来源发现保持为显式只读操作。使用统计获得有界刷新，重复打开未变化的活动 Session 时不再反复折叠同一份长日志。代价是超时刷新可能只返回部分数据，而且 Host 重启后会有意失去进程内加速。
