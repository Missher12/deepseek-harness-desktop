# Agent Note: 在独占创建被拒后证明 Windows 写入锁竞争

Status: implemented

[English](2026-09-22-windows-lock-probe.md) | 中文

## 问题

Windows Desktop Setup 门禁在模块回退写入锁测试中失败：独占 `wx` 创建返回 `EPERM`。现有探测只接受 `lstat` 返回 `EPERM` 后再查询父目录是否包含精确锁条目；Windows 在元数据探测被阻塞时还可能返回其他临时共享拒绝码。失败日志没有保留第二次探测的错误码，因此确切的 runner 错误方言仍未确认。

## 决策

`withFileLock` 只在 Windows 上把锁路径元数据探测返回的 `EACCES`、`EBUSY` 或 `EPERM` 视为临时情况，并且必须由父目录列表证明精确的 `<filename>.lock` 条目存在。条目不存在、父目录不可读以及所有 POSIX 路径都保留原始独占创建错误。定向测试在已有与缺失锁条目的 `EPERM` 用例之外，覆盖新增的探测错误码。

## 考虑过的替代方案

**不经证明就重试全部 Windows `EPERM`。** 拒绝，因为无关的权限故障可能被转换成锁竞争，从而掩盖原因。

**把所有元数据错误都视为竞争。** 拒绝，因为只有记录的 Windows 临时拒绝码符合条件，而且仍必须观察到精确目录条目。

**跳过 Windows 锁测试。** 拒绝，因为该测试是防止模块回退在共享写入锁释放前发布内容的行为约定。

## 影响

Windows 在元数据探测临时被拒时可以继续等待合作式锁竞争，而永久权限故障仍以原始错误暴露。POSIX 行为与陈旧锁处理不变。下一次 Windows CI 必须观察 runner 失败是否消除；即使通过，也只能验证修复，不能事后确定此前未记录的探测错误码。
