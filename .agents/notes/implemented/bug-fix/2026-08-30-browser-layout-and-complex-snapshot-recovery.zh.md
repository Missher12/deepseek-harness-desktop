# Agent Note: 浏览器布局与复杂快照恢复

Status: implemented

[English](2026-08-30-browser-layout-and-complex-snapshot-recovery.md) | 中文

## 问题

Desktop 实用工作台最大只有 960px，并会在布局受压时变成覆盖层。它可能盖住会话、遮挡输入框，或在左侧导航仍占大列时漂到中间空白区域。很长的状态行与 prompt rail 提示也可能画进 sticky 输入框。

Browser Control 把大型无障碍树当成全成或全败结果。复杂网站会耗尽 2,000 节点或 300 引用预算并返回 `QUOTA_EXCEEDED`，导致模型反复请求完全相同的快照、扩大请求上下文，却拿不到可用 ref。Debugger 冷启动只有十秒；条件等待可能在页面已经可用时仍报超时；用户也看不到 Agent 准备操作的指针目标。Windows 辅助安装器虽然展开了详情窗口，但 electron-builder 关闭详情输出后没有重新开启，因此进度列表看起来是空白的。

## 决策

实用工作台保持真正的第四个网格列。默认宽度为 720px，最大可到 1,600px；它先自行收缩，再临时把渲染中的左侧导航缩到 56px 控制栏，但不会改变用户已保存的宽度。Workbench 偏好与实时布局共用这套宽度约定，原生页面也会从分隔条向内留出间距，不能再盖住拖拽热区。真正狭窄的视口会在剩余网格中聚焦工作台，绝不覆盖会话。输入框高度约束 prompt rail，状态行改成有界的两行普通流布局。Browser 模式拥有唯一有效的原生页面矩形。Agent 表层挂载前，Electron main 会请求当前会话打开 Browser 模式，等待其发布正数尺寸的宿主矩形，并在该矩形存在前保持 `WebContentsView` 未附加且不可见。Main 绝不会补用相对窗口或全高的矩形；关闭 Browser 实用工作台会清除锚点并隐藏已挂载资源，窗口缩放与分隔条更新则会重排精确的活动 mount。

浏览器遍历最多接受 10,000 个原始节点和 800 个可操作 ref，同时保留现有 64KiB 编码结果边界。达到原始节点、CDP 调用、可操作项、语义文本或编码结果限制时，会返回确定性的部分快照。候选排序会在大量链接噪声前保留聚焦、可编辑和按钮类控件。模型 prompt 会把部分结果视为可用，并禁止对未变化页面循环请求 snapshot。Debugger 冷启动改为有界的二十秒、两次尝试。Loading 与 navigation wait 到十秒边界时返回当前 revision。Click 与 scroll 会显示由 main 持有的蓝色 CDP Overlay 标记，不注入页面代码或 selector。

NSIS 自定义安装钩子会先显式恢复 `SetDetailsPrint both`，再输出五个不含隐私的完成阶段。

## 考虑过的替代方案

**把协议 JSON frame 与语义文本提高到 256KiB。** 这会扩大每套 codec 与原生一致性约定，并增加模型／上下文成本。优先级部分快照可以保留现有 wire 边界，同时解决目标发现失败。

**继续把右侧表层当作 drawer。** Drawer 看起来可以很大，但仍会覆盖输入框并破坏原生浏览器 bounds。网格让步链可以保留独立调宽与精确 `WebContentsView` 几何。

**浏览器失败后回退 shell 或远程调试端口。** 这会绕过 BrowserControl 所有权，并重复用户报告的行为，因此恢复路径仍只允许官方 Stop 加一次有界重试。

## 后果

复杂页面可以在不发送无界页面 dump 的情况下提供当前可用 ref，未变化的快照失败也不会再鼓励重试风暴。部分快照可能省略低优先级的屏外内容，因此 Agent 可能需要先滚动或导航，再请求下一张快照。可视标记属于临时 debugger overlay 状态，会随自有 debugger 一起消失。

工作台可以占用桌面窗口的大部分宽度，同时保留导航宽度偏好。Agent 浏览器 acquire 会自动打开 Browser 实用工作台，页面只会出现在工具栏与状态行下方。非常窄的窗口会暂时隐藏会话，直到空间恢复，而不是让另一个面板覆盖会话。Windows 用户会看到有界的安装完成阶段；解压内部细节仍由 electron-builder 控制。
