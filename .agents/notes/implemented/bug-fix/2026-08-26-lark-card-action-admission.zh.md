# Agent Note: Lark 卡片操作准入与未绑定消息

Status: implemented

[English](2026-08-26-lark-card-action-admission.md) | 中文

## 问题

飞书回传卡片按钮时，JSON 对象成员的顺序可能与插件发送时不同。Lark 身份校验比较序列化后的对象，因此即使每个键和值都匹配，精确的 Session 选择操作仍可能失败。活动 Session 绑定存在前发送普通文字，还会让预期的 inbox 错误穿透 WebSocket 回调，使所有者得不到可操作的提示。

## 决策

- 卡片操作数据按照精确的字符串键值集合比较，不依赖对象成员顺序。所有者、私聊、nonce、操作、generation、到期时间和单次使用校验仍为必需项。
- 持久 inbox 在串行准入操作中返回 `accepted`、`duplicate` 或 `unbound`。命令路由器只在 `unbound` 时回复当前绑定状态；已接受和重复事件保持既有投递行为。

## 考虑过的替代方案

**移除操作数据比较。** 未采用，因为有效 nonce 不能授权被篡改的 workspace、Session、审批或 RPC 标识符。

**排序后序列化两个对象。** 未采用，因为准入 payload 是有界的扁平字符串记录；直接比较键和值即可表达精确规则，无需增加规范化序列化器。

**在进入队列前由命令路由器检查绑定状态。** 未采用，因为绑定可能在检查与 inbox 的串行预写操作之间变化。inbox 仍是权威准入点。

## 验证

身份测试覆盖顺序不同但内容精确的数据、被修改的值、nonce 所有权、generation、到期时间和单次使用行为。命令与 inbox 测试覆盖无持久写入或 Agent 投递的非活动绑定，并要求向所有者回复状态。

## 后果

有效的项目与 Session 卡片点击可以容忍 JSON 成员重新排序，同时继续拒绝缺失、多余或被修改的操作数据。绑定前的预期文字不再造成飞书回调失败。私有 inbox 接口携带三态结果，使面向所有者的路由器能够区分非活动绑定、已接受投递与重复投递。
