# Agent Note：Desktop alpha 集成与正文宽度自适应

Status: implemented

[English](2026-09-07-desktop-local-alpha-integration.md) | 中文

## 问题

Desktop 扩展依赖的 Session 持久化与附件 API 在 Harness 0.1.3-alpha.1 中发生变化。升级必须保留文档提取、历史脱敏、归档删除和准确的使用计量。持久化的旧子 Agent descriptor v2 记录也需要能够迁移为历史，同时不能获得未经支持的继续执行语义。右侧工作台移除后，正文拖动调宽仍是独立的交互。

## 决策

Desktop 集成指定标签的 alpha 内核，同时把消费方适配到显式读写句柄。只读消费方始终关闭句柄。Session 删除获取写入所有权并一并删除所有代际，避免保留的前代让已删除会话重新出现。已发布格式校验器只接纳已知 descriptor v2 组合并保留其版本；子 Agent 所有者仍保留当前版本限制。

使用统计 schema 3 读取已结算 Assistant 消息与紧凑尝试中的用量，保留单独计费的重试。两个并发读取适配 JSONL 冷读缓存。每行在打开句柄后、读取之前观察修订号，并在后续持久化或活动变化时失效。升级验证使用隔离的历史副本并校验保留前代文件的哈希；原生验证使用打包后的应用。

图片、本地提取文档与通用文件路径共用附件服务，但不混淆各自的存储或接纳约定。fixture 初始历史和实时后续事件使用生产渲染器投影。添加菜单与回形针共用一个文件输入框，避免通过重复控件绕过禁用状态。

正文宽度沿用现有 ResizeObserver 和自适应 clamp。手动拖动目标、处理器与已保存宽度覆盖均被移除。这部分替代了[正文宽度自适应](2026-08-18-conversation-adaptive-content-width.zh.md)：其共享宽度轴与固定定位后代的设计理由仍然适用。系统更新分别展示已安装的 Desktop 与 Harness 版本，以及未检查状态、预发布标记、进度和可处理的失败。

## 备选方案

把历史 descriptor 改标为当前版本会悄然授予未经验证的恢复语义。只隐藏宽度手柄而保留热区会留下用户反馈的交互。每次打开都重建全部使用记录会把一次迁移成本变为反复出现的延迟。以上方案均被否决。

## 影响

内核版本与 Desktop 版本保持独立。迁移中旧源日志保持不可变，不受支持的未来格式或未知事件形态仍拒绝转换。本地兼容性不代表 Windows 验收，也不授权 Git 发布。预发布升级在本机替换前需要完整历史和打包原生证据；仅源码构建不足以证明可用。
