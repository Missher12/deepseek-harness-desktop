# Agent Note: Web 发言导航刻度

Status: implemented

[English](2026-08-27-web-prompt-navigation-rail.md) | 中文

## Problem

长会话很难回到较早的一次用户指令。浏览器搜索可以找到相同文字，却不能识别轮次边界；在会话启动时加载全部历史页，又会用更慢的启动和更多内存换取导航便利。用户需要的是类似 Codex、用于定位发言的刻度，而不是改写历史或回退机制。

## Decision

在视口足够宽时，会话会在距会话面板左边约 16px 的沟槽渲染一条只负责导航的刻度，正文宽度保持不变。每个刻度都对应不可变尾页历史响应所返回轻量发言索引中的一个精确用户消息序号。轮次开头使用较长刻度，工作中追加的指令使用较短刻度，当前可见发言使用主题强调色、空心圆点和当前位置计数。

鼠标悬停与键盘聚焦都会显示本地化提示，其中包含发言序号、格式化时间和规范化摘要。摘要最多 48 个 Unicode 码点，只有图片的发言使用明确的回退文字，提示不会暗中携带完整消息内容。宽窗刻度支持 ArrowUp、ArrowDown、Home、End 和激活键，并且始终只有一个刻度进入 Tab 顺序。

选择刻度后，会话运行时会显示该精确序号。运行时串行处理导航请求，只拉取使目标具体化所需的旧历史页，再把对应消息行滚动到视口中央；开启减少动态效果时会立即滚动。目标已过期或不可用时，界面显示本地、非破坏性的状态，不会跳到相近消息。

刻度最多渲染 120 项，同时始终保留首条与末条发言的可达性。低于支持宽度时，密集刻度会替换为紧凑的发言导航入口，而不是覆盖输入框或消息列；宽窄模式和锚点替换只在定位线原本拥有焦点时转移焦点。新的实时用户消息会在本地追加锚点，重新同步则用新的不可变尾页切点替换索引。

刻度不会删除、编辑、倒回、重发、分支或分叉会话。既有的显式会话分叉操作保持独立且不变。

## Alternatives considered

**从发言刻度编辑或回退。** 拒绝，因为这会改变持久历史语义，也会让导航控件拥有用户已经明确不要的破坏性或分支含义。

**预先加载全部历史页。** 拒绝，因为这会增加最长会话的打开延迟和内存占用，而长会话正是刻度需要改善的场景。

**使用浏览器搜索或近似 DOM 位置。** 拒绝，因为重复文本和尚未加载的历史无法定位精确的持久消息边界。

**为每条发言无限制渲染一个刻度。** 拒绝，因为数千条发言会产生无意义的 DOM 开销和无法阅读的密度；有界采样仍保留当前邻域及两端。

## Consequences

用户可以通过紧凑的视觉路标回到精确的早期指令，也可以用鼠标悬停文字和键盘焦点理解刻度，同时不会改变会话。Host 会在与尾页相同的不可变切点计算一份轻量全历史发言索引，客户端则拥有按精确序号按需分页的路径。这会增加有界元数据与导航状态，但不会增加新的持久格式或历史修改 API。

## Testing

Host 历史测试覆盖仅尾页交付索引、规范化摘要、长历史与不可变切点。会话运行时测试覆盖精确目标加载、请求串行化、实时锚点更新和重新同步。会话界面测试覆盖左侧位置、长短刻度、当前圆点与计数、有界情况下首尾可达、本地化悬停与焦点提示、roving focus、宽窄模式焦点交接、紧凑入口、减少动态效果、精确滚动和目标不可用状态。
