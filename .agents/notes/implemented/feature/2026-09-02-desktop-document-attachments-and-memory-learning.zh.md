# Agent Note：桌面文档附件与记忆和学习

Status: implemented

[English](2026-09-02-desktop-document-attachments-and-memory-learning.md) | 中文

## Problem

Desktop 可以接收浏览器侧图片，但普通文件只会被当成工作区引用，不能作为消息附件。用户无法把报告或源代码直接拖入输入框，并让文件内容随消息进入会话。“外置大脑”这个设置名称也更像实现概念，没有直接说明真实提供的两项能力。尚未完成的 Browser／Computer Control 产品只存在于独立开发工作中，不能进入本次发行。

## Decision

附件合同在既有图片块旁新增持久文档块。浏览器输入框使用同一份闭集文件名规则分类文件，把图片与文档草稿保存在一个有序列表中，并在提交前分别校验图片和文档上限。图片继续使用对象 URL 预览；文档使用不可交互的文件卡，绝不创建浏览器对象 URL。准入后，历史用户消息按原顺序渲染同一组附件，不会把内容寻址标识作为普通 JSON 暴露出来。

Renderer 会在读取文件字节前，对图片与文档合计执行 296MiB canonical base64 载体预算预检，并串行读取文件，为闭合 HTTP JSON 信封留下 4MiB。Host 会在解码前独立重复组合上限检查，并要求本地附件服务先验证完整文档批次，再开始发布。原始字节与提取后的 UTF-8 文本分别存入仅所有者可访问的内容寻址目录。引用只包含 SHA-256 标识、已验证媒体事实、清理后的叶文件名、字节数和明确截断状态，绝不包含本地路径。

本地提取支持 PDF、DOCX、XLSX、UTF-8 文本、Markdown、JSON、CSV、YAML、XML，以及共享闭集中常见的源代码文件名。PDF 提取在单独打包的 Worker 中运行，设有 30 秒墙钟期限与 128MiB V8 old-generation 上限；页数、文本 item 工作量、单 item 字符数和输出字节也分别受限。OOXML 提取限制条目数、单条目大小、展开总量与路径深度；拒绝路径穿越、加密和宏，忽略外部关系，绝不计算电子表格公式。每次读取都会验证两份不可变摘要。模型适配器会在既有图片转换前，把文档块替换成统一、确定性的带标签文本。投影优先保留最新消息、保持同一消息内附件顺序，并把无法容纳进精确 route context 与输出预留的文档替换为确定性的仅元数据占位文本。

持久内容寻址 ID 仍保存在 Host Session 日志中，但不会作为 renderer currency。历史、实时 Session 事件、queue frame、presenter view 与已知扩展载体都要经过有界 renderer document DTO 才能跨越 Host 边界。它的 display id 由进程随机生成且不透明；附件 ID、提取文本 ID、源摘要与文本摘要都不会进入 renderer payload 或 DOM。

用户可见设置分区改为**记忆与学习**／**Memory & Learning**。页面把经过审核的项目记忆和学到的工作流程作为两项真实能力，旧记忆兼容只保留为辅助说明。Brain Hub 接口、Provider 顺序、本地数据库、召回上限、唯一注入路径与超时放行行为均不改变。

Desktop staging 维护一份精确的禁入成品清单，阻止尚未完成的 Browser／Computer Control 产品进入安装包。普通 Workbench 浏览器继续保留，因为它是工作区界面，不是浏览器自动控制。

## Alternatives considered

**把绝对文件路径发给模型。** 拒绝，因为路径属于宿主私有信息，不能可靠支持重放或分叉，也会让 Provider 获得环境文件系统知识。

**让每个模型适配器自行解析文件。** 拒绝，因为格式处理、上限和安全行为会按 Provider 漂移，并在每次请求中重复工作。

**接收任意压缩包、旧版 Office 或可执行格式。** 拒绝，因为本版本没有对应的有界、非执行式提取器。

**与 Browser Control 一起删除普通 Workbench 浏览器。** 拒绝，因为 Workbench 是独立的用户工作区能力，不携带已移除的控制权限。

## Consequences

用户可以把受支持文档与图片、文字一起拖入或选择，在发送前后看到文件，并在重启或分叉后继续获得确定性的模型可见文本。提取过程完全在本机并受上限约束，但在实现基于引用的垃圾回收前，源文件和提取对象会继续保留。受密码保护的 Office 文件、宏容器、旧版 `.doc`／`.xls`、任意压缩包与未知类型仍会被拒绝。macOS 与 Windows 成品必须来自同一公开提交；离线测试和 macOS 证据不能代替 Windows 原生验收。

## Testing

合同、提示词传输、本地提取、不可变存储、模型投影、输入框、历史渲染、本地化、记忆与学习、Desktop manifest 与 staging 测试覆盖新链路。本地附件包对自身源码执行完整的语句、分支、函数和行覆盖门禁。成品验收会另外验证最终 macOS 应用和同提交 Windows 工作流。
