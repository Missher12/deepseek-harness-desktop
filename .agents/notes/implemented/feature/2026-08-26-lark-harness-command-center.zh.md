# Agent Note: Lark 使用 Harness 原生命令中心

状态：已实现

[English](2026-08-26-lark-harness-command-center.md) | 中文

## 问题

首个 Lark 远程 Session 版本把精确 `/` 作为项目选择快捷方式，只暴露绑定、插话、停止和帮助命令。它可以继续现有 Session，但无法成为用户要求的 Harness 远程开发控制面，不能新建 Session、选择模型、执行原生命令或发现当前能力。

飞书机器人无法观察用户文本框里尚未发送的 `/` 按键。直接复制 OpenClaw 完整命令注册表还会暴露网关、频道、OAuth、浏览器、重启和管理操作；这些操作不属于可移除的 Harness Session 插件。

## 决策

现在发送精确 `/` 会返回完整且不调用模型的命令中心卡片。`/进入` 与 `/切换` 保留项目/Session 选择器。每个卡片 action 都复用现有的所有者、私聊、代次、有效期和一次性 nonce 准入边界。

该包通过现有 Host API 适配 Session 新建与重命名、新鲜模型与推理目录、skill 和 subagent。工具名称和后台任务来自精确 Agent 的作用域注册表。用量只读取已完成轮次最终 `assistant/message` 的 token 事实；诊断只输出脱敏布尔值和数量。模型与推理回调会重新读取目录，并在写操作前拒绝陈旧选择。

原生命令执行只允许显式的 `compact`、`goal`、`plan` 和 `permission` 白名单，并且仍要求精确绑定 Agent 已经注册该命令。未来 Harness 新增命令不会自动变成远程可调用命令。输入的 `/skill-name ...` 只有在当前 skill 目录精确匹配后才会准入，随后原样进入现有持久化 Lark FIFO，成为普通可见用户消息，由 Harness skill 前置步骤保持权威。

`/新建` 使用精确绑定 workspace 调用 Host create API，随后只接受 Host 返回的 Session，并校验 workspace 成员关系、归档、血缘、cwd 和普通解析。新建已经提交但后续绑定失败时，只报告事实，不执行破坏性补偿。

## 考虑过的替代方案

**继续让 `/` 打开项目选择器。** 已否决，因为所有者明确选择 `/` 作为完整命令发现入口；`/进入` 已经能精确表达项目选择。

**把每个未知斜杠命令透传给 Harness。** 已否决，因为未来或部署专属命令可能在没有远程安全约定的情况下改变权限、导出数据或执行管理操作。

**复制 OpenClaw 命令实现。** 已否决，因为它们面向 OpenClaw 网关和频道运行时，而不是选定的 Harness Session，并会制造重复状态和权限。

**把 skill 作为隐藏上下文调用。** 已否决，因为这会重现早先的可见性问题。skill 文本继续作为 Harness 会话中可见的普通持久化用户消息。

## 验证

测试要求精确 `/` 路由到命令中心、`/进入` 保留选择器、固定原生命令映射、精确 skill 准入、严格的新建 Session 绑定、签名模型/推理回调重新校验、有界的 skill/工具/任务/用量视图，以及诊断脱敏。完整 Lark 套件、TypeScript 构建、Bundle 构建、双语文档门禁、Profile 安装/移除、已安装字节校验、重启状态和一次真实所有者私聊构成剩余验证层。

## 结果

已配对所有者无需第二套 Agent 运行时或 Harness 核心补丁，就能获得实用的 Harness 远程开发命令中心。命令发现和只读状态不会消耗模型 token。Session 写操作只来自显式命令和签名回调。部分 OpenClaw 命令会继续有意缺席，直到 Harness 提供等价原生服务和明确的远程安全策略。
