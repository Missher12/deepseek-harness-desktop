# Agent Note: 桌面发布工具与已验收产物发布

Status: implemented

[English](2026-09-13-desktop-release-tooling-and-promotion.md) | 中文

## 问题

发布时重新构建安装器，会让公开字节与通过原生验收的安装器分离。只要求 macOS 和 Windows 的发布任务不能证明 Ubuntu 验收，也不能证明四份平台更新清单完整。覆盖选项还会允许重试替换已有资产，破坏原有身份记录。

## 决策

[桌面发布工作流](../../../../.github/workflows/desktop-release.yml) 以仓库只读权限验证发布工具，运行既有清单生成器和应用解析器测试，并检查自身受限职责。成功状态只代表工具证据，不代表原生验收或发布许可。

总指挥按[桌面发布流程](../../../../apps/desktop/releasing/README.zh.md) 发布已验收的原始安装器。发布记录将一个最终源码提交与 macOS、Windows、Ubuntu 原生回执、选定插件组合及每件资产的精确大小和 SHA-256 绑定。四份更新清单来自这些已验收的包字节。已发布资产和标签保持不可变，匿名下载验证最终公开传输。

## 考虑过的替代方案

**在同一工作流中重新构建并发布。** 第二次构建不是原已验收产物，构建成功不能替代平台生命周期回执。保留该工作流也会保留遗漏 Ubuntu 的发布路径。

**引入通用产物发布服务。** 各平台负责人已经产出具体回执，总指挥负责审查。在尚无实际平台输入前新增传输和回执聚合协议，会重复这项职责并扩大本次迁移。

## 影响

发布仍由总指挥明确执行，并保存资产清单。只读工作流提供可重复的有效检查，不隐含发布副作用。总指挥必须保留并审查原生证据、完成匿名验证；工具成功本身不能强制执行或证明这些人工审核义务。
