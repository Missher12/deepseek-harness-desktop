# Agent Note：兼容进程管理的生命周期测试显式选择对应路径

Status: implemented

[English](2026-09-22-subprocess-fallback-test-ownership.md) | 中文

## 问题

两个终端生命周期测试提供了假的 PTY 和进程树检查器，却沿用了运行机器的进程管理方式。在 Linux 上，原生 scope 创建了启动请求，假的 PTY 从未消费该请求，因此模拟的成功退出正确地触发了启动校验失败。另一个销毁测试假设无效 cwd 引发的拒绝一定先于 Linux 启动器在引导前被取消。

## 决策

这三个测试通过已有的运行时平台测试接口或返回不可用的 Linux 能力探测选择兼容进程管理，并在名称中明确该范围。终端测试继续断言进程静止后的释放，以及清理失败后的保留。启动失败测试在直接兼容启动路径上保留拒绝断言。已有的 Linux scope 测试分别验证原生封装、启动拒绝、取消信号和所有者清理。

## 考虑过的替代方案

**接受假终端未消费的启动请求。** 否决，因为这会为了从不执行引导的测试替身而削弱生产启动校验。

**销毁断言同时接受拒绝或取消。** 否决，因为该测试专门验证拒绝的容纳；原生取消已有独立断言。

## 影响

通用生命周期测试在各平台执行相同的选定路径。Linux 原生启动行为和生产环境的进程管理方式选择保持不变。
